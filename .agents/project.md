# 제품 경계

HeavyMach 2의 일반판과 HD판을 각각 보존 기준으로 삼는 독립 복원 작업이다. iPhone에서는 일반판, iPad에서는 HD판의 선명도·유닛과 오브젝트 비례·화면 구성을 재현하며 최종 Apple 앱은 유니버설 앱을 목표로 한다.

최종 게임 규칙·콘텐츠는 HD판을 기준으로 복원한 공통 코어를 사용하고, iPhone 표시는 일반판 포팅판, iPad 표시는 HD 포팅판과 대조한다. 현재 비교한 일반판2.0.1과 HD1.0.3은 버전도 다르므로 차이를 전부 기기 차이로 취급하지 않는다. 일반판과 다른 HD 규칙은 확인 근거와 함께 기록한다. 기준 판본·좌표·원작 실행 검증은 아직 남아 있다.

2026-11-10 사용자 요구: iPad 구성을 iPhone 화면 전체의 확대판으로 만들지 않는다. 더 넓은 유효 화면에서는 메크·오브젝트·HUD를 화면 크기에 비례해 함께 키우지 않고, 적정 표시 크기를 유지하면서 더 많은 전장과 정보를 보여준다. 원작 일반판·HD판의 표시 크기와 조립 비례를 각각 측정해 기기별 기준을 정한다. HUD는 우선 하단 중앙 고정 배치로 준비하며 자유 이동은 후속 기능으로 둔다. 월드 표시 배율, 카메라 범위, HUD 배치를 분리하고 창 크기와 안전 영역에 대응한다. 구체적인 비교·합격 기준은 `docs/hd-landscape-plan.md`를 따른다.

2026-11-10 채택한 복원 방향: HD 그래픽을 공통으로 사용하는 유니버설 앱을 목표로 한다. 그림 픽셀 크기와 게임 내 크기·기준점·파츠 접합점·카메라·HUD 배치를 분리하고, 일반판 iPhone과 HD iPad의 검증된 표시 기준에 연결한다. 기존 표본 측정값을 바로 고정 상수로 쓰지 않는다. HD와 일반판의 그림·여백·기준점·누락 자원을 대응표로 확인하며, 차이는 근거가 있는 공통 데이터·조립 경로에서 처리한다. 원작 비교 앱은 각각 보존한다. 이 결정은 모든 에셋 대응과 공통 로직의 검증 완료를 뜻하지 않는다.

후속 사용자 지정: “소스코드와 에셋은 hd것을 쓰되, 크기는 포팅판 2개에서 측정한 대로 플랫폼 별로 크기는 다르게 대응한다.” 확보한 원본 소스는 없으므로 소스코드는 HD 실행파일·데이터에서 확인한 동작을 새 소스로 복원한다는 뜻으로 적용한다. 기기별로 달리하는 값은 화면 표시 크기·카메라·HUD 배치이며, 월드의 충돌 크기·이동·공격·사거리는 HD 기준 공통 게임 규칙으로 유지한다. 세부 적용 기준은 `docs/restoration-plan.md`에 기록한다.

HeavyMach 1과 MachDefense의 파일은 변경하지 않는다. 모든 개발은 HeavyMach2 저장소에서 한다. 원본 IPA·사용자 저장·서명 비밀은 Git에 넣지 않는다. 광고는 표시하지 않는다.

기술스택은 HeavyMach 1의 C++20 공통 코어, Objective-C++ Apple 연결, Kotlin/NDK Android, Emscripten/WebAssembly 웹, Tauri 2 구성을 따른다. 원본 비교 앱은 Rust·SDL 기반 실행기를 별도로 검증한다. [기술스택과 에셋 절차](../docs/technology-and-assets.md)에 따라 원작 파일 형식·저장·reader·파츠 조립을 복원하고 신규 유닛도 같은 경로에 넣는다. 현재는 계획 단계다.
