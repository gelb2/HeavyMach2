# 제품 경계

HeavyMach 2의 일반판과 HD판을 각각 보존 기준으로 삼는 독립 복원 작업이다. iPhone에서는 일반판, iPad에서는 HD판의 선명도·유닛과 오브젝트 비례·화면 구성을 재현하며 최종 Apple 앱은 유니버설 앱을 목표로 한다.

최종 게임 규칙·콘텐츠는 HD판을 기준으로 복원한 공통 코어를 사용하고, iPhone 표시는 일반판 포팅판, iPad 표시는 HD 포팅판과 대조한다. 현재 비교한 일반판2.0.1과 HD1.0.3은 버전도 다르므로 차이를 전부 기기 차이로 취급하지 않는다. 일반판과 다른 HD 규칙은 확인 근거와 함께 기록한다. 기준 판본·좌표·원작 실행 검증은 아직 남아 있다.

2026-11-10 사용자 요구: iPad 구성을 iPhone 화면 전체의 확대판으로 만들지 않는다. 더 넓은 유효 화면에서는 메크·오브젝트·HUD를 화면 크기에 비례해 함께 키우지 않고, 적정 표시 크기를 유지하면서 더 많은 전장과 정보를 보여준다. 원작 일반판·HD판의 표시 크기와 조립 비례를 각각 측정해 기기별 기준을 정한다. HUD는 우선 하단 중앙 고정 배치로 준비하며 자유 이동은 후속 기능으로 둔다. 월드 표시 배율, 카메라 범위, HUD 배치를 분리하고 창 크기와 안전 영역에 대응한다. 구체적인 비교·합격 기준은 `docs/hd-landscape-plan.md`를 따른다.

2026-11-10 채택한 복원 방향: HD 그래픽을 공통으로 사용하는 유니버설 앱을 목표로 한다. 그림 픽셀 크기와 게임 내 크기·기준점·파츠 접합점·카메라·HUD 배치를 분리하고, 일반판 iPhone과 HD iPad의 검증된 표시 기준에 연결한다. 기존 표본 측정값을 바로 고정 상수로 쓰지 않는다. HD와 일반판의 그림·여백·기준점·누락 자원을 대응표로 확인하며, 차이는 근거가 있는 공통 데이터·조립 경로에서 처리한다. 원작 비교 앱은 각각 보존한다. 이 결정은 모든 에셋 대응과 공통 로직의 검증 완료를 뜻하지 않는다.

후속 사용자 지정: “소스코드와 에셋은 hd것을 쓰되, 크기는 포팅판 2개에서 측정한 대로 플랫폼 별로 크기는 다르게 대응한다.” 확보한 원본 소스는 없으므로 소스코드는 HD 실행파일·데이터에서 확인한 동작을 새 소스로 복원한다는 뜻으로 적용한다. 기기별로 달리하는 값은 화면 표시 크기·카메라·HUD 배치이며, 월드의 충돌 크기·이동·공격·사거리는 HD 기준 공통 게임 규칙으로 유지한다. 세부 적용 기준은 `docs/restoration-plan.md`에 기록한다.

2026-11-10 최신 순서: 복원판은 먼저 iPhone 가로·iPad 세로로 정상동작을 검증한다. 그다음 두 기기 모두 가로·세로를 지원한다. 기존 가로 우선 시험 계획보다 이 순서를 우선한다. 표시·입력·공격 판정은 일반판/HD 포팅판의 같은 조건에서 직접 대조하고, 확인되지 않는 내부 경계·변환은 데이터·코드·실행 관측으로 좁힌다. 포팅판 두 개만으로 판별 불가라고 미리 결론 내리지 않는다.

2026-11-10 대조 결과: 두 포팅판의 이동·적 선택·격파·임무1/5·500→503Cr를 시뮬레이터에서 확인했다. 일반판의 검은 지형 오류는 남는다. HD 탄환 충돌 함수는 HP·isInScreen·점 포함 조건을 사용하며, 기반 클래스의 표시 여부는 카메라 범위와 여유60에 연결된다. 화면 시야 확장만으로 HD 전투가 유지된다고 가정하지 않는다. 원작 터치 선택 반지름과 탄환 boundRect를 구분해 복원하고 화면 경계의 전투 후보 조건을 함께 검증한다. 두 판본의 WeaponInfo213행 중126행이 다르므로 기기별 배율 문제로 합치지 않는다. 같은 조건의 경계 검사는 아직 남는다. [관측·분석·보강 계획](../docs/reference-comparison-results-20261110.md)을 따른다.

HeavyMach 1과 MachDefense의 파일은 변경하지 않는다. 모든 개발은 HeavyMach2 저장소에서 한다. 원본 IPA·사용자 저장·서명 비밀은 Git에 넣지 않는다. 광고는 표시하지 않는다.

2026-11-10 사용자 최종 기술스택 요구: HeavyMach 1·MachDefense·HeavyMach 2는 같은 C++20 게임 코어·GPU 스프라이트·OpenAL 효과음·기존 플랫폼 어댑터 구성을 사용한다. Objective-C++ Apple, 기존 Kotlin/JNI·NDK Android, Emscripten/WebAssembly·WebGL2 웹/PWA, Tauri2 Rust 호스트를 따른다. Kotlin/JS/Rust는 기존 호스트 역할이며 게임을 별도 재개발하는 언어가 아니다. Python은 분석·오프라인 준비 도구에 한정한다. 임의 Python/Ruby 런타임·Three.js·새 게임 엔진을 추가하지 않는다. 원작 비교 앱의 Rust·SDL 실행기는 제품과 분리한다.

[실제 코드·빌드 설정 대조](../docs/technology-stack-review-20261110.md)와 [실행 계약](../docs/runtime-contract.md)을 따른다. 사격마다 DB/파일 쓰기·오디오 context/source 생성·효과음의 AVAudioPlayer/AVAudioEngine 대체·UIKit 인게임 그래픽/버튼을 추가하지 않는다. 원작 BGM AudioQueue와 OS 장치 연결은 효과음 임의 대체와 구분한다. HM2 HD의 PCM 형식·게임 시간·저장 포맷은 HM2 근거로 복원한다. [에셋 절차](../docs/technology-and-assets.md)의 공통 reader·파츠 조립·패키징을 원본/신규 유닛 모두에 적용한다. [첫 reader·조립·GPU 구현](../docs/initial-source-restoration-20261110.md)을 시작했으며 게임·전투·진행 전체는 미완료다.

2026-11-10 최신 치트 요구: 경험치·진척도·아이템 허들을 건너뛰고 모든 기능·버튼·레벨업을 여러 조건에서 동시에 검증한다. [동시 검증](../docs/validation-build.md)은 한 전투의 복합 조건과 독립된 시뮬레이터/상태/결과의 병렬 실행을 포함한다. 원작에서 배타적인 화면 상태를 강제로 동시에 활성화하지 않는다. 네 정적 조립 사례의 GPU 출력을 전체 치트 검사 완료로 쓰지 않는다. [모델 사용 이력](../docs/model-usage-history.md)은 사용자 제공 기록을 보존한다.
