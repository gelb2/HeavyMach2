# 맥미니에서 PWA 화면과 입력 검증

현행 PWA 검증은 휴대폰 가로·태블릿 세로·데스크톱을 기준으로 한다. 휴대폰 세로와 태블릿 가로 결과는 이전 방향 전환 검사 기록이다. 태블릿 가로 지원은 후속 작업으로 잡는다.

기준 커밋은 `a6a798c`다. 맥미니의 로컬 정식판과 치트판을 새 브라우저 프로필에서 연다. 검사용 저장을 만들고 기존 사용자 저장은 건드리지 않는다.

| 환경 | 확인할 화면과 동작 |
| --- | --- |
| 휴대폰 | iPhone과 Android 휴대폰의 세로·가로 화면. 기지에서 상점·사령부·전장으로 실제 터치 이동. |
| 태블릿 | iPad와 Android 태블릿의 큰 화면. 데스크톱 UA를 쓰는 iPad와 좁은 창에서도 기기 분류 유지. |
| 데스크톱 | 맥미니 Chrome과 WebKit의 넓은 창 및 좁은 창. 마우스로 기지에서 상점·사령부·전장으로 이동. 터치가 있는 데스크톱도 확인. |
| 경계 조건 | 회전·창 크기 변경, 600 CSS 픽셀을 기준으로 나뉘는 Android 화면, 접이식 화면 크기, 설치 캐시의 오프라인 재실행. |

1. 브라우저의 화면 크기·UA·터치와 `Web/Shell/display.js` 판별값을 기록한다. `app.js`가 Wasm에 넘긴 값과 공통 화면·입력 코드에서 쓰는 값을 확인한다.
2. Chromium·WebKit에서 동일한 게임 경로를 실행한다. 버튼의 실제 화면 위치에 클릭이나 터치를 보내 올바른 장면으로 진입하는지 확인한다. 창 크기 변경 후 캔버스의 비율, 화면 그리기, 입력을 다시 검사한다.
3. 사용할 수 있는 iPhone·iPad 시뮬레이터에서 Safari를 열어 화면을 확인한다. 맥미니의 Chromium 정식판에서 서비스 워커가 제어하는 상태로 네트워크를 끊어 다시 실행한다.
4. 실패한 조건은 재현한 다음 관련 모듈을 수정한다. 두 웹 판을 다시 빌드하고 해당 조건과 나머지 화면을 재검사한다. 검사 결과와 캡처 파일을 빌드 버전에 연결한다. 실제 기기에서만 확인할 수 있는 항목은 투두에 남긴다.

## 판별과 입력 경로

`Web/Shell/display.js`가 시작할 때 휴대폰·태블릿·데스크톱을 고른다. `Web/Shell/app.js`가 분류, 캔버스의 CSS 크기와 안전 영역을 Wasm에 넘긴다. 기기 분류는 탭을 열어 둔 동안 유지한다. Wasm의 `Runtime::resize`는 공통 `DisplayConfiguration`에 이 값을 넣는다. 좁은 태블릿 창은 태블릿 분류를 유지하면서 작은 화면용 HUD를 쓸 수 있다. 데스크톱은 창을 줄여도 데스크톱 HUD를 유지한다.

버튼의 그리기와 입력은 모두 같은 공통 `DisplayLayout`을 사용한다. 브라우저는 포인터의 CSS 좌표를 캔버스의 논리 좌표로 바꾼다. 실제 픽셀 버퍼 배율은 별도로 적용한다. 치트판에 Wasm이 최종으로 쓴 기기 값도 출력해 브라우저 값과 비교했다.

| 재현 | 원인과 수정 |
| --- | --- |
| WebKit 모의 터치가 타이틀을 넘기지 못했다. | 실제로 받은 포인터 번호는 0이었다. 공통 입력은 0을 입력 없는 상태로 쓴다. 웹 호스트가 포인터 번호를 Wasm에 넘길 때 1을 더한다. |
| 터치가 있는 Windows 데스크톱 모의 환경이 태블릿 메뉴를 열었다. | Windows UA에 해당하는 분기가 없어 터치와 화면 크기로 판별했다. iPhone·iPad·Android 판별 다음에 Windows NT를 데스크톱으로 처리한다. |

수정은 `73e825e`에 있다. 검증 산출물의 해시는 정식판 `0ab8f00c7c5b684a0debbb89`, 치트판 `78c7948d0848bcc21e9cce1c`다.

## 다시 실행하는 방법

[웹 빌드 절차](../Web/README.md)에 따라 로컬 서버를 실행한다. WebKit이 필요하면 `Web/node_modules/.bin/playwright-core install webkit`을 실행한다.

```sh
npm --prefix Web test
npm --prefix Web run smoke
npm --prefix Web run smoke -- --device-matrix
HM2_WEB_ENGINE=webkit npm --prefix Web run smoke -- --device-matrix
```

`HM2_WEB_TEST_EVIDENCE`에 절대 경로를 주면 장면 캡처와 기기별 판별값, 캔버스 크기, 실패한 버튼 좌표를 기록한다. `HM2_WEB_TEST_DEVICES`에 쉼표로 검사 환경을 지정할 수 있다. 화면 밖으로 나간 버튼을 발견하면 원인을 출력하고 나머지 기기도 검사한 뒤 명령이 실패를 반환한다.

## 화면과 입력 결과

표의 크기는 브라우저 안의 게임 캔버스 기준 CSS 픽셀이다. Chromium 158과 Playwright WebKit 26.0에서 각각 7개 환경을 검사했다. 각 환경의 기본 방향에서 검사용 슬롯으로 타이틀·기지·사령부·상점·전장·포털 복귀를 확인했다. 14개 실행 모두 브라우저와 Wasm의 분류가 일치했다. 축소·회전을 모의한 뒤에는 두 엔진에서 각각 3개 환경의 상점 왕복이 성공했고, 4개 환경에서 같은 배치 오류가 나왔다. OS의 실제 회전과 분할 화면은 별도 검사로 남겼다.

| 재현 환경 | 확인한 범위 | 발견한 문제 |
| --- | --- | --- |
| iPhone 모의, Android 휴대폰 모의 | 각각 734×343, 863×360 가로 화면에서 전장 왕복까지 동작했다. 세로로 줄인 뒤에도 휴대폰 분류와 캔버스 배율이 맞았다. | 393×659 및 412×839의 세로 기지에서 상점 버튼이 오른쪽 화면 밖에 있다. 두 엔진에서 같은 좌표를 얻었다. |
| iPad 모의 | 834×1194 세로 화면에서 전장 왕복까지 동작했다. 데스크톱 UA를 쓴 504×834 모의 창에서도 태블릿 분류로 상점에 들어갔다 나왔다. | 1194×834 가로 상점에서 복귀 버튼 중심이 게임 좌표 `(995, -298.156)`이다. 두 엔진에서 화면 아래로 벗어났다. |
| Android 태블릿 모의 | 640×1024 세로 화면에서 전장 왕복까지 동작했다. | 1024×640 가로 상점에서 복귀 버튼 중심이 `(853.333, -293.333)`이다. 두 엔진에서 화면 아래로 벗어났다. |
| 맥미니 데스크톱, 터치 Windows 데스크톱 모의 | 각각 1366×900과 820×540에서 데스크톱 분류를 유지했다. 상점 왕복과 기본 크기의 전장 왕복이 동작했다. | 검사한 크기에서 주요 이동 버튼이 보이고 눌렸다. |
| iPhone 17 Pro 시뮬레이터 Safari 26.5 | 874×338에서 휴대폰으로 분류했다. 타이틀에서 슬롯과 기지로 진입하고 사령부에서 기지로 돌아왔다. | 기지 오른쪽 위의 Shop과 Exit가 겹친다. Shop의 중심을 터치했을 때 상점 대신 슬롯 화면으로 이동했다. |
| iPad Pro 11 시뮬레이터 Safari 26.5 | Safari가 Macintosh UA와 터치 지점 5개를 보고했다. 834×1124에서 태블릿으로 분류하고 기지·사령부·상점·전장에 진입했다. | Safari 자동 터치로 포털을 눌렀으나 기지 복귀까지 확인하지 못했다. 같은 기본 경로는 iPad 브라우저 모의에서 통과했다. |

Chromium 정식판에서 설치 가능 조건 오류가 0개였다. 서비스 워커가 활성화된 상태에서 네트워크를 끊고 새로고침했다. 게임이 다시 실행됐고 정식판의 검사용 저장이 일치했다. 복구코드 오류·저장소 분리·대화상자 중 창 크기 변경과 WebGL 복구까지 기존 브라우저 검사 14개를 통과했다. 분류 단위 검사 5개도 통과했다. Android는 화면 짧은 변 599·600 CSS 픽셀과 방향별 경계를 단위 검사했다. 접이식 기기의 접힘·펼침 중 재분류는 검사하지 않았다.

## 화면 배치 후속

- 휴대폰 가로 기지의 `Screens::base`는 원본 Phone 표의 버튼을 `DisplayLayout::artScene`으로 확대한다. iPhone 17 Pro Safari 가로에서 관측한 Shop과 Exit의 겹침을 기준으로 시설마다 표시와 터치 영역을 대조한다.
- 태블릿 상점·사령부·기지의 `tabletMenu`는 캔버스를 덮는 배율을 선택한다. 넓은 가로 창에서는 위아래가 잘리고 버튼도 같은 변환을 받는다. 태블릿 가로 지원 단계에서 원본 비율, 전체 조작부와 배경을 함께 보이는 배치를 검증한다.
- 배치 수정에서는 저장·게임 규칙과 분리된 표시 정책을 사용한다. 수정 후 기지 여섯 곳의 시설부터 상점의 거래 버튼과 복귀, 사령부의 상세와 복귀까지 그림과 터치 영역을 같은 크기에서 대조한다. 이번 맥미니 검사 범위는 검사용 Ruin Field 기지다.

캡처와 JSON은 로컬 `.local/evidence/pwa-device-validation-20261120`에 있다. `route-screens.jpg`는 기본 방향과 오프라인 화면, `layout-findings.jpg`는 재현한 화면 오류를 모은 그림이다. `final`에는 브라우저별 캡처와 좌표, `simulator`에는 Safari 캡처와 터치 기록, `offline`에는 정식판 오프라인 캡처가 있다.

## 설치형 PWA 재검증

브라우저 진입 화면의 첫 동작을 게임 설치로 바꿨다. 브라우저가 설치 대화상자를 제공하지 않으면 Safari·Chrome·Edge에 맞는 메뉴를 안내한다. 설치한 앱은 홈 화면이나 앱 목록에서 열고 **게임 시작**을 누른다. 정식판과 치트판은 앱 식별자·캐시·저장소가 분리돼 있다. 설치 안내 탭은 게임을 시작하기 전까지 저장 잠금을 차지하지 않는다.

| 환경 | 실제 확인 |
| --- | --- |
| 맥미니 Chrome 앱 창 | 정식판 `774ab4808d74c853990a6282`과 치트판 `c36d24bebdcdaa9283908073`을 설치하고 앱 창에서 실행했다. 브라우저의 설치 안내 탭을 열어 둔 채 플레이했다. 각 앱 창을 닫고 네트워크를 차단해 다시 실행했고 저장 바이트가 일치했다. |
| 맥미니 설치 앱 창의 기기 모의 | 같은 치트판을 설치한 창에서 iPhone·Android 휴대폰 가로, 데스크톱 UA를 쓰는 iPad 세로, 데스크톱을 검사했다. 네 환경 모두 사령부·상점·전장·포털 복귀를 통과했고, 창 크기를 바꾼 뒤 다시 상점을 왕복했다. |
| iPhone 17 Pro·iPad Pro 11 시뮬레이터 Safari | 홈 화면 추가와 웹 앱으로 열기 안내를 표시했다. Apple 시뮬레이터의 홈 화면에서 앱을 설치하고 실행하는 단계는 확인하지 못했다. |
| Android 에뮬레이터 Chrome | 휴대폰 가로에서 게임 설치 버튼이 Android 설치 대화상자를 열었다. 설치 승인 뒤 Play 스토어가 WebAPK 요청에 `unknown_account`를 기록했고 앱이 설치되지 않았다. |
| Chromium·WebKit 자동 검사 | 설치 안내 5종, 설치 대화상자가 없는 경우, 취소와 승인, 설치된 창 안내 숨김을 검사했다. 최신 Chromium 일반 스모크 14개와 분류 단위 검사 5개를 통과했다. |

진행 막대와 단계별 다운로드 표시는 HeavyMach 1·MachDefense를 따라 구현하도록 [투두](todo.md)에 기록했다. 캡처와 로그는 로컬 `.local/evidence/pwa-install-20261120`에 있다. `installed-proof.jpg`에 설치 화면과 실행 장면을 모았다. `final-installed/installed.json`과 `installed-device-matrix/chromium-devices.json`에 앱 식별자·판별값·크기·검사 결과를 기록했다.

| 코드 시험 재현 | `install.js`는 사용자가 설치 창에서 승인하면 `appinstalled`를 받기 전에도 설치 버튼을 숨긴다. 해당 이벤트 없이 승인만 준 시험에서 버튼이 숨었다. Android 에뮬레이터에서는 별도로 Play 스토어가 `unknown_account`를 반환했다. | 설치 요청 승인과 설치 완료를 구분한다. 취소하거나 완료 확인을 받지 못해도 안내와 재시도 경로를 유지한다. |
| 재현 후 판정 보류 | iPad 시뮬레이터 Safari에서 포털 터치는 기록됐고 전장에 남았다. 맥미니의 설치 앱 창에서 iPad를 모의했을 때 복귀했다. | 같은 저장과 포털로 Safari 및 iPad 설치형 앱의 실제 터치를 대조한다. 화면 좌표·월드 좌표·복귀 조건을 기록해 입력 문제인지 판정한다. |
| 다운로드 개선 | 서비스 워커는 `cache.addAll`로 파일을 받으며 화면에는 파일별 진행률이 없다. 설치 안내는 서비스 워커가 페이지를 제어하는 시점만 확인한다. 업데이트에서 대기·활성 버전과 각 버전의 캐시 상태를 알려 주는 표시가 없다. | HeavyMach 1·MachDefense처럼 받은 바이트와 검증한 바이트, 전체 용량을 표시한다. 중단과 재시도, 기존 캐시 재사용, 새 버전으로 바꾸기와 오프라인 재개를 정식판·치트판에서 검사한다. 화면과 서비스 워커가 같은 파일을 중복으로 받는지도 네트워크 기록에서 확인한다. |
| 코드 검토 | `app.js`는 게임 시작 중 `live`가 되기 전의 가시성 변경을 건너뛴다. 저장 읽기 중 앱을 숨기면 시작 시점의 오디오·런타임 상태에 숨김이 반영되는지 미확인이다. | 시작 중 백그라운드 전환과 복귀를 재현한다. 숨긴 동안 효과음·배경음·진행이 멈추고, 복귀 시 화면과 음향이 한 번만 재개되는지 검사한다. |
| 코드 검토 | `storage.js`는 저장 연결 자체가 실패하면 잠금을 해제한다. 연결 뒤 저장 읽기나 그래픽 시작에서 실패하면 잠금을 탭이 닫힐 때까지 잡을 수 있다. Web Locks가 없는 실행 환경에는 별도 동시 쓰기 방지가 없다. | 읽기·그래픽 실패 뒤 다른 창에서 정상 재실행하고, 같은 판의 두 창과 일반판·치트판을 동시에 열어 저장 충돌 여부를 확인한다. 복구 백업과 기존 저장을 보존한다. |
| 검증 환경 | Apple 시뮬레이터는 설치 안내까지 확인했다. Android 에뮬레이터는 시스템 설치 창 뒤 실설치에 실패했다. Mac Safari의 Dock 설치도 안내와 실제 실행을 따로 확인해야 한다. | 설치 아이콘으로 열어 첫 시작, 터치·효과음, 앱 종료 뒤 오프라인 재실행과 저장 유지까지 확인한다. iPad 분할 화면, Android 접이식 화면, 사파리 데스크톱 사이트와 창 크기 변경도 실제 환경에서 검사한다. |
| 검사 보강 | 초기 Chromium iPhone 모의 실행에서 시작 버튼 타임아웃이 나왔다. 단독 재시도와 실제 설치 앱 모의 실행은 통과했다. WebKit Android 모의에서 863×360→915×412 변경은 캔버스 갱신 대기에서 실패했다. | 실패 때 런처 상태·콘솔·로드 실패 파일·실제 뷰포트를 함께 보존한다. 같은 조건의 재현 여부와 브라우저 모의 도구 문제를 구분한다. |
| 아이콘·Mac 패키지 | PWA·Tauri 런처는 검증용 아이콘을 사용한다. 정비소·도움말·검은 화면을 수정한 Mac 앱 결과는 있다. 최신 설치 화면을 포함한 정식 산출물로 Tauri를 다시 묶었을 때의 결과는 없다. | 모바일과 같은 일러스트를 연결한다. 최신 Mac 패키지를 실행해 Finder·Dock 아이콘, 저장 복원·재실행, 정비소·도움말, 창 크기 변경과 WebGL 복구를 다시 검사한다. |

이미 수정하고 재검사한 항목은 WebKit 포인터 번호 0의 터치 누락, Windows 터치 데스크톱의 태블릿 오분류, 설치 안내 탭의 저장 잠금, 대화상자를 연 상태에서의 크기 변경·WebGL 복구 뒤 검은 화면, 데스크톱 정비소 배경·슬롯과 첫 도움말 배치다. 정식판·치트판 분리와 오프라인 재시작 뒤 저장 보존은 맥미니 Chrome 설치 앱에서 확인했다.

## 가로 화면과 입력 재검증

현재 PWA는 휴대폰 가로·태블릿 세로·데스크톱을 기준으로 한다. 게임 화면, 설치 안내, 저장 이동 창의 조작부는 화면 안에 배치한다. 가로·세로 스크롤로 버튼을 드러내는 방식은 사용하지 않는다. 첫 화면에서는 설치한 앱으로 플레이하도록 권장한다.

| 항목 | 실행 결과 |
| --- | --- |
| iPhone Safari의 화면 높이 | Safari 탭과 같은 874×338과 전체 높이를 가정한 874×402를 Chromium 휴대폰 모의에서 비교했다. 338에서는 Shop 터치 뒤 슬롯 화면으로 돌아갔고 402에서는 상점·전장·포털 복귀를 통과했다. 두 경우의 기기 분류는 같다. |
| 태블릿 가로 | 설치한 Chrome 앱 창에서도 iPad 1194×834와 Android 태블릿 1024×640의 상점 복귀 버튼이 화면 밖이었다. 기본 세로 화면에서는 같은 경로를 통과했다. |
| 선택·복사와 전장 경로 | 캔버스에만 길게 누르기 메뉴, 선택, 드래그 시작, 복사 제한을 적용했다. Chromium 모의 기기의 터치와 Chromium·WebKit의 마우스 입력에서 전장 경로 점이 늘었고 포인터를 놓으면 입력이 끝났다. 복구코드 전체 선택과 복사 기능 호출, 코드 복원을 검사했다. Chromium·WebKit에서 높이 338의 설치 안내를 대조했고, 같은 높이의 저장 이동 창에서도 버튼과 입력칸이 스크롤 없이 들어왔다. |
| 설치와 오프라인 | 설치 승인 이벤트 뒤에도 완료를 확인할 때까지 안내를 표시한다. 맥미니 Safari에서 Dock에 추가한 웹 앱 후보 e9b293eef0289832b452223b를 시험 서버 종료 뒤 다시 열어 게임 화면을 띄웠다. 마지막 후보의 정식판 1eceff2a12eb3dc8b967292b와 치트판 665d480272a351afd269a894는 맥미니 Chrome에서 각각 설치해 오프라인 재실행과 저장 유지까지 통과했다. |
| 시작·잠금 | WebGL 초기화를 강제로 실패시킨 뒤 같은 판을 두 번째 탭에서 실행했다. 저장을 여는 중 앱 숨김을 모의해 오디오 중지 호출과 Wasm 진행 정지, 복귀 시 재개를 확인했다. |
| iPad Safari 포털 | 시뮬레이터 Safari 834×1124에서 사령부·상점·전장까지 확인했다. WebDriver 터치 뒤 전장에 남았고 이동 포인터가 눌린 상태로 기록됐다. 같은 834×1124를 사용한 Playwright WebKit에서는 기본 경로의 포털 복귀를 통과했다. 설치형 실기기의 직접 터치 확인이 남았다. |
| WebKit 모의 크기 변경 | 게임이 없는 고정 영역에서도 Android 가로 모의를 863×360에서 915×412로 바꾸면 WebKit의 창 크기만 바뀌고 고정 영역은 기존 크기를 유지했다. 같은 검사에서 Chromium의 고정 영역은 갱신됐다. |
| 다운로드와 아이콘 | 새 Chromium 프로필에서 91,435,806바이트의 game.data에 페이지와 서비스 워커가 각각 요청했다. 진행 막대는 없었다. 512픽셀로 맞춘 iOS 아이콘과 PWA 아이콘의 그림이 다른 것도 확인했다. |
| Tauri Mac | 별도 검증 패키지에서 White Mt. Base 슬롯을 읽었다. 저장 이동 창을 연 채 앱 창을 확대하고 복구코드를 생성·검증·복원했다. 복원 뒤 슬롯 화면이 표시됐고 저장과 백업 28,204바이트가 일치했다. |

실기기에서 열 수 있는 설치 주소가 준비되면 모바일의 홈 화면 실행, 오프라인과 음향, 분할·접이식 화면, 직접 터치를 확인한다. 결과는 [투두](todo.md)에 연결했다. 로그와 캡처는 로컬 `.local/evidence/pwa-gesture-20261120`에 있다.
