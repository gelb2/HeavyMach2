# 맥미니에서 PWA 화면과 입력 검증

휴대폰 PWA의 현행 검증 기준은 가로 화면이다. 아래 세로 전환 결과는 이전 검사 기록이다.

기준 커밋은 `a6a798c`다. 맥미니의 로컬 정식판과 치트판을 새 브라우저 프로필에서 연다. 검사용 저장을 만들고 기존 사용자 저장은 건드리지 않는다.

| 환경 | 확인할 화면과 동작 |
| --- | --- |
| 휴대폰 | iPhone과 Android 휴대폰의 세로·가로 화면. 기지에서 상점·사령부·전장으로 실제 터치 이동. |
| 태블릿 | iPad와 Android 태블릿의 큰 화면. 데스크톱 UA를 쓰는 iPad와 좁은 창에서도 기기 분류 유지. |
| 데스크톱 | 맥미니 Chrome과 WebKit의 넓은 창 및 좁은 창. 마우스로 기지에서 상점·사령부·전장으로 이동. 터치가 있는 데스크톱도 확인. |
| 경계 조건 | 회전·창 크기 변경, 600 CSS 픽셀을 기준으로 나뉘는 Android 화면, 접이식 화면 크기, 설치 캐시의 오프라인 재실행. |

1. 브라우저의 화면 크기·UA·터치와 `Web/Shell/display.js` 판별값을 기록한다. `app.js`가 Wasm에 넘긴 값과 공통 화면·입력 코드에서 쓰는 값을 확인한다.
2. Chromium·WebKit에서 동일한 게임 경로를 실행한다. 버튼의 실제 화면 위치에 클릭이나 터치를 보내 올바른 장면으로 진입하는지 확인한다. 창 크기 변경 후 캔버스의 비율, 화면 그리기, 입력을 다시 검사한다.
3. 사용할 수 있는 iPhone·iPad 시뮬레이터에서 Safari를 열어 화면을 확인한다. 맥미니의 Chromium 정식판에서 서비스 워커가 제어하는 상태로 네트워크를 끊어 다시 실행한다.
4. 실패한 조건은 재현한 다음 관련 모듈을 수정한다. 두 웹 판을 다시 빌드하고 해당 조건과 나머지 화면을 재검사한다. 검사 결과와 캡처 파일을 빌드 버전에 연결한다. 실제 기기에서만 확인할 수 있는 항목은 투두에 남긴다.

## 판별과 입력 경로

`Web/Shell/display.js`가 시작할 때 휴대폰·태블릿·데스크톱을 고른다. `Web/Shell/app.js`가 분류, 캔버스의 CSS 크기와 안전 영역을 Wasm에 넘긴다. 기기 분류는 탭을 열어 둔 동안 유지한다. Wasm의 `Runtime::resize`는 공통 `DisplayConfiguration`에 이 값을 넣는다. 좁은 태블릿 창은 태블릿 분류를 유지하면서 작은 화면용 HUD를 쓸 수 있다. 데스크톱은 창을 줄여도 데스크톱 HUD를 유지한다.

버튼의 그리기와 입력은 모두 같은 공통 `DisplayLayout`을 사용한다. 브라우저는 포인터의 CSS 좌표를 캔버스의 논리 좌표로 바꾼다. 실제 픽셀 버퍼 배율은 별도로 적용한다. 치트판에 Wasm이 최종으로 쓴 기기 값도 출력해 브라우저 값과 비교했다.

| 재현 | 원인과 수정 |
| --- | --- |
| WebKit 모의 터치가 타이틀을 넘기지 못했다. | 실제로 받은 포인터 번호는 0이었다. 공통 입력은 0을 입력 없는 상태로 쓴다. 웹 호스트가 포인터 번호를 Wasm에 넘길 때 1을 더한다. |
| 터치가 있는 Windows 데스크톱 모의 환경이 태블릿 메뉴를 열었다. | Windows UA에 해당하는 분기가 없어 터치와 화면 크기로 판별했다. iPhone·iPad·Android 판별 다음에 Windows NT를 데스크톱으로 처리한다. |

수정은 `73e825e`에 있다. 검증 산출물의 해시는 정식판 `0ab8f00c7c5b684a0debbb89`, 치트판 `78c7948d0848bcc21e9cce1c`다.

## 다시 실행하는 방법

[웹 빌드 절차](../Web/README.md)에 따라 로컬 서버를 실행한다. WebKit이 필요하면 `Web/node_modules/.bin/playwright-core install webkit`을 실행한다.

```sh
npm --prefix Web test
npm --prefix Web run smoke
npm --prefix Web run smoke -- --device-matrix
HM2_WEB_ENGINE=webkit npm --prefix Web run smoke -- --device-matrix
```

`HM2_WEB_TEST_EVIDENCE`에 절대 경로를 주면 장면 캡처와 기기별 판별값, 캔버스 크기, 실패한 버튼 좌표를 기록한다. `HM2_WEB_TEST_DEVICES`에 쉼표로 검사 환경을 지정할 수 있다. 화면 밖으로 나간 버튼을 발견하면 원인을 출력하고 나머지 기기도 검사한 뒤 명령이 실패를 반환한다.

## 화면과 입력 결과

표의 크기는 브라우저 안의 게임 캔버스 기준 CSS 픽셀이다. Chromium 158과 Playwright WebKit 26.0에서 각각 7개 환경을 검사했다. 각 환경의 기본 방향에서 검사용 슬롯으로 타이틀·기지·사령부·상점·전장·포털 복귀를 확인했다. 14개 실행 모두 브라우저와 Wasm의 분류가 일치했다. 축소·회전을 모의한 뒤에는 두 엔진에서 각각 3개 환경의 상점 왕복이 성공했고, 4개 환경에서 같은 배치 오류가 나왔다. OS의 실제 회전과 분할 화면은 별도 검사로 남겼다.

| 재현 환경 | 확인한 범위 | 발견한 문제 |
| --- | --- | --- |
| iPhone 모의, Android 휴대폰 모의 | 각각 734×343, 863×360 가로 화면에서 전장 왕복까지 동작했다. 세로로 줄인 뒤에도 휴대폰 분류와 캔버스 배율이 맞았다. | 393×659 및 412×839의 세로 기지에서 상점 버튼이 오른쪽 화면 밖에 있다. 두 엔진에서 같은 좌표를 얻었다. |
| iPad 모의 | 834×1194 세로 화면에서 전장 왕복까지 동작했다. 데스크톱 UA를 쓴 504×834 모의 창에서도 태블릿 분류로 상점에 들어갔다 나왔다. | 1194×834 가로 상점에서 복귀 버튼 중심이 게임 좌표 `(995, -298.156)`이다. 두 엔진에서 화면 아래로 벗어났다. |
| Android 태블릿 모의 | 640×1024 세로 화면에서 전장 왕복까지 동작했다. | 1024×640 가로 상점에서 복귀 버튼 중심이 `(853.333, -293.333)`이다. 두 엔진에서 화면 아래로 벗어났다. |
| 맥미니 데스크톱, 터치 Windows 데스크톱 모의 | 각각 1366×900과 820×540에서 데스크톱 분류를 유지했다. 상점 왕복과 기본 크기의 전장 왕복이 동작했다. | 검사한 크기에서 주요 이동 버튼이 보이고 눌렸다. |
| iPhone 17 Pro 시뮬레이터 Safari 26.5 | 874×338에서 휴대폰으로 분류했다. 타이틀에서 슬롯과 기지로 진입하고 사령부에서 기지로 돌아왔다. | 기지 오른쪽 위의 Shop과 Exit가 겹친다. Shop의 중심을 터치했을 때 상점 대신 슬롯 화면으로 이동했다. |
| iPad Pro 11 시뮬레이터 Safari 26.5 | Safari가 Macintosh UA와 터치 지점 5개를 보고했다. 834×1124에서 태블릿으로 분류하고 기지·사령부·상점·전장에 진입했다. | Safari 자동 터치로 포털을 눌렀으나 기지 복귀까지 확인하지 못했다. 같은 기본 경로는 iPad 브라우저 모의에서 통과했다. |

Chromium 정식판에서 설치 가능 조건 오류가 0개였다. 서비스 워커가 활성화된 상태에서 네트워크를 끊고 새로고침했다. 게임이 다시 실행됐고 정식판의 검사용 저장이 일치했다. 복구코드 오류·저장소 분리·대화상자 중 창 크기 변경과 WebGL 복구까지 기존 브라우저 검사 14개를 통과했다. 분류 단위 검사 5개도 통과했다. Android는 화면 짧은 변 599·600 CSS 픽셀과 방향별 경계를 단위 검사했다. 접이식 기기의 접힘·펼침 중 재분류는 검사하지 않았다.

## 화면 배치 후속

- 휴대폰 가로 기지의 `Screens::base`는 원본 Phone 표의 버튼을 `DisplayLayout::artScene`으로 확대한다. iPhone 17 Pro Safari 가로에서 관측한 Shop과 Exit의 겹침을 기준으로 시설마다 표시와 터치 영역을 대조한다.
- 태블릿 상점·사령부·기지의 `tabletMenu`는 캔버스를 덮는 배율을 선택한다. 넓은 가로 창에서는 위아래가 잘리고 버튼도 같은 변환을 받는다. 가로·분할 화면에서 원본 비율, 전체 조작부와 배경을 함께 보이는 배치를 정하고 치트판에서 확인한다.
- 배치 수정에서는 저장·게임 규칙과 분리된 표시 정책을 사용한다. 수정 후 기지 여섯 곳의 시설부터 상점의 거래 버튼과 복귀, 사령부의 상세와 복귀까지 그림과 터치 영역을 같은 크기에서 대조한다. 이번 맥미니 검사 범위는 검사용 Ruin Field 기지다.

캡처와 JSON은 로컬 `.local/evidence/pwa-device-validation-20261120`에 있다. `route-screens.jpg`는 기본 방향과 오프라인 화면, `layout-findings.jpg`는 재현한 화면 오류를 모은 그림이다. `final`에는 브라우저별 캡처와 좌표, `simulator`에는 Safari 캡처와 터치 기록, `offline`에는 정식판 오프라인 캡처가 있다.
