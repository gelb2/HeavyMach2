# 맥미니에서 PWA 화면과 입력 검증

기준 커밋은 `a6a798c`다. 맥미니의 로컬 정식판과 치트판을 새 브라우저 프로필에서 연다. 검사용 저장을 만들고 기존 사용자 저장은 건드리지 않는다.

| 환경 | 확인할 화면과 동작 |
| --- | --- |
| 휴대폰 | iPhone과 Android 휴대폰의 세로·가로 화면. 기지에서 상점·사령부·전장으로 실제 터치 이동. |
| 태블릿 | iPad와 Android 태블릿의 큰 화면. 데스크톱 UA를 쓰는 iPad와 좁은 창에서도 기기 분류 유지. |
| 데스크톱 | 맥미니 Chrome과 WebKit의 넓은 창 및 좁은 창. 마우스로 기지에서 상점·사령부·전장으로 이동. 터치가 있는 데스크톱도 확인. |
| 경계 조건 | 회전·창 크기 변경, 600 CSS 픽셀을 기준으로 나뉘는 Android 화면, 접이식 화면 크기, 설치 캐시의 오프라인 재실행. |

1. 브라우저의 화면 크기·UA·터치와 `Web/Shell/display.js` 판별값을 기록한다. `app.js`가 Wasm에 넘긴 값과 공통 화면·입력 코드에서 쓰는 값을 확인한다.
2. Chromium·WebKit에서 동일한 게임 경로를 실행한다. 버튼의 실제 화면 위치에 클릭이나 터치를 보내 올바른 장면으로 진입하는지 확인한다. 창 크기 변경 후 캔버스의 비율, 화면 그리기, 입력을 다시 검사한다.
3. 사용할 수 있는 iPhone·iPad 시뮬레이터에서 Safari를 열어 화면을 확인한다. 맥미니의 Chromium 정식판에서 서비스 워커가 제어하는 상태로 네트워크를 끊어 다시 실행한다.
4. 실패한 조건은 재현한 다음 관련 모듈을 수정한다. 두 웹 판을 다시 빌드하고 해당 조건과 나머지 화면을 재검사한다. 검사 결과와 캡처 파일을 빌드 버전에 연결한다. 실제 기기에서만 확인할 수 있는 항목은 투두에 남긴다.
