# iPhone 공통 개발 기준·계획·금지사항

2026-11-14 공통 줌 수정 계획: [담당 모듈·후보 배율·검사 기준](common-camera-plan-20261114.md)에 따라 공통 C++ `CameraPresentation`에서 화면 구성별 정책을 결정한다. iOS/Android 앱별 줌 수식·기종 분기를 금지한다. 현재 iPad 배율1을 보존하고 휴대폰 대기 배율1.0을 첫 수정 후보로 검사한다. 화면 채움 값을 확대 계수에 곱하지 않으며 출력·입력은 같은 카메라 결과를 사용한다. 아직 계획 단계다.

2026-11-14 최신 절차: [최근 TODO 수정·계측 계획](iphone-fixes-and-profiling-plan-20261114.md)을 따른다. 원작의 에셋 로딩·재사용·렌더러 전달·캐시 수명/해제 절차를 준수한다. 구현을 마친 뒤 치트빌드·시뮬레이터를 검증하고 실제 기기의 정식 Release를 Xcode Instruments로 계측한다. 메모리 누수·잔류 증가·프레임 지연·CPU/GPU/열 상태를 실제 기록으로 확인하며 추적기 없는 대조 실행을 분리한다. 시뮬레이터나 짧은 누수0 기록으로 실기기 발열 해결을 대신하지 않는다.

2026-11-14 가변 줌 추가 지시: 사용자는 iPhone에서 화면에 보이는 적의 락온은 되지만 월드 줌인·줌아웃이 동작하지 않는다고 정정했다. 월드 출력 영역을 화면 전체로 고정하는 요구는 카메라 배율을 고정하라는 의미가 아니다. iPad에서 관측한 원거리 락온 시 줌아웃/상황별 줌인과 대조해 보이는 월드 범위가 변하도록 조사·수정한다. HUD 크기·입력 대응·검은 레터박스 금지를 함께 유지한다. 현재는 [TODO](todo.md)에 등록한 미해결 항목이다.

## 표시 크기와 좌표 설계

### 2026-11-13 실기기 수정 계획 — 검은 레터박스 금지

사용자 관측: 적을 공격하면 줌과 함께 월드가 차지하는 사각형까지 커졌다 작아지며, HUD는 작은 크기로 유지된다. 앞선 실제 iPhone 조작에서도 기지·사령부의 세로 배치와 설명/목록 잘림을 확인했다. 기존 시뮬레이터 통과를 이 문제들의 합격 근거로 재사용하지 않는다.

1. **전장 전체 출력:** 화면 전체를 월드 출력 범위로 사용한다. 노치·홈 표시줄의 안전 영역은 HUD/버튼 배치에 사용하고 전장을 검게 자르는 데 사용하지 않는다. 출력 사각형은 선택/해제·사격·경로·줌과 무관하게 고정한다.
2. **맵 경계와 줌:** 맵1024단위보다 넓은 시야를 축소 배율로 출력해 검은 바깥을 드러내는 경로를 고친다. 같은 맵 자원과 월드 좌표를 유지하고, 화면을 채울 최소 배율과 카메라 경계를 함께 계산한다. 원작의 선택적 배경은 같은 자원으로 출력 범위를 채운다. 현재보다 더 넓은 월드를 임의로 생성하거나 지형·충돌·공격 수치를 늘리지 않는다.
3. **HUD 크기:** 현재 작은 화면의0.5배 HUD를 키우고 유효 폭/높이 안에 배치한다. 전투 줌이 HUD를 확대·축소시키지 않게 한다. 실제 그림·clip·버튼·무기 목록·퀵슬롯 드롭과 Player 보호 하단이 같은 배율을 사용해야 한다.
4. **기지·사령부:** 원본 배경을 화면 전체에 표시한다. 기지의 테이블 버튼은 같은 이미지·ID·콜백을 사용해 겹치지 않게 배치하고 설명창과 EXIT의 영역을 분리한다. 사령부 목록은 실제 목록/상세 높이를 기준으로 처음부터 위쪽에 표시하고 필요한 범위만 스크롤한다. iPad의 원래 테이블 배치와 동작은 보존한다.
5. **나머지 메뉴:** 상점·정비·슬롯과 전환에서도 검은 테두리를 남기지 않는다. 배경 확장과 UI 재배치를 구분하며 상품24개·인벤토리25칸·에어리프트6행·퀵슬롯5개를 보존한다.
6. **검사:** 공통 C++에서 줌별 출력/역입력·맵 경계·HUD 크기·기지 설명/EXIT 분리·3행 및 최대 임무 목록 시작/스크롤을 검사한다. 정식/치트 공통 구현을 마친 뒤 양 시뮬레이터에서 기존115조건 동시 실행과 GPU 캡처·입력을 묶어 검사한다. 화면 가장자리의 검은 띠와 공격 전후의 출력 사각형을 실제 픽셀로 확인한다. 통과 후 iPhone 정식 Release를 갱신하고 같은 메뉴·전투 경로를 직접 확인한다. 기존 iPad/iPhone 저장은 백업 후 보존한다.

이 절은 수정 계획이다. 구현·검사·설치는 실행한 결과를 따로 기록한다. 이번 요청에 develop/main 병합은 포함하지 않는다.

1. 이미지 픽셀 수, HD 월드 단위, UI 배치 단위, 화면 point, drawable pixel을 구분한다. HD 그림의 픽셀 수를 곧바로 오브젝트 크기로 쓰지 않는다.
2. 메크·무장·탄환·이펙트·그림자·이동 마크·지형·게이트는 같은 월드 표시 변환을 사용한다. 파츠별 임의 보정을 추가하지 않는다.
3. HUD·상점·인벤토리·임무창·도움말·팝업은 월드 줌과 별도로 배치한다. 생성 좌표와 이후 갱신 좌표에 같은 구성을 전달한다.
4. 호스트는 실제 bounds·pixel scale·안전 영역·방향을 공통 코어에 전달한다. 구체적인 새 타입 이름과 API는 구현 시 정하며, 아직 코드에 존재한다고 쓰지 않는다.
5. 표시와 입력에 같은 변환과 역변환을 사용한다. OS 입력→공통 화면→overlay/UI→월드의 좌표 소유자를 명시하고, renderer 변환과 카메라 역변환을 중복 적용하지 않는다.
6. 버튼뿐 아니라 도움말·아이템 선택/끌기·퀵아이템·이동 경로·적 선택·공습/수리 좌표까지 연결한다. 입력 우선순위·누름/이동/해제/취소·멀티터치 소유권을 유지한다.
7. 기존28×31·46×53 같은 표본은 보존하되 고정 기기 배율로 쓰지 않는다. 장비·적 ID·방향·애니메이션 프레임·표적/경로·현재/목표 줌을 묶은 원작 장면과 연결한다.
8. 넓어진 화면에서 메크·HUD를 함께 확대하지 않는다. 검증한 표시 크기를 유지하며 전장 시야와 패널 배치를 계산한다. 보이는 적의 선택·명중·AI·재생성이 화면과 어긋나지 않아야 한다.

## 구현과 검사 순서

1. **조사 마감:** 카메라/투영/역변환, 화면 판정과 전투 결합, 전체 UI 입력 경로, 저장·시간·음향 사건을 근거와 연결한다. 미확정은 정적 추적 가능·원작 실행 필요·제품 채택 결정으로 나눈다.
2. **표시 기준 확정:** 같은 조건의 원작 메크·적·지형·HUD 크기와 카메라 상태를 기록한다. 원작 일반판은 iPhone 구성, HD는 iPad 구성에서 확인한다. 일반판의 알려진 검은 지형 오류를 정상 기준에 포함하지 않는다.
3. **공통 화면 구성 연결:** 호스트→Session/카메라/Screens/도움말/퀵아이템/전환의 소비 경로를 연결한다. iPad 기준에서는 기존 표시·입력 결과를 유지한다. 초기화·화면 변경 시 필요한 자원을 준비하며 매 프레임 다시 읽지 않는다.
4. **공통 iPhone 배치 구현:** 월드 표시, HUD·패널·합성 화면, 표시와 입력의 역변환을 한 묶음으로 구현한다. 원작 코드 분석은 재사용하고 기능 하나마다 포팅판을 열어 왕복하지 않는다.
5. **치트 구성:** 각 독립 Session 자체에 실제 iPhone 가로 또는 iPad 세로 구성을 넣는다. 외부 모음 화면의 폭만 바꾸지 않는다. 실제 화면 좌표의 자동 입력도 같은 배치를 사용한다.
6. **동시 검사:** 이동·조준·발사·피격·BOT·아이템 획득·성장·임무·메뉴·저장 조건을 같은 프레임 구간에 실행한다. 서로 배타적인 화면은 독립 상태로 실행하고 해당 게임 상태의 pause 규칙을 유지한다.
7. **정식판·시뮬레이터 확인:** 한국어 메뉴·보통 진행·장착·임무·저장/재실행·음향과 기기별 표시/입력을 확인한다. 작은/큰 iPhone, 양쪽 가로 방향, 비대칭 안전 영역과 현재 iPad 기준을 포함한다.
8. **최종 일괄 대조·실기기:** 필요한 원작/정식/치트 일괄 대조를 마친다. 시뮬레이터 검사 통과 후 저장을 백업하고 실기기에서 확인한다. 설치·develop/main 병합·릴리스는 각각 결과와 승인 범위를 구분한다.

원작 실행에서만 알 수 있는 항목을 임의 구현으로 채우지 않는다. 해당 항목의 시작 상태·입력·기대 관측·필요한 원작 구성을 먼저 적고 묶어서 확인한다. 모든 캠페인 검사를 iPhone 화면 기반 구현의 선행 조건으로 추가하지 않으며, 기존 미해결 퀘스트 TODO도 삭제하지 않는다.

같은 HD 규칙을 사용해도 표시 범위가 다르면 활성화·명중 후보·재생성·난수 소비가 달라질 수 있다. 기기 간 모든 전투 상태 hash가 무조건 같아야 한다는 기준을 만들지 않는다. 같은 카메라·시작 상태의 회귀와, 확장한 시야에서 원본 분기대로 발생하는 차이를 나눠 기록한다. 기존 전투 영역을 고정해 바깥의 보이는 적을 선택·명중할 수 없게 만드는 방식으로 수치만 맞추지 않는다.

## 하면 안 되는 것

다음은 기존 사용자 지시와 이번 조사에서 확인한 제약이다.

- iPhone 전용 에셋 묶음·별도 게임 코어·유닛별 C++ 정의/조립/그리기 우회를 만들지 않는다.
- 파일 확장자만 바꾸거나 원작 데이터를 임의 JSON·다른 형식으로 위장하지 않는다. 원본·신규 유닛 모두 같은 reader·파츠 조립·애니메이션·공격·패키징을 사용한다.
- 화면에 맞추려고 월드의 충돌 반경·이동 속도·사거리·피해·SP·인벤토리 용량·임무 조건을 기기별로 바꾸지 않는다.
- 모든768/1024/60 같은 수치를 화면 크기로 일괄 치환하지 않는다. 카메라 여유·레이더 월드 변환·스폰 거리·전환 시간에는 서로 다른 의미가 있다.
- HD 세로 화면을 통째로 가로에 넣은 출력만으로 iPhone 배치 완료라고 보고하지 않는다. 원작과 다른 표시 크기·누락·가독성·터치 어긋남을 숨기지 않는다.
- 매 사격·피격·획득·프레임마다 DB/파일을 쓰지 않는다. 예열과 재생을 구분하지 않고 오디오 context/source/buffer를 매번 만들거나 해제하지 않는다.
- 효과음을 AVAudioPlayer/AVAudioEngine으로 임의 대체하지 않는다. 원작 BGM AudioQueue와 OS 장치 연결은 별도로 보존한다.
- UIKit으로 인게임 그래픽·HUD·버튼을 만들지 않는다. 기존 OS 입력·시스템 이름 입력·확인창과 게임 화면을 구분한다.
- Python/Ruby 게임 런타임·Three.js·새 게임 엔진을 추가하지 않는다. 기존 분석용Python, Apple호스트Objective-C++, 후속 플랫폼의 기존 어댑터 역할을 혼동하지 않는다.
- 치트에서 명중·격파·획득·보상·레벨업·임무 성공 결과를 강제로 주입해 통과시키지 않는다. 시작 조건과 자동 입력을 준비하고 실제 공통 게임 동작을 실행한다.
- 테스트를 하나씩 눌러 확인한 것을 동시 검사 완료라고 보고하지 않는다. 렌더 모음 화면 크기만 바꾼 것을 각Session의 iPhone 검사라고 보고하지 않는다.
- 구현 중 기능 하나마다 포팅판/복원판 빌드·실행을 왕복하지 않는다. 원본 HD를 iPhone에서 실행해 HD 정상 여부나 일반판 표시 기준을 판정하지 않는다.
- 시뮬레이터 실패를 둔 채 실기기에 빌드하지 않는다. 무료서명·연결 제한을 피하려고 사용자 앱·저장을 임의 삭제하지 않는다.
- 원본 IPA·실행파일·전체 디컴파일·전체 복호 테이블·사용자 저장·서명 비밀을 Git/LFS/릴리스/보고 사이트/외부 분석 서비스에 보내지 않는다. 비공개 저장소도 예외가 아니다.
- 다른 두 게임·구 checkout·허브 파일을 수정하지 않는다. 사용자 원고·커밋·원본·현재 iPad 저장·실패 증거를 임의 롤백·초기화하지 않는다.
- main/develop에 직접 기능 커밋하거나 feature를 main에 직접 병합하지 않는다. 공유 이력 reset/force-push·태그 재지정·가드 우회를 하지 않는다.
- 사용하지 않는 빌드를 계속 쌓아 두지 않는다. 현재 검증 후보·재현에 필요한 빌드·원본·저장·실패 증거를 구분하고 사용 여부를 확인한 뒤 재생성 가능한 출력만 정리한다.
- 함수 export·파일 개수·컴파일·형식 검사·기존 iPad 성공을 전체 의미 조사·iPhone 실행·실기기·릴리스 완료로 바꾸어 말하지 않는다.
- 오래된 `Screens::coverage()` 등록값·주소만으로 실제 기능의 구현/미구현을 판정하지 않는다. 원본 함수·실제 소비 코드·실행 근거를 연결하고 등록표의 오래된 값은 별도 TODO로 관리한다.
