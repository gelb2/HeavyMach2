# 일반판·HD 포팅판 표시·입력·전투 대조

2026-11-10. 일반판2.0.1을 iPhone Air, HD1.0.3을 iPad Air 11-inch (M4)의 iOS/iPadOS26.5 시뮬레이터에서 실행했다. 기존 포팅 앱을 사용했다. 새 앱 빌드·실기기 설치·복원 코어 구현은 하지 않았다.

## 판단

두 포팅판에서 전장 터치에 따른 이동, 적 선택, 격파, 임무 진행1/5, 재화500→503Cr를 확인했다. 포팅판 대조로 표시·입력·공격 결과를 판별할 수 있다. 이번 시험은 같은 장비 ID·월드 거리·시간을 고정한 정밀 경계 비교까지 수행한 것은 아니다.

HD 동작·그래픽을 공통 기준으로 삼고 기기별 표시 크기를 연결하는 방향은 유지한다. 다음 세 가지를 복원 계획에 추가한다.

1. **그림·선택·명중을 각각 복원한다.** HD의 터치 대상 선택은 반지름 비교를 사용한다. 조사한 탄환 충돌 경로는 살아 있는 적의 `isInScreen`을 확인하고 `isInPtX:Y:`를 호출한다. 기반 클래스의 후자는 월드 위치와 `boundRect`를 사용한다. 그림의 투명 경계를 충돌 도형으로 임의 대체하지 않는다.
2. **카메라와 전투의 연결을 보존·검증한다.** HD 기반 클래스는 카메라 범위와 여유60을 사용해 표시 여부를 갱신한다. 이 값이 탄환 충돌 후보 조건에 들어간다. 표시 시야만 넓혀도 원작의 명중 가능 대상이 달라질 수 있다. 시야 확장만으로 HD 전투가 그대로 유지된다고 가정하지 않는다.
3. **두 판본의 데이터 차이를 구분한다.** WeaponInfo213행 중126행이 다르다. 기기별 배율만으로 두 판본의 공격 결과를 같게 만들지 않는다. 복원판 전투는 HD 규칙과 대조한다. 일반판은 iPhone 표시와 원작 동작 차이의 비교 자료로 유지한다.

일반판 영상10초에는 이동 표식과 지형이 보인다. 20초에는 선택 적의 HP 막대와 공격 효과, 지형의 검은 영역이 보인다. 27초에는 격파 임무1/5와503Cr가 보인다. HD 영상90초에는 선택 적의 HP 막대, 96초에는 폭발과 임무1/5가 보인다. 별도 격파 직후 캡처에서503Cr를 확인했다. 단일 탄환의 경로·정확한 피해량을 모두 추적했다는 뜻은 아니다.

녹화 시간은 호스트 시간이다. 두 영상의 같은 초가 같은 게임 상태나 같은 전투 시간을 뜻하지 않는다. HD의 긴 영상에는 분석 중 대기 구간이 포함돼 있다. 일부 적 터치는 이동 때문에 빗나가 다시 눌렀다. 같은 화면 픽셀을 같은 월드 입력으로 취급하지 않았다.

저장은 시험 전에 백업하고 시험 후 파일도 별도로 보존했다. 두 판본의 저장 길이는26344/28204바이트로 다르다. 서로 덮어쓰거나 초기화하지 않았다. 시험 후 해시 변화는 기록했지만 저장 내용을 해석하거나 재실행 복구까지 확인한 것은 아니다.

## HD 실행파일에서 확인한 경로

Ghidra12.1.4로 원본 ARM 실행파일을 읽었다. 아래는 원본 소스가 아닌 역분석 결과다. 구조와 조건 분기는 확인했으나 디컴파일러의 부동소수점 인자·CGPoint 표현을 그대로 구현하지 않는다. 실제 ARM 호출 규약과 명령을 추가 대조한다.

| 함수·주소 | 확인한 내용 |
|---|---|
| GobWorld::onTap_EasyMove:State:ID: `0x12698` | 카메라·halfScr를 사용하는 입력 변환. HP가 양수인 적에 대해 거리 제곱과 정보 반지름 제곱을 비교해 대상을 선택. 선택 적에 setTarget 전달. 이미 선택한 적을 다시 누르는 경로에는 setMoveToTarget 호출 |
| GobWorld::checkBulletCollideX:Y: `0x10ddc` | 적 목록 순회 → HP>0 → isInScreen → isInPtX:Y:. 처음 일치한 적 반환. 이 함수로 모든 무기·폭발 판정을 설명하지 않음 |
| QobBase::isInPtX:Y: `0x36a40` | 월드 위치에 boundRect 최소·최대 좌표를 더한 사각형과 점 비교 |
| QobBase::tick `0x36d98` | show·visual·remove 조건 아래 isInCam 결과를 _isInScreen에 기록하고 표시 등록 |
| QobBase::isInScreen `0x3689c` | _isInScreen 조회 |
| QobBase::isInCam `0x37750` | 화면 위치·boundRect와 -60부터 2×halfScr+60 범위 비교. 카메라가 없으면 참. 60은 이 함수 좌표의 값이며 현대 출력 픽셀60으로 고정하지 않음 |
| GobWorld::processCamera `0x11cac` | 플레이어·선택 적·이동 목적지에 따른 카메라 이동과 제한 처리. 화면 배율만 조정해 대체하지 않음 |

추가로 원본 ObjC class-list80개의 인스턴스 메서드를 읽었다. `GobHvM_Enemy → GobHvMach → QobBase` 상속을 확인했다. 이 클래스 목록에서 해당 적·메크 클래스의 isInPt/isInScreen/isInCam 재정의는 없었다. GobBullet·일부 효과에는 isInCam 재정의가 있으므로 기반 클래스 하나로 모든 오브젝트를 처리하지 않는다. category·실행 중 메서드 교체와 전체 호출 경로는 미확인이다.

일반판 ARMv7에는 GobWorld 등 C++ RTTI 문자열이 있고 HD에서는 위 ObjC 메서드가 확인된다. 일반판의 동등 충돌 함수를 아직 특정하지 못했다. 이름·동일 MCB만으로 두 바이너리의 내부 구현이 같다고 하지 않는다.

## 보강한 복원·검증 순서

1. **비교 입력 고정:** 두 포팅 앱의 실행기 코드 해시·게스트 판본·slice·기기·방향·옵션·저장 사본을 기록한다. 이번 두 호스트의 `__text` 해시는 다르다. 같은 소스/패치 기준의 검증된 실행기 후보로 재검사하되, 기존 실패 증거와 앱은 보존한다. 전체 파일 해시와 서명 전 패키징 해시도 구분한다.
2. **기준 장면 고정:** 각 판본에서 맵·임무·플레이어/적 ID·장비 ID·월드 좌표·방향·카메라 중심·배율·갱신 시간을 확인한다. 저장 형식이 다르므로 저장 파일을 서로 복사하지 않는다. 원본 전투를 바꾸지 않는 호환 계층 관측으로 입력→월드 좌표·HP·발사/명중 시점을 연결한다. 난수 상태를 관측·재현할 수 없으면 반복 분포와 조건을 기록한다.
3. **HD 기준 코어 복원:** 터치 선택 반지름, 탄환 boundRect, HP 조건, 적 목록 우선순위, 표시 여부 갱신 시점, 무기별 발사·피해·사거리 규칙을 데이터와 소비 함수에 연결한다. 탄환·유도탄·폭발 등 경로별 누락을 조사한다. 임의 공통 원/사각형 하나로 치환하지 않는다.
4. **최초 두 구성 검증:** iPhone 가로·iPad 세로에서 HD 기준 코어와 각 기기 표시 크기를 연결한다. 렌더링과 입력 역변환은 같은 카메라 변환을 사용한다. HUD 터치는 월드 선택에 전달되지 않게 검사한다. 일반판 지형 오류를 정상 화면의 기준으로 복제하지 않는다.
5. **경계 검사 후 화면 확장:** 아래 검사를 원작 HD 기준 시야에서 먼저 수행한다. 이어 렌더 시야와 원작 전투 후보 영역을 각각 기록하며 넓은 시야 후보를 검사한다. 카메라에서 비롯한 전투 조건을 삭제하거나 화면 크기에 무조건 연결하지 않는다. 넓어진 화면에서 보이는 적을 선택·명중할 수 없는 문제와, 보이는 범위 변화로 원작 결과가 달라지는 문제를 모두 확인한다. 둘을 동시에 만족하지 못하면 해당 규칙 차이를 명시하고 화면 확장 설계를 고친 뒤 확정한다. HD 규칙을 바꾸고도 배율 조정으로 보고하지 않는다.
6. **방향 확장:** 최초 구성의 표시·전투·진행·저장·음향 검증 뒤 iPhone 세로·iPad 가로를 추가한다. 회전 전후 같은 월드 상태와 HUD 입력을 재검사한다. 포팅판의 시뮬레이터 정상동작 확인 전 실기기 설치 금지는 유지한다.

| 남은 검사 | 고정할 조건·기록할 결과 |
|---|---|
| 터치 선택 경계 | 중심·반지름 안/경계/밖, 겹친 적, 사망 적, 같은 적 재선택. 선택ID·이동목표를 기록 |
| 탄환 명중 경계 | boundRect 네 변·모서리의 안/경계/밖, 정지·이동 적, 발사 위치·갱신 시간·HP 전후·보상 기록 |
| 화면 경계 | 적 boundRect가 카메라 가장자리와 여유60 안/경계/밖에 있을 때 isInScreen·선택·탄환 충돌 비교. AI·스폰·임무 경로의 같은 조건 사용 여부도 조사 |
| 사거리·시간 | 같은 무기 ID의 사거리 안/경계/밖, 탄수·발사 간격·재장전·명중·피해 기록. 일반/HD 테이블 차이와 실행기 차이를 분리 |
| 표시·입력 연결 | 기기별 표시 배율·카메라·줌 변화와 회전 전후 같은 월드 지점 선택, 포구·파츠·효과 정렬, HUD/전장 터치 겹침 검사 |

이번 작업은 위 계획 보강과 첫 전투 관측까지 완료했다. 같은 조건의 경계 검사, 일반판 지형 수정, 저장 복구·실제 음향, 전체 전투 경로 및 유니버설 구현은 미완료다.
