# ExperimentalHUD·허브·상점·사령부 수정

## 현재 결과

ExperimentalHUD의 11개 독립 조각과 좌우 무기 선택 패널 2개를 구현했다. Phone 허브·상점·사령부는 원본 Phone 삽화 전체를 표시하고, 세로 스크롤 없이 버튼·품목·설명에 접근하도록 바꿨다. 공통 C++ 코드와 기존 GPU·자원 reader를 사용한다.

최신 공통 CPU 검사 5개와 ASan/UBSan 검사 3개 및 변경 후 관련 검사를 통과했다. Apple 최종 GPU 검사는 iPhone·iPad 각각 9/9를 통과했다. 두 전장 실패 조건의 실제 캡처에서 검은 대각선이 사라졌다. 정식·치트 Simulator Release와 준비 자원 1,532개씩의 바이트 일치, 실행파일/dSYM UUID 일치를 확인했다. 실제 iPhone 설치본은 기존 `3666fc7`이다. develop/main 병합은 하지 않았다.

## HUD 구성과 이동

| 독립 조각 | 보존한 기능 |
| --- | --- |
| HP | 원래 표식·바탕·HP 잔량 막대 |
| BOOSTER/SP | 원래 표식·사용 가능 색·잔량 막대 |
| EXP | 원래 표식·경험치 막대 |
| 레벨 | 원래 숫자 이미지·증감 표시 |
| 보유금 | CR 표식·원래 금액과 숫자 이미지 |
| 왼쪽·오른쪽 무기 | 각 버튼·무기 그림·선택과 사거리 표시 |
| 퀵아이템 5슬롯 | 빈 등록 칸·그림·수량·선택 상태 |
| 메뉴 3버튼 | MENU·MISSION·ITEM과 눌림 상태 |
| 레이더 | 격자·기존 월드 좌표로 갱신하는 모든 마커 |
| 대상 정보 | 원래 조건으로 나타나는 대상 이름·HP |

큰 금속 배경판과 기능 없는 장식만 덜어냈다. `GameUI_BG.png`에서 필요한 표식·바탕·슬롯·격자를 기존 UV 영역으로 읽는다. 원본 그림 파일은 바꾸지 않는다. HP·SP는 현재 소비 중인 `GameUI_GaugeBack.png`, EXP는 `GameUI_GaugeEXP.png`, 레벨·금액은 기존 숫자 이미지를 사용한다. 새 숨김·접기·레이더 열기/닫기를 넣지 않았다.

좌우 무기 선택 패널도 별도의 편집 대상이다. 해당 무기 버튼의 이동을 따라가며 버튼 기준 상대 위치를 따로 저장한다. 실제 보유 인벤토리 위치·ItemCode와 원래 장착 동작은 유지한다. 화면 안쪽에 펼치고, 긴 목록은 6행 단위 페이지로 모두 접근한다.

스테이지 메뉴 → HUD 배치에서 클래식과 Experimental을 선택한다. 조각을 직접 끌거나 ‘다음 조각 선택’ 후 고정 이동 핸들을 끈다. 편집 도구에 가린 조각도 이 핸들로 꺼낼 수 있다. 화면 끝까지 배치할 수 있고 안전영역을 강제 여백으로 쓰지 않는다.

설정 버전 3은 기존 버전 1·2를 읽는다. 클래식 3조각과 Experimental 13개 배치를 별도로 보관한다. 적용할 때만 설정을 기록한다. 드래그·그리기·전투 중 설정이나 게임 저장을 쓰지 않는다. 편집 문구 16개를 처음에 준비하며 선택·이동마다 문자를 다시 만들지 않는다.

## 허브·상점·사령부

Phone 삽화는 원래 비율로 전체를 표시한다. 시설·길 버튼과 선택 강조는 삽화와 같은 변환을 사용한다. 남는 좌우·하단에는 기존 게임 패널을 이용해 품목·목록·설명·동작 버튼을 둔다. 원본 게임 패널의 어두운 색은 화면에 남는다. 빈 레터박스나 늘린 삽화로 여백을 채우지 않는다.

- 허브 6곳의 삽화·시설 버튼·선택 설명·임무 알림을 같은 공통 배치로 연결했다. 내부 ID인 Base001을 안내 문구로 노출하던 부분도 고쳤다.
- 상점 24개 상품과 인벤토리 25칸을 유지한다. 원래 Phone 그림의 16/20칸과 HD에서 추가되는 8/5칸을 함께 배치한다. 원래 슬롯 번호·장비·BOT·드롭 좌표를 유지한다.
- 상세 패널과 BUY·SELL·EXIT를 분리했다. 화면에 보이는 실제 버튼 좌표로 선택·구매·판매를 검사했다. 실제 GameSession의 아이템·금액 반영과 거래별 파일 쓰기 0을 확인했다.
- 사령부의 새 임무/받은 임무 각 5행과 원래 임무 ID·수락·완수·보상을 유지한다. 긴 설명과 보상은 페이지로 나눈다. 원래 동작 버튼 5100/5200/5004/5007을 연결했다.

위 Phone 배치는 공통 화면 모듈에서 처리한다. UIKit 게임 버튼이나 별도 iPhone 게임 코어를 추가하지 않았다. iPad의 기존 메뉴 경로는 유지했다.

## 발견한 결함과 수정

| 발견한 문제 | 수정과 검사 |
| --- | --- |
| 잘라낸 HUD 표식이 다른 조각과 중복 | 실제 불투명 픽셀을 기준으로 기능 영역을 분리하고 중복 소유 0 확인 |
| 최대 HP 막대 끝 잘림 | 조각 범위에 최대 막대 끝을 포함 |
| 무기 선택 패널 핸들 역선택·그림/입력 크기 불일치 | 양쪽 핸들을 분리하고 동일한 표시·터치 변환 적용 |
| 편집 도구가 조각을 덮음 | 고정된 선택 조각 이동 핸들 제공 |
| 취소·프로필 변경 후 선택 인덱스 범위 초과 | 현재 스타일의 조각 수로 제한하고 재진입 검사 추가 |
| 마지막 메뉴 버튼의 눌림 그림 3px 잘림 | 원본 pressed 타일의 불투명 끝 771과 터치 끝 769를 포함하도록 범위 보강 |
| 레이더 가장자리에서 BOT 마커 잘림 가능 | 격자와 현재 마커의 합친 범위를 계산하고 그룹 전체에 필요한 최소 이동만 적용. 마커 간 거리·월드 좌표·배율·저장 앵커는 보존 |
| Phone 전장 검은 대각선 | 기존 사각형과 화면의 교집합만 제출하고 원래 이미지 UV를 보간. 카메라·맵·유닛·이미지 비율·색·블렌드는 유지 |

전장 결함은 같은 90프레임을 다시 그려도 RGB 차이가 0이며 지형만 그려도 재현됐다. 107번/90프레임은 명시적 strip을 없애면 정상화됐지만, 56번/360프레임의 Retina 2736×1260에서는 직사각형 경로도 실패했다. 같은 원본 프레임에서 보이는 사각형만 제출하고 원래 UV를 보간한 경우만 정상 지형색을 표시했다.

최종 공통 MapPreview는 화면 밖 부분만 제출에서 제외한다. 원본 Sprite의 중심·크기와 이미지 픽셀은 유지한다. 잘린 사각형을 새 크기로 늘려 그리지 않는다. 38개 맵×두 화면×네 모서리와 비정수 카메라/오프셋·네 경계·전체 포함·빈 교집합을 검사했다. 모든 제출 정점이 원래 이미지의 같은 위치를 가리킨다. 최종 GPU 검사에서는 두 실패 조건의 3개 표본이 모두 정상 지형색이며, 이미 잘린 사각형의 재제출 RGB 차이는 0이다. 특정 GPU 드라이버 내부 원인까지 확정한 결과는 아니다.

## 검증 범위

최신 CPU 5/5와 ASan/UBSan 3/3을 통과했다. HUD 값·그림·입력·배치 저장, 실제 구매/판매·사령부 동작, 38개 맵 경계를 검사했다. 원래 장비 23종을 공통 reader로 실제 장착했으며 최대 SP 320·막대 최대폭 146을 확인했다. 예열 뒤 100회 HUD 갱신 중 자원 읽기·문자 준비·설정 쓰기 증가는 0이다.

iPad 126조건과 혼합 배치 중 iPad 98조건을 각각 1,200프레임 실행해 이전 기록과 대조했다. 게임 상태·저장 차이는 0이다. 화면 차이는 HUD 편집 조건 119번뿐이다. 새 HUD의 의도된 편집 화면 변경과 기존 플레이 회귀를 구분했다.

최초 Native 검사는 Phone/iPad 각각 8/8을 통과했으나 실제 캡처에서 전장 결함을 발견해 최종 합격으로 사용하지 않았다. 사령부 전용 GPU fixture는 제어한 UI 상태이며 원작 플레이 재현이라고 부르지 않는다. 실제 공통 Screens·원본 타일·한국어 글꼴·GPU를 사용하며 게임 프레임과 저장은 고정한다. 반복한 한국어 글자는 긴 설명의 페이지·글꼴 검사 입력이다. 실제 임무 원고로 교체한 것이 아니다. 최초 iPad 한국어 검사 실패는 빈 설명 상태에서 한국어를 요구한 검사 입력 문제였다. 선택 시설·한국어 설명과 연출 정착 시간을 제공한 뒤 같은 글자 검사를 통과했다. 이전 실패 로그는 보존했다. 레이더의 첫 추가 검사도 메뉴를 겹치게 둔 입력 때문에 Apply가 정상 거절됐다. 해당 거절 검사를 남기고 저장 검사를 별도 배치로 분리해 통과했다. 최종 Native 9개씩은 지형·클래식/Experimental·360프레임 동시 메뉴·사령부 fixture·조립 GPU를 재검사한 결과다. 앞선 전체 동시 실행은 Phone 126조건 2,100프레임, iPad 126조건 1,200프레임이었다.

## 계측과 한계

기존 Simulator Release 치트에서 Instruments Time Profiler 30.589초·24,990샘플을 확보했다. 초기 준비와 126조건 부하가 포함되어 일반 플레이 FPS로 해석하지 않는다. Allocations/Leaks trace는 생성됐으나 실제 할당·누수 표가 없어 메모리 합격 근거로 사용하지 않았다. 별도 macOS leaks CLI의 한 프로세스 스냅샷은 1,155,434노드·835,347KB 중 누수 0건/0바이트였다. 수정 뒤 최종 Release는 Time Profiler 30.766초·26,182샘플을 확보했다. 실행파일 SHA와 dSYM/trace UUID를 연결했다. 같은 치트 프로세스의 leaks CLI 스냅샷은 1,153,833노드·846,521KB 중 누수 0건/0바이트다. 이는 한 시점의 검사이며 실기기 발열·전체 수명의 무누수 판정은 아니다.

실제 iPhone 발열·전체 앱 수명의 무누수·모든 임무/캠페인 동등성은 이번 Simulator 검사로 확정하지 않는다. 원본 IPA·실행파일·전체 디컴파일·사용자 저장은 보고 사이트에 올리지 않는다. 실패 캡처와 로그는 로컬 증거에 보존한다. 보고 사이트에는 최종 캡처와 대표적인 수정 전 실패를 구분해 올린다. 보고 페이지 브라우저 확인은 연결 호스트가 없어 실행하지 못했다. HTML·링크·원본 PNG와 게시 결과는 별도로 검사한다.
