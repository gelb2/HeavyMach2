# 복구코드로 저장 옮기기

[플레이 안내](public/quick-play.md) · [플랫폼과 설치](canonical.md#플랫폼과-검증-현황)

복구코드는 **슬롯 세 개 전체**를 옮긴다. 임무·기지·지도·레벨·경험치·크레딧·보유 아이템과 장비가 들어간다. HUD 배치 설정은 각 앱의 별도 기록이다. 한 기기에서 이어서 플레이한 진행을 다른 기기에 옮기려면 새 코드를 만든다.

1. 원본 앱의 슬롯 화면에서 **저장 이동**을 연다. iPhone·iPad·Android에서는 **코드 복사**, PWA·Tauri에서는 **코드 만들기 → 복사**를 누른다. 코드 전체를 다른 기기에서도 볼 수 있는 개인 메모에 보관한다.
2. 받을 앱에 보존할 진행이 있으면 같은 방법으로 먼저 그 앱의 코드를 만든다.
3. 받을 앱에서 **저장 이동**을 열어 코드를 붙여넣는다. PWA·Tauri는 **코드 확인 → 슬롯 교체**를 누른다. Apple·Android는 **코드 입력 → 코드 확인 → 슬롯 교체**를 누른다.
4. 교체한 슬롯을 골라 **OK**로 시작한다.

PWA 저장은 브라우저 오리진의 IndexedDB에 있다. 스킴·호스트·포트를 바꾸려면 **기존 설치 주소의 앱**에서 코드를 먼저 복사한다. 같은 오리진에서는 정식판과 치트판의 저장 이름이 다르다. 복구코드는 운영체제 사이에서 옮길 수 있으며 저장을 실시간으로 동기화하지 않는다.

공통 형식은 `HM2-1-`이다. 다른 형식, 잘린 코드와 현재 앱에 없는 맵은 교체 전에 거부한다. 현재 내장 캠페인과 호환되는 빌드를 사용한다. 슬롯 화면의 **저장 이동** 버튼이 없다면 기존 앱 위에 기능이 들어간 정식 빌드를 설치한다.

## 복구코드로 레벨 22부터 시작하기

[레벨 22 복구코드](public/saves/level-22.txt)는 초반 레벨업을 건너뛰고 플레이하려는 사람을 위한 예시다. 1번 슬롯의 이름은 `XP SAMPLE`이다. 경험치 **366,785 EXP**, 레벨 **22**, 크레딧 **38,417 Cr**로 Ruin Field Base에서 시작한다. 초기 장비를 갖추고 있으며 임무 진척도는 0%다. 2번과 3번 슬롯은 비어 있다.

1. 슬롯 화면의 **저장 이동**을 열고 현재 앱의 복구코드를 복사해 앱 밖에 보관한다. 예시를 적용하면 기존 슬롯 세 개가 모두 교체된다.
2. 예시 파일에서 `HM2-1-`로 시작하는 한 줄 전체를 복사해 같은 메뉴에 붙여넣는다. PWA와 Tauri에서는 **코드 확인 → 슬롯 교체**를 누른다. iPhone·iPad·Android에서는 **코드 입력** 뒤 확인한다.
3. 1번 슬롯의 `XP SAMPLE`을 선택하고 **OK**를 누른다.

### 경험치 복원 검사

정식 PWA v0.2의 [공개 배포 파일](https://github.com/gelb2/HeavyMach2/blob/2eea699b1b030222fe2f3f26860179bb4d0ce467/build.json)을 로컬에서 제공하고, 별도 Mac Chrome 프로필에 설치했다. 새 슬롯을 만든 뒤 이 예시를 **저장 이동**으로 적용했다. 게임 저장을 읽어 1번 슬롯의 값을 대조했다.

| 확인 시점 | 레벨 | 경험치 | 크레딧 |
| --- | ---: | ---: | ---: |
| 복구 전과 복구 전 백업 | 1 | 0 EXP | 500 Cr |
| 예시 코드 적용 직후 | 22 | 366,785 EXP | 38,417 Cr |
| 오프라인 종료·재실행 후 | 22 | 366,785 EXP | 38,417 Cr |

재실행 뒤 게임에서 만든 복구코드는 예시 코드와 일치했다. 1번 슬롯을 열어 Ruin Field Base로 들어갔다. 공통 코어의 `OriginalHDSaveEnvelope`와 `OriginalSessionTransitions` 검사도 통과했다.

## iPhone·iPad 실기기 복구코드

2026년 11월 22일에 iPhone과 iPad 정식 앱에서 저장을 읽었다. 아래에서 한 기기의 코드를 열어 한 줄 전체를 복사한다. 코드를 적용하면 현재 앱의 세 슬롯을 교체한다.

| 기기 | 레벨 | 경험치 | 크레딧 | 복구코드 |
| --- | ---: | ---: | ---: | --- |
| iPhone | 22 | 406,150 | 20,511 | [iPhone 코드](public/saves/iphone-native-20261122.txt) |
| iPad | 22 | 366,785 | 38,417 | [iPad 코드](public/saves/ipad-native-20261122.txt) |

Mac Chrome에 설치한 정식 PWA v0.3에서 두 코드를 각각 가져왔다. 기존 저장을 백업했고, 오프라인에서 다시 연 뒤 경험치와 내보낸 코드가 원본과 같은지 확인했다.

## 개발과 확인

[RecoveryCode.cpp](../Sources/Core/Data/RecoveryCode.cpp)는 저장 전체를 인코딩하고, [GameSession.cpp](../Sources/Core/Session/GameSession.cpp)는 코드 검사 → 기존 기록 백업 → 저장 교체 → 세션 갱신을 담당한다. Apple·Android는 OS 입력과 앱 전용 파일을 연결한다. 웹은 [store](../Web/Shell/storage.js)의 트랜잭션을 기다리고, Mac은 [Tauri 저장 어댑터](../Desktop/Tauri/src-tauri/src/storage.rs)의 교체 결과를 기다린다.

[코덱 검사](../tests/SaveTests.cpp)와 [세션 검사](../tests/SessionTests.cpp)를 사용한다.

| 호스트 | 확인한 동작 | 남은 확인 |
| --- | --- | --- |
| iPhone·iPad | iPhone 시뮬레이터에서 정식 빌드의 Apple 런타임으로 공개 iPhone·iPad 코드 두 개를 가져왔다. 코드 검증, 기존 저장 백업, 재시작한 런타임의 세 슬롯을 대조했다. iPhone Air와 iPad Air에 설치해 각각 재실행했고 전후 저장 파일이 바이트 단위로 일치했다. | 최신 iPad 시뮬레이터에서의 복원과 iPhone·iPad 시스템 복구창의 복사·붙여넣기·교체 전체 검사. |
| Android | 정식 에뮬레이터 앱에서 두 공개 코드를 적용했다. 잘못된 코드 거부, 취소 시 저장 보존, 복원 전 백업, 재실행 뒤 세 슬롯을 확인했다. 갤럭시에 같은 APK를 설치해 재실행했고 기존 슬롯과 **저장 이동 → 코드 입력**을 확인했다. | 갤럭시의 실제 슬롯 교체는 별도 시험 저장으로 확인한다. |
