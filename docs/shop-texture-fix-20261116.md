# 상점 페이지 텍스처 준비 누락 수정 — 2026-11-16

레벨 5의 실제 HD 상품 데이터로 iPhone 상점의 `Icon10113.png` 오류를 GPU에서 재현한 뒤 수정했다. 해당 아이콘은 9개 상품 중 아홉 번째다. Phone 첫 화면은 앞의 8개만 준비하며 다음 표시 페이지에서 이 아이콘을 처음 사용한다. iPad는 처음부터 9개를 준비한다.

## 원인과 수정

`Screens` 내부 페이지는 GameSession 액션 없이 UI를 재구성한다. 정식·치트 실행기는 UI 자원 세대 변경을 감지하면서도, 게임 화면 revision이 그대로이면 새 UI 텍스처를 준비하지 않았다. 보존 목록에 등록하는 것만으로 GPU 업로드가 되지는 않는다.

`HM2GameRuntime.mm`과 `HM2ConcurrentRuntime.mm`에서 UI 준비를 자원 변경 경계로 옮겼다. 화면 전체를 다시 만들 때와 내부 페이지에서 새 자원이 생길 때 모두 첫 그리기 전에 준비한다. GPU는 기존 이름/형식 캐시를 그대로 재사용한다. 매 프레임 로드, 아이콘 대체, 경고 숨김, 게임 데이터/카메라/HUD 배치 변경은 추가하지 않았다.

## 실행 근거

| 실행 | 결과 |
| --- | --- |
| 수정 전 실제 GameRuntime/GPU | Phone 다음 버튼2106에서 `Frame uses unprepared original texture: Icon10113.png`로 실패. 같은 검사 Tablet 조건은 통과. |
| 수정 후 iPhone Air 시뮬레이터 | Native4/4 통과. 새 첫 사용 검사, 상점 상세/판매, 텍스처 해제/재사용, 동시 전투 중 메뉴 준비를 확인. |
| 수정 후 iPad Air 11-inch 시뮬레이터 | Native3/3 통과. 새 첫 사용 검사, 적 이름/중첩 메뉴 자원 수명, 동시 전투 중 메뉴 준비를 확인. |

새 검사는 원본 형식의 별도 시작 저장을 만든 뒤 실제 GameRuntime으로 기지→상점→다음 버튼을 입력한다. 상품 배열 주입·직접 Screens refresh·revealButton·검사 측 renderer 준비를 사용하지 않는다. 두 표시 조건을 각각 새 런타임에서 시작한다. Phone 내부 페이지에서 게임 revision이 그대로이고 UI 세대만 바뀌는 경계를 확인했다. 새 아이콘 업로드는 1회이며 3번의 이전/다음 왕복에서 추가 업로드는 0회다. 각 조건의 예열 후120프레임 동안 추가 자원 읽기·업로드·저장 요청은 0회다. 캡처에서 Phone 두 번째 페이지 아이콘 표시를 확인했다.

실패 기록도 보존했다. 최초 검사 추가 때의 C++ 변수 형식 컴파일 오류는 고친 뒤 실제 RED를 확보했다. iPad 첫 실행은 테스트 시작 전 `Busy / Application failed preflight checks`로 중단됐다. bootstatus에서 부팅 완료를 확인한 다음 새 결과 번들로 3/3을 통과했다. 테스트 로그의 Tablet 페이지 왕복 횟수 표기는 실제 실행값0으로 고쳤다.

원시 로그·xcresult·캡처·시작 조건 조사·소스 해시는 `.local/evidence/shop-texture-fix-20261116/`에 보존한다. [검사 요약](evidence/shop-texture-fix-20261116.json)을 따른다. 기기 앱·사용자 저장은 변경하지 않았다. 시뮬레이터의 수정 전 실패와 수정 후 성공이며 실제 사용자 저장의 같은 페이지 재검사·정식 Release 설치는 아직 수행하지 않았다.

## 다음 작업

사용자 지시 순서는 상점 수정·검증·커밋 후 별도 브랜치에서 원본 iPhone IPA와 포팅판을 REA로 분석하는 것이다. 이번 수정 커밋을 기준으로 분석 브랜치를 만든다. 일반판2.0.1·HD1.0.3의 판본 차이와 복원 결함을 구분하며 카메라 배율·점프/부스터·path를 포함한 전체 로직을 대조한다. 현재 합의한 HD 공통 게임 규칙을 유지한다. 새 분석을 이유로 상점 수정·정상 iPad·원본·저장을 되돌리지 않는다.
