# 치트 앱과 동시 검증

## 현행 범위 — 2026-11-11

현재는 iOS·iPadOS 정상 플레이·원본 대조·동시 검증을 진행한다. 다른 플랫폼 확장·설치 전달·배포와 develop/main 릴리스는 제외한다. 아래59/68조건과 보행 시작 화면의 설명은 당시 기록이다. 현재 Source는 한국어 정상 타이틀·슬롯·기지·전투를 연결했다.

기존112조건에 실제 피해 GameOver·기지 저장과 랭킹 이용 불가 안내를 추가한114조건을 같은 갱신 루프에서 실행한다. CPU action/실제Screens 두 경로와 양 시뮬레이터 Native 각1,200프레임을 확인했다. 기존55전투·110무기·5분류·메뉴 전투 겹침 기준을 유지한다. 모든 임무·하체23개·캠페인·원작 전체 대조는 남는다. [현행 결과와 한계](gameover-restoration-20261111.md)를 따른다.

## GameOver OS UI 검사

시작 저장과 기존 `SessionHost.absoluteTimeLow` 입력만 DEBUG의 UUID 격리 검사에서 준비한다. 고정 시계 입력1은 World reseed와 저장 encode에 사용된다. 일반 Source는 기존 실제 시계를 사용한다. 적을 실제로 공격한 뒤 다른 적으로 선택을 바꿔 반격을 유도하며 피해·사망·저장 결과를 주입하지 않는다.

원본 문 전환의 모든 float 연산과166 tick은 공통 회귀에서 대조한다. Source UI에서는 실제 confirm 수락 프레임을 읽고 첫 phase8 관측까지166~300 tick을 검사한다. 300은 원본 수식의 값이 아니라 UI polling을 포함한 검사 상한이다. 외부 대기 제한은60초다. 기존15초 대기는 시뮬레이터에서 실패했으며 성능 실패로 남긴다. 기존 수식·게임 시간·문 전환 속도를 바꾸거나 이 실패를 성능 통과로 표시하지 않는다.

iPad 시뮬레이터의 실행 샘플은 main thread629개 중456개가 `glDrawArrays`와 `GLRendererFloat`의 삼각형 그리기에 있었다. 실제 문 전환 중 전장7~8tick/s·기지18~20tick/s를 관측했다. Debug O2도15초 벽시계 실패를 해결하지 못했다. 기능·프레임 검사와 이 환경의 벽시계 성능을 구분하고 실기기 성능으로 확대하지 않는다. Core와 UIKit의 시간·상태·저장 검증을 보존한다.

2026-11-10 사용자 지정: 치트 앱은 경험치·레벨·아이템·진척도의 허들을 건너뛰고, 게임에서 지원하는 모든 기능과 버튼을 여러 조건 아래 동시에 검증하기 위한 앱이다. 기능을 하나씩 켜 보고 종료하는 검사만으로 완료하지 않는다.

## 구현 기준

- 일반·치트 앱은 같은 C++ 코어·원작 데이터·렌더·음향·저장 경로를 쓴다. 치트는 시작 조건을 준비한다. 명중·획득·경험치 지급·레벨업·강화·임무 성공의 결과를 강제로 만들어 통과시키지 않는다.
- 기능 목록은 실제 원본의 메뉴·버튼 ID·장비·스킬·전투·진행·저장 소비 경로에서 작성한다. 테이블에 없는 코드 생성 버튼도 포함한다. UI가 보였다는 사실과 버튼을 눌러 실제 효과가 발생했다는 결과를 구분한다.
- 한 전투에 무기·파츠·아이템·성장·임무 조건을 함께 준비한다. 이동·조준·발사·피격·획득·경험치 증가·레벨업·효과음·HUD를 함께 동작시키며 결과와 프레임·메모리·자원 수명을 검사한다.
- 서로 배타적인 원작 화면·저장 조건은 독립 인스턴스로 병렬 검사한다. 장비창에서 원작이 전투를 멈추면 그 규칙을 바꾸지 않는다. 별도 전투 인스턴스를 동시에 실행하고, 각 인스턴스에서 메뉴·장착·저장·전투 결과를 확인한다.
- 실행마다 simulator/process·게임 상태·일반/치트 저장·seed·입력·출력 로그·xcresult를 분리한다. 같은 시뮬레이터 화면이나 저장을 여러 실행이 동시에 조작하지 않는다. 하나의 빌드 산출물은 읽기 전용으로 재사용한다.
- 개별 경계 검사, 복합 조건의 동시 실행, 전체 기능/버튼 목록의 검증 여부를 함께 남긴다. 전수 목록에서 미구현·미검사 항목을 숨기지 않는다. 명령·검사가 실제로 겹쳐 실행됐는지도 기록한다.

## 현재 구현한 범위

[동시 검증 구현 기록](concurrent-validation-20261110.md)을 현행 상태로 본다. 59개 독립 Session의 실제 전투·거래·임무·저장 재시작·이동 및 획득을 같은 프레임에 실행한다. C++ 1,200프레임과 ASan/UBSan을 통과했다. Apple의 실제 CADisplayLink·공통 GPU 화면·단일 OpenAL을 연결했으며 자원 준비와 출력 최적화 검증을 진행 중이다. 전체 기능 완료는 아니다.

`HeavyMach2Source`의 설치 시작 화면은 아직 보행 단계다. `HeavyMach2Validation`은 새 자동 실행기로 변경했지만 해당 타깃의 새 설치 검증은 남는다. bundle ID는 각각 `com.gelb2.heavymach2.restored`, `com.gelb2.heavymach2.validation`이다. 이전 정적 조립·보행·개별 메뉴 검사는 모듈 회귀 검사로 보존한다. 이 검사들을 전체 동시 치트 성공으로 합산하지 않는다.

독립 기기의 실행을 병렬로 돌리는 것과 한 게임 타이머의 복합 조건 실행을 구분한다. `tools/test_apple_parallel.py`는 전자를 수행하는 보조 도구다. 새 자동 실행기는 후자를 실제 Session과 출력에서 수행한다.

## 다음 연결

먼저 실제 Player의 보행·조준·맵 충돌·전투·UI·성장·저장·음향을 원본 함수와 연결한다. 해당 기능을 구현할 때마다 전체 기능 목록과 복합 시나리오에 추가한다. 예를 들어 레벨업 직전 경험치·모든 장비 접근·아이템 재고를 함께 준비한 뒤 실제 전투의 경험치 획득으로 레벨업하고, 같은 시간에 다른 인스턴스의 장착·임무·저장 검사를 실행한다. 구체적인 XP 임계·장비 ID·저장 필드는 원작 조사로 정하며 HM1/MD 값을 대입하지 않는다.
