# HD 1.0.3 원본 함수와 복원 범위

2026-11-11. 실제 iPad Air 13인치 `GrassPlate`에 HD 포팅판을 무선 설치하고 실행 프로세스를 확인했다. 사용자는 그 포팅판에서 스테이지 이동과 전투가 정상 동작한다고 확인했다. 이는 원본 포팅판에서의 사용자 관측이다. 정식 복원판·치트 빌드와의 대조는 전체 구현 후 같은 iPad 시뮬레이터에서 진행한다.

이전 iPad 시뮬레이터 대조에서 같은 저장과 입력을 사용했을 때 HD 포팅판과 복원판 모두 80Cr, 100Cr 순으로 보상을 지급했다. 두 판 모두 보상 지급 뒤 680Cr, EXP 400, 수리품 8개, 완료 임무 2개를 저장했다. 당시 대조는 사령부의 해당 경로를 확인했다. [사령부 실행 대조](command-detail-restoration-20261111.md)

## 원본에서 확보한 근거

HD 1.0.3 ARMv7 실행파일 SHA-256은 `5feb7ae5f796cdfee5d650037923d338ce7b28de7f600c8548a7a5bbf7ef5090`이다. Mach-O에서 클래스 80개, 메서드 1,194개, 인스턴스 필드 763개를 읽었다. REA/Ghidra 함수 목록에서 메서드 주소 1,194개가 모두 일치했다.

REA 목록에는 함수 본문 1,300개, 연결 함수 348개, 외부 참조 333개가 있다. Objective-C 메서드 1,194개와 그 밖의 함수 본문 106개 전부의 어셈블리와 의사 코드를 보존했다. 연결 함수와 외부 참조는 같은 목록에 따로 표시한다.

원본과 상세 분석은 HeavyMach2 전용 외부 경로에 보관한다. `tools/audit_hd_coverage.py`는 입력 해시와 함수 주소를 확인하고 `restoration-method-index.tsv`, `restoration-call-sites.tsv`, `restoration-method-summary.json`, `restoration-button-ids.tsv`를 그 경로에 만든다. 주소가 소스 주석에 나오거나 의사 코드에 호출 선택자가 나타난 경우는 조사 후보로 기록한다. 실제 구현 여부는 호출부와 소비 코드를 읽어서 판단한다.

## 공통 구현과 검사에서 확인할 범위

전체 동작을 구현한 뒤 원본과 복원판의 같은 저장·입력에서 나온 상태와 이벤트를 모아 자동으로 비교한다. 한 전투 안에서 같이 일어날 수 있는 동작은 같이 실행하고, 배타적인 화면은 독립 인스턴스에서 같은 프레임에 실행한다. 결과에서 빠진 원본 항목과 다른 값을 먼저 좁히고, 직접 조작이 필요한 화면·음향만 iPad에서 확인한다.

## 이번에 확인한 누락

- `GuiGame.init`(`0x29c9c`)은 HUD의 레이어 9, 좌표 (409, 40)에 레이더를 만든다. `DlgRader.init`(`0x23c7c`)은 원본 `RaderMark.png`를 가로 8칸으로 나누고, `DlgRader.draw`(`0x23d28`)는 플레이어·BOT·등록된 출입구를 타일 0·1·2로 그린다. 각 좌표에는 월드 좌표의 1/16을 더한다. 복원판에 빠진 표식을 공통 HUD에 연결했다.
- 정식 앱에서 시험용 저장 경로를 선택할 수 있던 환경변수 판정을 Debug 전용 코드 안으로 옮겼다. 해당 Release 패키지의 실제 검사는 전체 구현 이후에 진행한다.
- `GuiBase.setSelect:`(`0x243b8`)과 `GuiBase.tick`(`0x251d0`)에 따라 시설 설명을 복원했다. 원본 기지 테이블의 `Desc` 좌표와 한국어 설명을 사용한다. 설명 배경은 기지 기준 X ±480에서 출발해 매 틱 남은 거리의 1/6만큼 움직인다. 목표까지 1픽셀 이내에 들어오면 텍스트를 표시하고, 이후 배경과 글을 함께 세로로 펼친다.
- `GuiBase.init`(`0x246d4`)의 임무 알림을 연결했다. 보상 수령 장소가 현재 기지인 완료 임무와 현재 수락 가능한 새 임무에 원본 `MissionNotice.png`의 서로 다른 칸을 사용한다. 사령부 버튼의 위·아래 28픽셀에서 0.5초 간격으로 표시를 바꾼다.
- 기지·상점·정비 화면의 첫 진입 도움말을 기존 `GuiHelp` 처리에 연결했다. 기지는 저장 카운터 1에서 한국어 첫 페이지를 표시하고 2를 저장한다. 상점과 정비는 카운터 2에서 둘째 페이지를 표시하고 카운터를 3으로 올린다. 정비의 표시 좌표는 원본 부모와 자식의 위치를 합산했다. 도움말을 닫는 터치는 뒤쪽 버튼으로 전달하지 않는다.
- `GobWorld.setStage:LinkGate:`(`0x13778`)가 전달하는 지역명을 전장 진입 배너에 연결했다. `GuiGame.setPlaceName:`(`0x2a820`)의 `PlaceNameBG.png`, Arial 32, 흰 글자와 검은 그림자 좌표를 사용한다. 배너는 X −1024에서 중앙 384를 거쳐 900에서 제거된다. 출입구 위 이름은 기존 `MapList`의 목적지 표기이고 배너는 현재 스테이지의 `MapInfo` 이름이다.

호스트 검사 70개가 모두 통과했다. 기지 버튼 입력과 한국어 설명의 이동·펼침, 새 임무와 완료 임무의 알림, 도움말의 저장 카운터와 닫기 입력, 지역명 배너의 진입·제거·재진입을 확인했다. 레이더와 임무 배치 물체의 수집·격파·보상 저장 검사, 기존 115조건의 호스트 동시 검사도 통과했다. 변경된 Apple 앱의 글꼴과 화면, HD 포팅판과의 실행 대조는 전체 구현 뒤 확인한다.

## 전장 크레딧과 퀵슬롯

- `GuiGame.init`(`0x29c9c`)과 `GuiGame.tick`(`0x29508`)에 따라 전장 크레딧 표시를 0으로 시작한다. 틱마다 잔액과의 차이를 5로 나누어 더하고 남은 차이가 5 미만이면 잔액으로 맞춘다. 잔액 500에서 실제 표시 숫자 0→100→180, 잔액 감소, 화면을 숨겼을 때의 진행과 HUD 재생성 초기화를 확인했다.
- `WndQuickSlot.handleButton:`(`0x34e54`)은 재고가 있는 등록 아이템을 선택하고 같은 항목을 다시 눌러 취소한다. `GobWorld.useItem:`(`0x108a0`)은 구급상자와 공습만 새 대상 모드로 바꾼다. 공통 코드에서 선택을 막던 타입 필터를 제거했다. 실제 버튼으로 Item Picker A의 선택·취소를 검사했고, 수리 모드에서 항목을 바꾼 뒤 플레이어를 터치하면 원본처럼 교체된 항목 하나가 소비되는 경로도 확인했다. 해당 테스트에서는 HP와 저장 횟수가 그대로였다.
- 위 두 경로의 수정 전 실패와 수정 후 통과를 보존했다. 최종 호스트 검사 70개가 모두 통과했다.

## 저장 슬롯 움직임과 획득 표시

- `GuiSelectSlot.refreshSlot:`(`0x2e6f8`), `refreshSelect`(`0x2dfe0`)과 `tick`(`0x2e0a0`)을 따라 저장된 장비의 메크를 기존 공통 보행 코드로 움직인다. 선택된 메크만 `GobHvM_Player.tick`(`0xc028`)의 난수 조건으로 목적지를 고른다. 슬롯을 다시 그릴 때 바뀐 자세만 전달한다. 실제 스프라이트 위치와 선택 전환, 난수 호출 수, 저장 데이터의 바이트 일치, 추가 자원 읽기와 저장이 없음을 확인했다.
- `GobHvM_Player.pickupItem:Count:`(`0xb454`)와 `tick`(`0xc028`)에 따라 `PickItem.png`에 아이템명 또는 `%d cr`을 표시한다. Arial 12, 120×14, 가운데 정렬을 사용한다. 실제 임무 아이템 획득과 동시 전투 중 크레딧 획득에서 문구를 확인했다. 배너는 월드 시간에 맞춰 플레이어 위로 튀어 오른다. 2.5초가 지나면 틱마다 세로로 줄어 사라진다. 튀어 오르는 중에 일시정지하면 높이가 유지된다.
- 호스트 70개가 통과했다. 기존 115조건 동시 검사와 실제 스테이지에서의 임무 아이템 획득을 포함한다. 이번 변경의 iPad GPU 표시와 HD 포팅판 대조는 전체 구현 뒤 확인한다.

## 버튼 목록에서 추가로 확인한 동작

- `DlgMission.init`(`0x22b1c`)은 ID 5002 확인 버튼을 만든 뒤 숨긴다. 해당 버튼을 다시 표시하거나 처리하는 경로는 `DlgMission`에서 확인되지 않았다. 버튼 목록에는 숨김 상태를 기록한다.
- `GuiGame.handleButton:`(`0x281e0`)에서 ID 7000의 Push는 `setPathMove:1`을 호출하고 Pop은 `setPathMove:0`을 호출한다. HD 함수 목록에서 버튼 생성과 `pathMove` 값을 읽어 이동을 바꾸는 호출부는 아직 확인되지 않았다.

## 커밋 시점의 검사와 작업 순서

공통 코어 70개 통과 로그는 HeavyMach2 외부 분석 공간의 `HD103/slot-and-pickup-verified-tests.log`에 보존한다. 커밋 준비에서 포팅 패키징 경계 검사 6개와 ARM 인자·숫자 출력 검사 4개도 통과했다. 숫자 출력 검사는 실행기에서 추출한 함수와 대역 메모리로 수행했으며 앱 실행 검사가 남아 있다. 검사 산출물은 로컬 `.local/evidence/commit-20261111/printf-formats/`에 둔다. 원본 IPA·실행파일·저장과 앱 빌드는 커밋 대상에서 제외한다.

포팅 실행기의 실제 수정본에 맞춰 `Compatibility/patches/heavymach2.patch`를 갱신했다. 고정 upstream 커밋에서 만든 패치가 실제 작업본에 역적용 가능한지 읽기 전용 검사로 확인했다. 이전 패치와 변경 근거는 같은 로컬 검사 폴더에 보존했다.

최신 사용자 지시에 따라 전체 기능 구현·수정, 동시 치트 구성·검사와 정식판의 일반 플레이 확인을 끝낸 뒤 마지막 단계에서 HD 포팅판·정식판·치트판을 일괄 대조한다. [작업 순서](validation-build.md#작업-순서)를 따른다.
