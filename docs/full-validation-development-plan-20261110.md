2026-11-11 범위 변경: 현재는 iOS·iPadOS 정상 플레이·원본 대조·동시 치트 검증을 진행한다. 후속 플랫폼 확장과 빌드 설치·전달·배포, develop/main 릴리스는 현재 작업에서 제외한다. 아래 플랫폼·전달 계획은 후속 기록으로 보존한다.

## 현재 출발점

`176cfd5`에서 공통 reader·파츠 조립·GPU·맵·보행·조준·터치 경로·지형 충돌, WeaponInfo 소비와 포구 계산을 구현했다. C++15개, iPhone·iPad 시뮬레이터 각각 unit4개·터치UI1개를 통과했다. Source는 터치 보행, Validation은 보행과 다른 장비의 명시 조준 사례를 표시한다. 실제 발사·적 AI·피해·성장·메뉴·저장·음향은 미완료다.

치트 앱에 설정창만 추가해서는 전체 검증이 되지 않는다. 먼저 실제 게임 기능을 같은 코어로 복원하고, 시작 조건 준비·실제 입력·실행 관측·결과 판정·실패 재현을 연결해야 한다. 정식 앱도 같은 게임 기능을 사용한다.

## 자동 검증을 위해 추가할 코드

아래 파일명과 모듈명은 계획이다. 현재 존재하는 코드로 표현하지 않는다.

- `Sources/Core/Validation/FeatureCatalog`: 모든 기능·테이블/코드 버튼·데이터 ID와 검사 상태를 관리한다. 목록에서 빠진 버튼은 완료 집계 전에 오류로 검출한다.
- `ScenarioSetup`: 레벨/EXP 임계 직전·Cr·장비/장갑·아이템/특수공격/동료·임무/맵·시작 위치·seed를 메모리에 준비한다. 유효한 원본 상태와 실제 이동/생성 조건을 확인한다. 무적/HP 변경 같은 보조 조건은 결과에 별도로 표시하며 기본 명중·생존·자연 진행 검사의 증거로 섞지 않는다.
- `ScenarioRunner`: 같은 코어의 tick과 실제 입력/명령을 실행한다. 코어 회귀는 빠르게 실행하고 프레임·음향·화면 검사는 실제 시간으로 실행한다. 지형/적/임무를 거치지 않고 결과를 직접 설정하는 명령은 성공 근거로 사용하지 않는다.
- `Observation`: 위치·표적·장착·탄창/재장전·탄환/피해·HP·아이템·EXP·레벨·임무·저장 요청/완료와 객체 수명 계수를 읽는다. 관측은 상태를 변경하지 않는다. 반복 전투 로그는 메모리에 모으고 종료/명시적 내보내기 때 저장한다.
- `ValidationPanel`: 원작 이미지·글꼴과 공통 GPU/UI 입력으로 조건을 설정한다. UIKit·DOM·Android View로 게임 버튼을 재작성하지 않는다. 패널을 닫으면 원작의 재개 규칙을 따른다. 패널을 계속 열어 둔 상태를 동시 전투 검증으로 세지 않는다.
- Apple 입력 자동화: 실제 탭·드래그·다중터치·영역 밖 종료·취소·홈/복귀·화면 전이를 검사한다. 현재 accessibility 상태 출력은 시작점이다. 최종 판정은 실제 게임 결과·화면·음향과 함께 한다.
- 결과 출력: run ID, 소스/앱/자원 해시, 원본 판본, 기기/방향, seed/시작 상태, 입력, 기대/실제 값, 실패 최초 tick, 캡처/오디오/xcresult, 자원/저장 계수를 연결한다. 일반 사용자 저장·원본 전체 데이터·비밀정보는 보고 사이트에 포함하지 않는다.

## 동시에 실행할 검사 묶음

한 전투 안에서 여러 기능을 함께 실행하고, 배타적인 화면은 별도 인스턴스에서 같은 시간에 실행한다. 자원이 부족하면 독립된 core 인스턴스를 병렬로 실행하면서 Apple UI 검사를 배치한다. 한 시뮬레이터의 화면을 두 runner가 동시에 조작하지 않는다.

## 원작 대조와 알려진 미확인 처리

- 첫40tick 수식 비교를 원작 실행 계측으로 대신하지 않는다. 고정 상태의 보행·조준·공격 프레임을 포팅판에서 직접 비교한다.
- 일반판 포팅판의 검은 지형 오류는 별도 미해결 항목이다. HD가 정상 표시된다는 이유로 일반판 표시 기준까지 전부 통과했다고 하지 않는다. 해당 실행기가 정상동작하기 전 실기기 설치 금지를 유지한다.
- 원본 IPA에 없는 `Blt_Missile06.png`, `Blt_Missile07.png`는 원작의 nil 그림·효과·공격 경로를 확인한다. 보기 좋은 대체 탄환을 임의로 만들지 않는다.
- 버튼이 원작에서 아무 동작도 하지 않는다면 함수·호출부·직접 실행으로 확인해 원작 no-op으로 기록한다. 편의 기능을 임의 연결하지 않는다.
- 표시 시야 확장에 따른 적/탄환의 isInScreen·선택·명중·AI·spawn 변화는 별도 검사한다. 월드의 판정 크기를 기기별 화면 배율로 바꾸지 않는다.
- 코어/Apple/원작 실행/실기기/후속 플랫폼의 통과를 구분한다. 모든 기능은 목록으로 추적할 수 있지만 한정된 검사로 가능한 모든 상태 조합까지 보장한다고 표현하지 않는다.

## 오류를 찾고 고치는 절차

1. 실패를 재현한 seed·원본/앱 해시·시작 상태·입력·최초 다른 tick·화면/로그를 고정한다. 원본 자료와 사용자 저장은 보존한다.
2. 원본 함수/데이터→reader→조립/상태 전이→렌더/음향/저장의 어느 경로가 달라졌는지 좁힌다. 검사 조건 자체의 오류도 실제 게임 오류와 구분한다.
3. 공통 소비 코드에서 수정한다. 유닛별 임시 C++ 경로·기기별 피해 보정·결과 강제·실패 허용오차 완화로 숨기지 않는다.
4. 실패 재현 검사, 관련 경계 검사, 영향을 받는 복합/병렬 묶음, 실제 Apple 화면/입력을 다시 검사한다. 원작 동등성은 원작과 다시 대조한 범위만 표시한다.
5. 코드·회귀 검사·기능 목록·TODO·트러블슈팅·사이트 보고를 같은 상태로 갱신한다. 한 빌드 트리를 재사용하고 실행 확인 후 불필요한 구 빌드만 정리한다. 로그·캡처·원본·저장은 남긴다.

## 전체 치트 검증 완료 기준

- 원본의 지원 기능·모든 버튼과 위 데이터 ID에 미등록/미구현 항목이 없다. 원작 no-op·금지된 광고·손상 자원 등 예외는 근거와 함께 따로 표시한다. 보류·미검사를 PASS에 포함하지 않는다.
- 각 기능의 실제 입력과 결과를 자동으로 판정할 수 있다. 화면, 피해/수량/성장/진행, 저장 후 복원을 필요한 범위에서 함께 확인한다.
- A~H의 복합/병렬 검사와 iPhone 가로·iPad 세로의 실제 UI·화면·음향 검사가 통과한다. 원작과 다른 점, 원작 실행 문제와 후속 화면/플랫폼 범위를 별도로 남긴다.
- 예열 뒤 사격별 저장 쓰기·음향 객체 생성·파일 재읽기 등의 금지 동작을 실제 플랫폼 계수로 검사한다. 미계측을0으로 쓰지 않는다. 프레임/메모리/음향 합격 기준은 같은 조건의 원작/기준 실행 측정으로 정한다.
- 일반 앱의 치트 분리·진행·저장과 회귀 검사를 통과한다. 빌드 성공·전체 기능 검사·원작 동등성·일반 난이도 진행·배포는 각각 보고한다.

## 참고한 기존 두 게임의 기록

HeavyMach의 `docs/validation-mode.md`에서 시작 조건과 실제 결과, 무기/보스/맵 수와 실제 클리어 수, 조건 재주입 없는 재실행을 나누는 방법을 확인했다.
