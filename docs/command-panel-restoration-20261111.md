# 사령부 보상창 배경과 완료 표시

HD 원본에서 보상창 뒤에 보이는 접힌 NEW MISSIONS 배경을 복원했다. 사령부 임무 행에서 원본에 없던 COMPLETED 마크를 제거했다. 전장 임무 창에는 원본대로 완료 조건을 충족한 행에 마크가 표시된다.

## 적용한 원본 규칙

HD `GuiCommandCenter.init`(0x2614c)은 사령부 그림 위에 목록의 가운데·아래·위 타일을 차례로 만든다. 목록 행이 아직 없을 때 타일 중심은 논리 좌표 y=512·480·544다. 가운데 타일은 초기 높이64를 유지하고, 보상창은 이 타일들 위에 그린다. 세 타일은 입력을 받지 않는다.

`refreshMissionList`(0x2708c)는 사령부의 신규·수락 행에 CompleteMark를 추가하지 않는다. 전장의 `DlgMission.refreshAcceptList`는 완료 조건이 충족된 행에만 추가한다. 기존 공통 UI가 원본 화면별 규칙을 따르도록 분기했다. 제목·임무 조건·보상은 기존 테이블에서 읽는다.

## 검사 결과

- 공통 검사70개를 통과했다. 변경 전에는 첫 보상창의 배경 타일 검사가 실패했다. 변경 후 타일 크기·위치·그리기 순서와 목록 행의 터치 미등록을 확인했다.
- 실제 임무 상태를 공통 화면에 전달해 사령부에는 마크가 없고 전장 임무 창에는 조건 충족 행의 마크가 한 개 있는 것을 확인했다. 이 전장 검사에서는 화면 소비자를 확인했다.
- 독립 검토에서 원본의 배경 생성 순서·배율과 화면별 완료 표시 조건을 대조했다.
- iPadOS 26.5 시뮬레이터에서 정상 앱의 실제 터치·상세창·저장 재시작 검사와 115조건 동시 치트 검사를 통과했다. 1,200프레임 중 348·356프레임에서 두 보상창 뒤 배경을, 364프레임에서 마크가 사라진 사령부 목록을 GPU 출력으로 확인했다.

## 남은 차이

HD 원본은 신규 목록과 저장의 임무 레코드를 구성할 때 `dictMission.allValues`를 읽는다. 보존된 포팅 실행기 소스는 이 호출을 Rust 해시맵의 값 순서로 처리한다. iPad 포팅판에서 본 신규 임무 순서를 원래 iOS의 고정 정렬 순서로 사용하기 전에 실행기와 원본의 사전 동작을 확인한다. 같은 슬롯 OK 입력에서 두 판의 보상 순서는 앞선 대조에서 일치했다.

원본 60개 임무를 공통 reader로 읽어 전장에 배치하는 아이템 action7건, 적 action7건, 이벤트 문 action4건을 확인했다. 현재 전장 생성 경로는 이벤트 문을 소비한다. 아이템과 적은 원본 `GobWorld.addMissionObjects`의 공통 소비자를 기준으로 다음 단계에서 연결한다.

원본 대조 화면과 분석은 `.local/evidence/command-detail-restoration-20261111/`, 이번 검사 로그와 60개 임무 조사표는 `.local/evidence/command-panel-restoration-20261111/`에 보존했다. [검사 수치와 근거](evidence/command-panel-results-20261111.json).
