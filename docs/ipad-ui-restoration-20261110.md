# iPad 피드백의 UI·BOT·맵 전환 복원

사용자가 설치된 정상 Source에서 지적한 누락을 공통 C++ 코어와 Apple 출력에 연결했다. 이 문서는 작업 후보의 결과다. 현재 물리 iPad의 앱은 이전 설치본이며, 이번 변경을 설치하거나 develop/main에 병합하지 않았다. 전체 게임 복원 완료도 아니다.

## 원본 절차와 검토 수정

HD 실행파일·데이터의 로컬 REA 분석과 원본 reader/공통 조립 근거를 사용했다. 원본 소스코드를 확보했다는 뜻은 아니다. 게임 그래픽·버튼·문자·효과는 공통 GPU 경로이며 UIKit은 창·터치·OS 입력창에 사용한다. 새 게임 엔진이나 별도 게임 규칙을 추가하지 않았다.

독립 검토에서 발견한 세 차이를 수정했다. 맵 로딩 중 Player 처리에는 원본 gameState를 적용하고, World 시간은 맵 교체마다 초기화하지 않는다. 프레임 순서도 World→GuiGame→MapLoading으로 유지해 공유 난수와 저장 콜백 순서를 맞췄다. 최초 Help는 setStage의 조건부 저장 뒤에 wrapper가 pause를 푼다. 이전 World의 파츠/타일 소유권은 원본의 별도 제거 단계까지 유지한다.

## 112조건 동시검증

기존106조건의 번호와 수용 기준을 유지하고 BOT2조건과 Help4조건을 추가했다. 실제112개 Session을 같은 프레임에 갱신한다. BOT 조건은 3종을 각 슬롯에 함께 배치한다. 위치·명중·드롭·HP 감소·수집 결과를 강제로 만들지 않는다.

최초 Native 검사에서는 양 시뮬레이터 모두1,200프레임에서 수용 검사에 실패했다. 무기110종 중109종 발사, Picker별 접촉0, BOT 실제 피격과 일부 이동/획득 누락이 있었다. 공통 코드 Host가 실제 Screens tick을 생략하고 Native만 원본 UI의 공유 난수를 소비한 차이를 확인했다. 공통 코드에도 실제 UI·포인터 경로를 추가하자 같은 실패가 재현됐다. 이 실패 로그와 결과는 보존했다.

자동 입력을 다음과 같이 고쳤다. 원본 게임의 무기·AI·피해·드롭·난수 수식은 바꾸지 않았다.

- 화면 밖의 적을 매 프레임 선택해 원본의 선택 해제/이동 정지를 반복하던 입력을 실제 화면 안 선택으로 바꿨다.
- 조건38은 Gun이 적을 먼저 죽이므로 가시 범위의 먼 적을 먼저 선택하고 Missile의 실제 발사를 관측한 뒤 가까운 적을 선택한다.
- 수동 Tank의 실제 반격이 필요한 Picker 조건107은 낮은 레벨과 기본 무장으로 시작해 실제 선택·공격·피격을 거친다. 그 뒤 유효 지상점으로 한 번 이동하고 실제 HUD/인벤토리 입력으로 준비한 장비를 교체한다. 실제 장비 수량·슬롯·발사 결과를 검사한다.
- 단일 지상 입력 간격은31프레임 이상이며 해당 조건의 dashStarts0을 요구한다. 다른 조건의 실제 Dash 검사는 유지한다.

수정 후 공통 코드68개·ASan/UBSan 구성66개와 양 시뮬레이터의 Native 동시 검사 각각2개가 통과했다. 실제 UI를 포함한1,200프레임에서 다음을 확인했다. 이 결과는 이후 발견한 그래픽·음향 차이를 수정하기 전 버전이다.

같은 공통 코어의 action-only 검사도 유지한다. 실제 UI를 소비하는 검사는 선택 사항인 진단으로 남기지 않고 CTest에 필수 항목으로 등록했다. Native 자동검사의 CPU/GPU 제출 시간은 실시간60fps나 실기기 성능의 합격 판정으로 쓰지 않는다.

## Apple 검사와 원본 그래픽·음향 차이

페이지 점을 반영한 Native Session3개와 A8 그림자 GPU 검사를 통과했다. SG-1 큰 아이콘/설명/가격·인벤토리 팝업·SELL 위치, 메뉴/전투·원자 저장/재실행·손상 저장 보존·이름 경계를 검사했다. 이는 원본 앱 전체 화면의 픽셀 동등성 판정이 아니다.

정상 Source의 실제 UIKit 입력 검사도 iPhone/iPad 각각1개 통과했다. 타이틀·이름/슬롯·기지·전장·이동/선택/사격·한국어 최초/메뉴 Help·pause/재개·저장 재실행/삭제를 확인했다. 물리 iPad 설치 결과는 아니다.

사용자가 원본 그래픽·음향 절차 준수를 질문한 뒤 실제 차이를 추가로 찾았다. 효과음 재생마다 context를 연결·해제한 점, NSString 이름 변환, 슬롯 그림자의 부모 좌표 누락, 전장 Player의 atlas 강제와 슬롯의 레이어 차이를 확인했다. 독립 검토에서 항공기 그림자 offset 오류도 찾았다. [원본 절차 대조와 수정 상태](graphics-audio-fidelity-20261110.md)에 원본 주소·실패·수정·실행 범위를 기록한다. 이 차이를 놓친 이전 검사 성공을 원본 그래픽·음향 전체의 복원 완료로 사용하지 않는다.

음향 context 유지 수정은 Mac 정상 출력 장치·공통 코드·양 시뮬레이터 Native에서 통과했다. 항공기 그림자 수정판의 공통 코드68개·ASan/UBSan66개도 통과했다. 슬롯 GPU 비교는 초기1-LSB 변동을 따로 기록하고, 예열 후 동일Frame16회 반복·예상Frame·원본 그림자 가림의 픽셀 차이0을 양 시뮬레이터에서 확인했다. 최종 Native 관련7개 검사는 양 시뮬레이터에서 각각 모두 통과했다. 초기 변동의 원인은 미확정이다. 원본 packed PartsTile의 정상 활성은 정적 분석에서 확인하지 못했으며 runtime hit/miss 관측은 남는다. 앞선 문서의 '슬롯 direct 자체가 원본과 다르다'와 '그림자가 반드시 보여야 한다'는 해석은 원본 근거에 맞춰 정정했다.

## 원작 HD 포팅판 상점

원본 HD 포팅판에서 SG-1을 선택할 때 touchHLE의 printf가 원본 ItemInfo.makeItemDesc의 `%+d`를 처리하지 못해 `assertion failed: !prepend_sign`으로 중단됐다. HM2 전용 로컬 실행기의 해당 C printf 지원을 수정하고 회귀/독립 검토 후 시뮬레이터에서 다시 실행했다. SG-1 상세의 `Atk 20 (L:+3 R:+3)`·가격·BUY 표시를 확인했다. 원본 IPA의 게임 코드·데이터는 수정하지 않았고 패키지 내 IPA 해시도 원본과 일치했다.

재설치 전에 Documents 전체를 로컬 백업했다. 재설치 전후 게임 저장과 설정의 해시가 같음을 확인했다. 실행 로그는 종료/재실행으로 바뀌므로 Documents 전체가 같은 해시라고 주장하지 않는다.

실행기 재현 조사에서는 기존 런타임과 현재 patch 사이의 네 파일 차이도 발견했다. 그중 일반판 게스트 전용 allocator 변경은 기존 동작 차이이며 단순 로그 추가가 아니다. pinned 소스에서 현재 실행기를 재현하는 별도 patch 후보와 검토를 보존했고 아직 채택하지 않았다. 이 변경의 원본 동작 정합성과 일반판 검은 지형 문제는 미확인이다. HD 상점 성공을 모든 포팅판 기능의 성공으로 확대하지 않는다.
