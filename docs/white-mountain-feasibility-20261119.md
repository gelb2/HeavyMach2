# 화이트마운틴 전장과 미등장 전투 콘텐츠 기술조사

**현재 공통 코어로 새 화이트마운틴 전장을 만들 수 있다.** iPad용 HD 1.0.0에 설원 전장 그림 6장이 남아 있다. 여섯 헤비멕 2 원본에서 화이트마운틴에 연결된 맵·충돌·포털·적·임무 데이터는 발견되지 않았다. MachDefense의 설원 4종을 참조해 새 지형과 동선을 설계할 수 있다. 아래 검사는 로컬 원본 및 호스트 코어에서 수행했다.

## 새 전장을 만들 때 손댈 영역

1. MachDefense 4종에서 눈·노출 지면·수로·시설의 배치 방식을 참고해 헤비멕 2용 전장과 장애물의 배치를 새로 설계한다. HD에서 찾은 6장은 이 게임의 색과 지면 표현을 대조하는 데 쓴다. 바닥과 장애물의 월드 좌표를 함께 기록한다. 투명 구역에 원경이 필요한 전장만 선택적 `<맵 ID>BG.jpg`를 쓴다.
2. 신규 맵 ID를 정해 공통 데이터에서 그림 이름, `MapInfo.mcb`의 맵·충돌·양방향 포털·스폰 레코드, `MapList.tble`의 포털 표시명을 맞춘다. `Maps::parse`의 ID 필드 폭, `WorldGates`의 목적지와 입구 번호, `CombatScene`의 입구 안쪽 50단위 오프셋까지 검사한다. `tools/prepare_hd_assets.py`의 원본 바이트 보존 경로와 추가 콘텐츠의 패키징 입력을 구분한다. 추가 데이터 검사에서 중복 ID, 없는 목적지·입구·텍스처, 막힌 도착점, 잘못된 충돌 좌표를 검출한다.
3. 첫 후보는 기존 필드에서 왕복할 수 있는 전장 하나로 한정한다. 기지 자체를 열 때는 `Base004`를 맵과 시설에 연결하고, 사령부의 임무 제공과 일반 플레이의 저장·복귀를 확인한다. 에어리프트를 제공한다면 `GameSession::enterBase`의 방문 기록과 목적지 표를 한 목록으로 관리한다. 현재 방문 기록은 다섯 곳만 쓰고 에어리프트는 여섯 번째 슬롯을 읽는다. 화이트마운틴 도착 전에는 잠금 상태를 유지해야 한다.
4. 맵·충돌·적·이동 경로는 공통 데이터와 코어에 둔다. iPhone과 iPad는 현재의 화면 투영을 사용한다. 눈길 마찰이나 이동 보정은 별도 기획과 검증이 필요한 기능으로 둔다.

코어 실험에 HD 1.0.0의 실제 `MapInfo.mcb`와 `STAGE 12.png`를 넣었다. 원래 데이터에서 `STAGE 12`와 `Base004`를 요청하면 `Unresolved HM2 map`이 나왔다. 메모리 사본에 임시 맵과 왕복 포털 번호, 사각 충돌을 추가하자 `MapPreview`가 같은 PNG를 912×420과 1024×768에서 1024×1024 전경으로 만들었다. 좌표 왕복, 게이트 번호의 상호 참조, 네 충돌 경계와 접촉 보정을 확인했다. 이 검사는 CPU에서 실행했다. 새 전장의 게임플레이와 GPU 출력 확인은 후속 단계다. ## 등장시키려면 필요한 작업

격리한 맵·아이템 사본으로 공통 코어를 실행했다. 적 9종이 파츠를 읽고 생성됐다. 무장한 6종이 420틱 동안 모두 발사했고 비무장 비행체 3종은 이동했다. BOT 5종의 이동과 세 수집형의 탐색을 확인했다. 이 수치는 호스트 실험의 조건에서 나온 값이다. 오디오 요청과 프레임 데이터까지 확인했으며 기기 출력과 일반 입수는 후속 검증 범위다. 기존 맵·충돌·전투 관련 호스트 검사 26개도 통과했다. 활성화 구현 시 레이저 음원 중복, 보스 아이템 보상, 비행기 무장과 BOT 방어를 각자의 범위에서 검사한다. 콘텐츠 변경은 공통 인벤토리와 전장 진입 경로를 통해 검증한다. 먼저 치트 빌드에서 맵 전환·복귀, 벽 충돌·점프, 머즐·피격·음향, 아이템 드롭·수량·쿨다운을 검사한다. 두 기기 시뮬레이터에서 같은 좌표의 연속 프레임과 뷰포트, 저장 재개를 비교한다. 그 후 정식 빌드의 일반 진행에서 입수·잠금·왕복을 확인한다. 기존 전장·상점·저장의 회귀를 통과하면 두 실기기에 올린다. 이번 결과는 원본 재조사와 격리한 코어 검사까지다.
