# iPad PWA의 HUD·가로 전환·기존 설치 갱신

사용자는 공개 v0.6을 새로 설치한 iPad의 세로 화면에 잘림이 없다고 확인했다. 기존 설치의 갱신 실패, 가로의 검은 화면, 네이티브와 다른 HUD 크기도 보고했다.

같은 iPad에서 정식 네이티브와 설치형 PWA를 실행한 결과는 [iPad Air 13 PWA 전장 HUD 크기](pwa-ipad-air13-hud-20261124.md)에 기록했다.

## 원인과 바꾼 동작

- v0.6 Web 호스트는 짧은 세로 전장에서 지도 경계를 적용하려고 `compact=true`를 설정했다. 같은 설정을 공통 화면 모듈에도 전달해 작은 HUD를 선택했다. 웹 호스트가 이제 HUD에 실제 화면 구성을 전달한다. 짧은 화면의 전장 카메라는 기존 공통 지도 경계를 사용한다. HUD와 카메라의 비율을 맞추기 위해 전장 전체에 균일한 배율을 적용하고, 월드 터치에 역변환을 적용한다. HUD의 좌표와 터치는 원래 HD 변환을 쓴다. [웹 런타임](../Sources/Platform/Web/Runtime.cpp) · [공통 HUD 배율](../Sources/Core/Presentation/DisplayLayout.cpp)
- v0.6은 태블릿의 매니페스트에 세로를 지정했지만 런타임은 휴대폰의 세로만 차단했다. iPadOS가 가로 창을 주면 전장 화면 대신 세로 회전 안내를 표시한다. 가로에서는 게임 화면 크기와 시뮬레이션을 갱신하지 않는다. 전장과 입력은 세로에서 이어진다. [웹 방향 처리](../Web/Shell/app.js) · [WebKit 홈 화면 앱 설명](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- v0.6은 파일이 달라지는 새 워커를 기존 문서가 닫힐 때까지 대기시켰다. 새 워커는 검증을 마치면 대기 중인 이전 문서가 있어도 활성화한다. 실행 중인 문서는 같은 캐시에서 읽고, 새 탐색은 새 판본으로 연다. 해시가 같은 파일은 재사용한다. 현재 코드가 실행되는 시작 화면이나 앱으로 돌아올 때 새 워커를 확인한다. iPadOS가 오래된 아이콘에 기록한 상태 막대 설정은 별도 확인 대상이다. [서비스 워커](../Web/Shell/sw.js) · [서비스 워커 수명 주기](https://web.dev/articles/service-worker-lifecycle)

## 검사

| 환경 | 확인 항목과 결과 |
| --- | --- |
| iPad 크기 WebKit 치트판 | Ruin Field의 일반 세로 768×1,024와 짧은 세로 850×975에서 HUD 배율은 각각 1.00000과 0.95215였다. 하단 양쪽의 검은 띠는 0행이었다. 상점·사령부 왕복, 경로 입력, 전장 복귀 포털, 가로 전환 중 시뮬레이션 정지와 같은 세로 전장 복귀를 확인했다. |
| Mac Chrome 설치형 PWA 치트판 | 850×975에서도 배율 0.95215와 하단 0행을 확인했다. 가로에서 멈추고 세로의 기존 전장으로 돌아왔다. |
| Chromium 휴대폰 치트판 | 90°와 270° 가로, 세로에서 일시 정지, 홈 복귀 2회, 기존 배경음 위치에서 재생을 확인했다. |
| iPad 크기 WebKit 치트 캠페인 | 44개 맵을 열어 전장 진입과 데이터 로딩을 확인했다. |
| Chromium과 WebKit 정식판 갱신 | v0.6 문서 두 개를 연 채 후보를 제공했다. 열린 게임의 WASM 해시와 다음 탐색의 해시가 각 판본에 맞았다. 이전 게임이 저장 잠금을 놓은 뒤 서버 응답을 차단한 상태에서 새 게임을 시작했다. |
| iPad Pro 13 시뮬레이터 네이티브 치트판 | Release로 빌드해 실제 실행했다. 126개 조건에서 2,100프레임을 그렸다. HUD와 전투가 동시에 실행된 프레임은 7개, 이동과 전투가 함께 실행된 프레임은 2,063개였다. |
| Mac Chrome 설치형 정식·치트판 | 두 판을 각각 설치하고 저장을 만들었다. 오프라인에서 같은 아이콘으로 열었을 때 각 판의 저장이 동일했다. |

첫 iPadOS 홈 화면 시험은 기존 v0.6 아이콘의 시작 동작과 홈 화면 재탐색에서 실패했다. 후속 시험은 맥 재시작 전 시뮬레이터 연결이 끊겨 종료됐다. iPad 네이티브 정식판의 별도 UI 테스트도 Ruin Field 진입 조건을 통과하지 못했다. HD HUD 비교에는 같은 크기로 실행한 네이티브 프레임과 PWA 프레임을 사용했다. 물리 iPad의 후보 확인은 위 결과에 포함하지 않는다. 보호된 Apple·Android·공통 소스와 에셋의 Git 차이는 0이다. 실행 로그, 캡처와 판본 명세는 로컬 `.local/evidence/ipad-pwa-hotfix.BdRMxq/v07-verification/`에 있다.


## 공개 배포와 재부팅 후 확인

GitHub Pages `aa9fe50`에서 정식 v0.7을 제공한다. 공개 파일 17개의 크기와 SHA-256이 빌드 `45105f58bba4f4ffd507f043`과 일치했다. 공개 주소에서 새 WebKit 프로필로 게임을 시작하고 iPad의 세로 복귀 안내를 확인했다. [공개 빌드 정보](https://gelb2.github.io/HeavyMach2/build.json) · [v0.7 릴리스](https://github.com/gelb2/HeavyMach2/releases/tag/v0.7)

재부팅 후 iPad Pro 11 시뮬레이터에서 v0.6으로 추가해 둔 기존 홈 화면 아이콘을 열었다. 같은 시험 주소에서 공개 정식 v0.7과 같은 파일을 제공했다. 가로 안내가 나타났고, 세로로 돌아와 게임을 시작했다. 재설치는 한 번도 하지 않았다. 첫 XCTest에서 타이틀과 회전 안내를 캡처했다. 두 번째 XCTest에서 Ruin Field에 들어가 가로 안내와 같은 전장의 세로 복귀를 확인했다. 인벤토리·임무·시스템 메뉴도 열었다. 두 검사 모두 통과했다. 이 검사는 물리 iPad의 동일 동작을 포함하지 않는다. 로컬 기록은 `ipad-existing-v07-resumed.log`, `ipad-existing-v07-title.png`, `ipad-existing-v07-rotate.png`, `ipad-existing-v07-ruin-field.png`, `ipad-existing-v07-panels-preview.png`, `public-v07-files.json`이다.

Chromium에서는 v0.6에서 만든 검증용 저장을 두고 같은 버전 교체를 실행했다. 서버 응답을 끈 상태에서 v0.7을 다시 연 뒤 28,204바이트 저장을 읽었다. 갱신 전후 SHA-256이 일치했다. 로컬 기록은 `update-v07-save.log`다.
