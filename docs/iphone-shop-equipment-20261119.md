# iPhone 상점 Equip 화면 수정

iPhone의 Equip에서 하단 탭에 겹쳤던 ATK·DEF·SPD와 세 번째 BOT을 다시 배치했다. 912×420 캡처에서 세 능력치 행·장비 여섯 칸·BOT 세 칸·인벤토리 두 행과 페이지 버튼을 모두 확인했다. 배치 커밋은 `b105721`이다. 세 번째 BOT을 선택했을 때 보이는 원본 DISARM 버튼은 `5ef5ad8`에서 연결했다.

## 원본 실행

원본 일반판 2.0.1에 레벨 22와 Wasteland Base를 설정한 비교용 저장 사본을 사용했다. 원본의 파일 읽기와 레벨 확인 함수는 REA로 대조했다. 기존 원본 IPA와 플레이 세이브는 보존했다.

| 원본 분류 | 화면에서 확인한 페이지 수 |
| --- | ---: |
| Weapon | 3 |
| Parts | 2 |
| BOT | 1 |
| Attack | 1 |
| Etc | 1 |

페이지 화살표를 눌러 각 분류의 마지막 화면까지 캡처했다. BOT 두 대를 사서 두 번째와 세 번째 칸에 드롭했다. 세 번째 BOT을 선택했을 때 원본 DISARM이 보인 화면도 남겼다. Ruin Field Base 레벨 1의 다섯 분류, 가로·세로 드래그와 SG-1 거래는 [첫 대조](iphone-shop-comparison-20261119.md)에 있다. 그때 기록한 아이템 285개의 원본 및 HD 파일 크기를 이번에도 사용했다.

## 수정과 확인

`MenuGridLayout`이 Equip 왼쪽의 장비·수치·탭과 오른쪽 인벤토리의 배치와 화면 경계를 계산한다. `Screens`가 동일한 배치로 원본 `MaintenanceBG.jpg`의 영역, 장비와 BOT, 숫자, 페이지 버튼, 터치 역좌표를 연결한다. 원본 그림을 같은 비율로 그린 조각으로 화면을 덮는다. 기존 시제품에서 발견한 검은 상단과 걸쳐 보이던 빈 인벤토리 행도 수정했다.

Shop에서 Equip으로 바꾸거나 기지에서 직접 Equip에 들어갔다가 Shop으로 갈 때 현재 인벤토리 페이지와 보던 칸을 유지한다. 실제 공통 세션에서 페이지 전환, BOT 세 번째 슬롯의 드롭 좌표, 탭 전환 시 저장 요청과 미지원 입력이 늘지 않는 것을 확인했다.

iPhone 시뮬레이터의 667×375·852×393·912×420·912×550에서 GPU 화면을 남겼다. 912×420에서 세 번째 BOT을 선택해 DISARM과 하단 탭 사이를 확인했다. iPad에서는 여섯 기지 상점 모두 이전 후보와 다른 픽셀이 0개였다. `b105721`의 독립 치트빌드로 두 시뮬레이터에서 각각 126조건·2,100프레임을 완료했고 버튼 실패는 0건이었다. DISARM을 추가한 `5ef5ad8`은 공통 표시·입력 검사와 iPhone GPU 검사로 확인했다.

복원판은 iPhone의 넓은 화면에 맞춰 양쪽 영역에 서로 다른 비례를 사용한다. iPhone Air에서 32px 아이콘은 Shop 약 60.8pt, Equip의 장비 쪽 약 46.3pt, 인벤토리 쪽 약 75.3pt다. 같은 기기의 원본 포팅판은 480×320 화면을 맞춰 약 42pt로 표시한다. 원본과 아이콘·상세창 표시 크기를 모두 맞추는 일과 수정 후보의 실기기 확인은 TODO에 남겼다.

후속 수정에서 32px 아이콘을 Shop과 Equip 모두 42pt로 맞췄다. 상세창·거래 버튼과 웨이스트랜드 페이지 재검증은 [상점 크기와 페이지 검사](iphone-shop-layout-verification-20261119.md)에 있다.
