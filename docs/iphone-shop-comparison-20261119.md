# iPhone 상점 원본 대조와 거래 버튼 수정

iPhone 상점의 Buy·Sell을 원본 세로 버튼으로 교체했다. 상세창을 목록 사이의 거래 버튼과 페이지 버튼에서 떼었다. Equip의 능력치와 BOT 슬롯이 잘리는 현상은 재현했다. 장비 화면 배치 수정은 남았다.

## 일반판 2.0.1 실행

iOS 26.5 iPhone Air 시뮬레이터를 따로 만들어 원본 포팅판과 비교용 저장 사본을 실행했다. 좌표와 입력은 XCTest로 재생했다. 원본 PNG는 기기가 내보낸 방향 정보와 바이트를 보존했다. 게임의 논리 화면은 480×320이다.

- Ruin Field Base의 레벨 1 저장에서 Weapon, Parts, BOT, Attack, Etc를 열었다. 다섯 상품 목록에 각각 페이지 한 개가 보였다. 각 목록의 오른쪽 페이지 위치를 네 번 눌렀을 때 캡처가 같았다. 이전·다음 화살표가 있는 인벤토리는 세 페이지를 오갔다. 둘째와 셋째 페이지는 비어 있었다.
- Weapon의 빈 셀에서 가로·세로로 드래그했다. 드래그 전후 PNG 세 장의 SHA-256이 일치했다. 장비를 끌어 슬롯에 놓는 동작은 이 결과에 포함하지 않았다.
- SG-1의 상세, 구매 확인·취소·확정, 인벤토리 상세, 판매 확인·취소·확정을 모았다. 구매 후 잔액은 500→250 Cr, 판매 후에는 250→375 Cr였다. Equip에서 SG-1을 선택하자 정보창만 표시됐다. Shop으로 돌아와 같은 아이템에서 세로 Sell을 확인했다.
- Equip의 장비 여섯 칸, BOT 세 칸, ATK·DEF·SPD를 캡처했다. 비교 저장에는 첫 BOT만 장착돼 있었다. 두 번째와 세 번째 BOT을 모두 장착한 원본 화면, 고레벨·다른 기지의 상품 마지막 페이지는 추가 확인이 필요하다.

## 원인과 수정 위치

복원판은 확인창의 가로 BUY·SELL 이미지를 목록 옆에도 사용했다. 상세창과만 겹치지 않도록 버튼을 옮기는 경로가 있어 버튼이 오른쪽 인벤토리 위로 이동했다. 상세창을 화면의 안전 영역 안에만 맞추면서 페이지와 하단 탭을 덮는 경우도 생겼다. 뒤에 등록한 상세창과 거래 버튼이 겹친 좌표의 터치를 먼저 받았다.

REA/Ghidra로 원본 armv7의 `0x4369c`에서 `Btn_ShopBuy.png`·`Btn_ShopSell.png`의 두 프레임, 버튼 ID 2102·2103, 상대 좌표 (-18, -2)를 확인했다. `0x442c8`에서 상세창의 206×128 수신 영역을 확인했다. `0x40f2c`는 한 페이지에 16개 상품을 순회한다. 관측 주소·해시는 [증거 목록](evidence/iphone-shop-comparison-20261119.json)에 있다.

`MenuGridLayout`이 iPhone 상점에서 페이지·카테고리 터치 경계와 거래 버튼을 기준으로 상세창 영역을 계산한다. `Screens`는 기존 타일·텍스트·입력에 같은 배율을 적용한다. 거래 버튼은 원본 좌표에 고정하고, Sell은 인벤토리의 판매 가능 상태일 때 Shop에서만 표시한다. 기지에서 직접 들어가는 정비 화면의 상세와 iPad의 HD 경로는 기존 변환을 사용한다.

## 수정 후보 검사

- iPhone Air Native 3개와 iPad Air 11인치 Native 2개가 통과했다. iPhone 동시 검사에서 720프레임과 메뉴 상태 20개를 실행했다. 공통 코어 관련 검사 5개를 통과했고 Sell 노출 정책을 마무리한 뒤 표시·입력 검사를 다시 통과했다.
- 기본 500 Cr로 상점에 들어간 복원판에서 같은 SG-1과 250 Cr 확인창을 실제 화면에 표시했다. 터치로 확인창을 취소했다. 공통 코어의 실제 세션 검사에서는 구매·판매 후 수량과 크레딧이 바뀌었다. 장착품과 Equip 탭에서는 Sell이 표시되지 않았다.
- iPad의 여섯 기지 상점 PNG 모두 기존 iPad 기준과 바이트가 일치했다. 이번 수정 후보의 실기기 설치와 독립 치트 앱 실행은 남았다. 기존 실기기에는 `f8e82d8`의 결과만 있다.

## Equip이 잘리는 원인과 수정 계획

`DisplayLayout::ui`의 `phoneEquipment`가 상품 행에 맞춘 세로 변환을 장비·BOT·능력치에 적용한다. 912×420에서 능력치 행의 중심은 약 54·26·−3pt이며, 세 번째 BOT의 수신 영역은 y75pt부터라 하단 탭 구역에 걸친다. 능력치 명칭과 빈 슬롯 윤곽은 `MaintenanceBG.jpg`에 그려져 있다. 별도로 움직인 숫자·아이콘은 그 기준점에서 어긋난다.

`DisplayLayout`에서 Phone Equip의 상단·장비·하단 영역을 분리해 수치 세 줄과 BOT 전체를 화면에서 확보한다. 같은 변환을 `Screens::append`의 장비 배경·슬롯·라벨과 `phoneDropPoint`의 역변환에 적용한다. 원본 자원 파일과 공통 저장 형식은 유지한다. 합격 조건은 라벨과 숫자 정렬, BOT 세 칸과 탭의 터치 분리, 장비 드롭 성공, iPad 상점의 동일 캡처다.
