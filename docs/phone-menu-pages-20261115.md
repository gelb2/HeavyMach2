# iPhone 메뉴 버튼 페이지와 원본 배치 — 2026-11-15

## 사용자 요구

허브·상점·사령부의 가로·세로 스크롤을 금지한다. 페이지는 원본 좌우 버튼으로만 전환한다. iPhone은 일반판의 배경·버튼·정보창 배치를 사용하고, 상품·아이템·게임 규칙은 공통 HD를 유지한다. iPad는 기존 상태를 유지한다. 탭 투 플레이는 HD 그림을 위쪽부터 화면 전체에 표시한다. 가로 로고·지역명은 물리 화면 전체 폭을 사용한다.

## 공통 코드 변경

`DisplayLayout`·`MenuGridLayout`·`MenuArtwork`·`Screens`에서 표시 정책을 관리한다. Apple 호스트에 메뉴 구현이나 UIKit 게임 버튼을 추가하지 않는다. 기기별 게임·저장·무기 규칙을 분리하지 않는다.

- 장면 팬과 상품/인벤토리 스크롤 상태·추가 스크롤 버튼을 제거했다. 작은 화면의 표시 칸은 원본 좌우 버튼으로 넘긴다. HD의 상품24개/페이지·인벤25칸/페이지와 저장 인덱스는 유지한다.
- 원본 게임의 페이지 이벤트는 push, 새 표시 창의 처리는 pop이었다. Phone 페이지 입력을 받아 표시 창을 먼저 넘기고, HD 데이터 페이지가 바뀔 때 원래 push 콜백을 전달한다. 자동 이동 없이 모든 상품·인벤 칸에 접근한다.
- 상품·아이템 드래그/드롭은 같은 역변환으로 원래 HD 인덱스에 연결한다. 치트 입력도 실제 페이지 버튼을 누른다.
- Phone 설명창192×128/글꼴12, 사령부 목록·상세·ACCEPT, 상점 BUY/SELL·거래창·카테고리/페이지/EXIT·숫자를 원본 자원과 함수에서 확인했다. 공통 준비 도구가 원본70파일을 바이트 변경 없이 패키징한다. Phone Base002/005의 원본 교차 참조도 유지한다.
- 원본 배경 텍스처를 상단·본문·하단 클립으로 배치한다. 각 부분은 같은 원본과 균일 배율을 사용한다. 에셋 새 생성·픽셀 연장·검은 채움·가로/세로 비율 변형을 사용하지 않는다. 본문에 보이지 않는 상품/인벤 칸은 좌우 버튼 페이지에 보존한다. 이 구성은 원작의 픽셀 동일 복사를 뜻하지 않는다.
- 탭 투 플레이의 Main_BG는 HD 원본이다. 최상단을 화면 상단에 맞추고 균일 cover로 그린다. 로고/지역명의 클립과 등장·퇴장 위치는 물리 화면 전체를 기준으로 한다.

## 발견한 실패와 수정

첫 GPU 검사는 두 렌더러가 같은 출력면을 써서 `Cannot allocate HM2 drawable`로 실패했다. 검증 코드의 전투·메뉴 출력면을 분리했다. 다음 실행에서는720프레임 동안16개 메뉴 상태와126개 게임 상태를 함께 갱신했다. 이를 전체 게임 복원 완료로 확대하지 않는다.

실제 캡처에서 상점 제목 잘림, ACCEPT/EXIT 겹침, 보유금 정렬을 발견했다. 해당 후보를 시각 합격으로 처리하지 않고 공통 배치를 수정했다. iPad 화면 비교에서는6개 상점 캡처에 각각376픽셀 차이가 있었다. HD 인벤 페이지 버튼이 Phone 자원을 참조하도록 바뀐 것을 찾아 원래 HD 자원으로 복구했다. 최초 실패 캡처와 비교 결과는 로컬에 보존한다. 최종 재검사에서 iPad18장 전체 PNG 바이트 일치를 확인했다.

거래창 바탕이 사라진 캡처는 검사 입력 시각12초와 그리기 시각3초가 뒤집힌 결함이었다. 버튼의 release 계산에 잘못된 미래 시각을 공급했다. 검사 시각을 같은 게임 clock에 연결했다. 게임 실행파일·라이브러리 해시가 유지되는 것을 확인했고, 이 결함을 제품 오류로 기록하지 않는다.
