# 사령부 임무 상세창 펼침

사령부에서 임무를 고르면 상세창이 즉시 전체 높이로 나타나던 동작을 수정했다. 새 임무와 수락한 임무 모두 높이 0부터 펼쳐진다. 같은 행을 다시 선택해도 펼침을 다시 시작한다.

## 원본 동작과 구현

HD 1.0.3의 REA 분석에서 `refreshMissionInfo 0x26af8`, `tick 0x26558`, `refreshMissionList 0x2708c`를 대조했다. 상세창을 만들 때 내부 높이를 0으로 두고, 게임 tick마다 128까지 남은 거리의 25%를 더한다. 차이가 0.1 이하인 tick에서 목표값을 적용한다. 이미지와 설명의 세로 배율에는 이 값을 128로 나눈 비율을 적용한다.

목록의 위쪽 배경과 선택한 행은 올라가고, 선택한 행 아래의 임무는 내려간다. 새 임무 아래에 있는 MY MISSIONS 표제와 수락한 임무에도 이 이동을 적용한다. 수락한 임무의 상세창은 해당 행의 위치를 기준으로 펼쳐진다. 기존 공통 GPU UI의 그림, 글꼴, 행과 버튼 위치를 갱신한다.

ACCEPT는 원본 그림의 1×2 타일과 기존 크기 및 터치 영역을 사용한다. 상세창이 펼쳐지는 중에도 누를 수 있다. 수락하면 선택 테두리가 바로 사라지고, 상세창과 버튼 및 행 위치는 다음 목록 갱신까지 유지된다. 독립 검토에서 이 순서가 어긋난 것을 찾아 수정했다.

## 검증

- 변경 전 실제 Screens 입력으로 임무를 선택했을 때 첫 프레임의 높이가 0이어야 하는 검사가 실패했다.
- 변경 후 첫 두 tick의 높이 64와 112, 26번째 tick의 높이 256, 같은 임무 재선택과 화면 갱신 시 진행 유지, 펼침 도중 터치, 수락 직후와 다음 tick의 창 수명을 검사했다.
- 수락한 임무의 상세창 위치와 ACCEPT 미표시, 수락 전후 추가 저장 0을 공통 검사에 포함했다. 최신 공통 검사 70개가 통과했다.

- 최신 ASan/UBSan 구성에서 완료 임무 및 동시 실행 관련 검사 3개를 통과했다.
- iPadOS 26.5 시뮬레이터에서 최신 복원판의 실제 터치, 두 종류의 상세창, 저장 재시작을 확인했다. 같은 iPad에서 115개 조건의 동시 치트 검사를 1,200프레임 실행했다. 별도의 iPhone 회귀는 복원판의 공통 동작만 검사했다.

## HD 포팅판 실행에서 확인한 차이

iPadOS 26.5 시뮬레이터에서 HD 1.0.3의 사령부를 같은 한국어 검사 저장으로 열었다. 원본에서 보상창 두 개를 OK로 닫고 새 임무와 수락한 임무의 상세창을 각각 열었다. 새 임무에는 ACCEPT가 보이고 수락한 임무에는 보이지 않았다. 원본 앱의 전체 화면을 기록했다. 포팅 실행기의 글꼴 대체도 로그에 남아 있어 픽셀 단위 동등성은 별도 조사 대상이다.

두 판에서 슬롯 OK만 눌러 같은 저장을 열었을 때 보상은 볼트·너트 수집(M002010) 80Cr, 적 탱크 파괴(M001010) 100Cr 순으로 나왔다. 수락한 임무의 행 순서도 일치했다. 첫 HD 실행에는 슬롯 행 터치가 추가됐고 보상창이 반대 순서로 나왔다. 첫 결과를 복원판의 순서 결함으로 판단한 보고를 정정했다. 원본 분석에서는 슬롯 행과 OK 모두 슬롯을 불러올 수 있으며, 저장할 때는 사전 순서로 임무 레코드를 쓴다는 점을 확인했다. 슬롯 재선택 후 배열 순서가 달라지는 경로는 후속 대조 대상이다.

두 보상 뒤에는 원본과 복원판 모두 680Cr, EXP400, 수리 아이템8개, 완료 임무2개를 저장했다. 원본에서 사령부를 나가기 직전에 읽은 파일에는 보상이 아직 기록되지 않았다. 앱을 재실행한 뒤에는 같은 보상이 다시 나타나지 않았다.

같은 입력으로도 원본 보상창 뒤에는 접힌 NEW MISSIONS 배경이 보인다. 복원판에서는 이 배경이 빠진다. 새 임무의 행 순서도 다르다. 원본의 사령부 목록에는 COMPLETED 마크가 없으며, 정적 분석에서는 전장 임무 목록이 완료 조건을 충족했을 때만 그 마크를 그린다. 세 차이는 후속 수정 대상이다.

원본 정적 근거와 검사 로그는 `.local/evidence/completed-missions-restoration-20261111/reference-followup/` 및 `.local/evidence/command-detail-restoration-20261111/`에 보존했다. 같은 폴더에 원본 실행 화면, 펼침 영상과 저장 판독 결과를 남겼다. 두 실행 뒤 기존 포팅판 저장의 바이트를 확인하고 복구했다. [검사 수치와 근거](evidence/command-detail-results-20261111.json).
