# iPhone 유니버설 UI 후속 조사

같은 HD 자원과 공통 C++ 코어를 유지할 수 있다. 다만 일반판의 좌표를 HD 그림에 일괄 배율로 적용하면 인벤토리 인덱스, 부모·자식 위치, 터치 영역과 버튼 역할이 달라진다. **게임 규칙과 UI 동작은 HD를 보존하고, 조립된 화면의 배치와 역입력을 함께 바꾼다.**

이번에는 원본 캐시와 현재 소스만 읽었다. 앱 실행·빌드·시뮬레이터·기기 검사는 하지 않았다. 원본 전체 코드·표·그림을 문서나 저장소로 복사하지 않았다. [상세 근거와 해시](evidence/iphone-universal-ui-followup-20261113.json)

## 조사 분모와 확인 수준

기존 [일반판·HD 차이 조사](universal-design-audit-results-20261113.md)의 입력·Retina·HUD·도움말·전환 근거를 재사용했다. 이번 후속 범위는 인벤토리·장비·BOT·퀵슬롯·상점·정비·거래·상세·에어리프트·타이틀·슬롯·맵 로딩·메뉴·알림·레이더·기지·사령부의 **18개 화면 계약 묶음**이다.

| 구분 | 수 | 의미 |
| --- | ---: | --- |
| 선택한 구조·입력·콜백 계약 확인 | 15 | 아래에 적은 구체적인 계약을 원본 함수와 연결함 |
| 가변 분기 전체 대응이 남은 후보 | 3 | 아이템 상세 팽창, 기지 표와 동적 자식, 사령부 가변 임무 행 |
| 역할의 대응 위치를 찾지 못한 묶음 | 0 | 모든 동작과 모든 함수가 동등하다는 뜻은 아님 |
| 이번 문서가 연결한 함수/진입점 | 112 | 같은 함수의 여러 역할은 중복 계산하지 않음 |
| 문법 색인만 수행한 함수 | 283 | 자원·selector·해시는 기록했지만 선택 계약의 해석 근거로 쓰지 않음 |
| HD UI 선언 | 19클래스·184메서드 | 전체 메서드의 자원·selector·본문 해시를 색인함 |

| 동적 버튼 생성자 미확정 | 1 | handler의7000 분기와 실제 생성/등록을 아직 연결하지 못함 |

일반판 전체 1,077개와 HD 전체 1,300개 몸체를 대상으로 직접 scissor/clip 호출도 검색했다. 이 색인은 모든 함수의 의미를 해석했다는 수치가 아니다. 선택 계약을 읽은 함수와 문법 색인만 수행한 함수를 JSON의 `meaning_status`로 구분했다.

일반판 사령부 tick `0x39e14`는 기존 1,077개 몸체 밖의 가상 진입점이었다. 네이티브 조사 담당이 추가로 추적한 18개 명령을 읽어 상태 변경과 목록/완수 확인 연결을 확인했다. 기존 분모를 늘려서 전수 수집 완료로 표현하지 않았다.

## 공통 배치가 보존할 계약

원본의 부모 위치 계산은 일반판 `0x4bd18`, HD `0x373bc`에서 **위치를 더하는 방식**이다. 부모의 scale·rotation을 자식 offset에 자동으로 곱하는 일반적인 노드 변환으로 교체하지 않는다. 카메라 변환과 반 픽셀/정수 위치 맞춤은 그다음 별도 단계다.

현재 [Screens](../Sources/Core/UI/Screens.cpp)는 원본 자식 위치를 상당 부분 화면 좌표로 펼친다. [GameSession::drag](../Sources/Core/Session/GameSession.cpp)는 인벤토리·장비·BOT·퀵슬롯의 HD 원점을 별도 수식으로 계산한다. 그림만 옮기면 드롭 위치가 남는다. 생성과 매 tick 갱신, 버튼과 드롭 격자, 팝업과 문자에 동일한 배치 결과를 전달해야 한다.

[Button](../Sources/Core/UI/Button.cpp)은 HD의 왼쪽/아래 경계 제외·오른쪽/위 경계 포함을 보존한다. 타일 교체가 bounds를 바꾸는 경로, bounds 설정 뒤 표시 scale을 바꾸는 경로도 있다. 버튼 그림 크기만으로 터치 영역을 새로 정하지 않는다. 동적 팝업 등록 순서와 멀티터치 capture·release·cancel을 유지한다.

전체 캐시 검색에서 직접 `glScissor` 호출은 각 판본의 EAGL surface 함수 `0x3ce8`/`0x3514`에만 있었다. 이것은 모든 UI 가림 규칙이 없다는 증명이 아니다. 부모 show, 그려지는 패널, 레이어 순서, 거래 팝업의 전체 입력 차단은 clip과 별개다. 복원판 렌더러의 scissor 기능이 존재한다는 사실도 원본 UI가 그 기능을 썼다는 근거가 되지 않는다.

## 개발 경계와 금지사항

1. **HD 자원 한 벌과 같은 C++20 코어를 유지한다.** iPhone용 원본 자원을 따로 가져오거나 별도 게임 코드 파일을 만들지 않는다. 폰20칸/상점16개/공수5행/타이틀11초/슬롯 미리보기 난수를 기기 분기로 이식하지 않는다.
2. 호스트는 bounds·pixel scale·safe area·방향을 전달한다. 공통 viewport/layout이 유효 영역과 패널 앵커를 정한다. Screens 생성·갱신, Button hit, Session drag, Help, MapLoading, Transition이 같은 결과와 역변환을 사용한다.
3. 게임 시간·phase·저장·음향·난수 호출과 화면 coverage geometry를 분리한다. 원본 UI의768/1024와 파생 임계값을 화면 높이로 일괄 치환하지 않는다. 전투·사거리·이동·아이템 인덱스에는 표시 배율을 적용하지 않는다.
4. 같은 HD 합성 이미지에 GPU의 UV·clip·contain·확대 이동·스크롤을 사용할 수 있다. 필요한 동작은 표시 확장으로 기록한다. 글자가 있는 배경을 임의로 찌그러뜨리거나 잘라서 별도 iPhone 파일을 생성하지 않는다.
5. UIKit은 기존 HD의 OS 대화상자·이름 입력·키보드·안전 영역과 방향 연결 범위에 둔다. HUD·상점·인게임 패널을 UIKit으로 다시 만들지 않는다. 새 게임 엔진·런타임을 추가하지 않는다.
6. 최종 방식은 각 창의 실제 표시 크기와 글자 잘림을 측정해 정한다. 원본 근거가 없는 최소 글자 크기를 합격값으로 만들지 않는다. 전체 HD 화면을 작게 넣는 것만으로 가독성 검증을 마쳤다고 보고하지 않는다.

폰 가로에서 HD25개 인벤토리와24개 상점 상품을 어떻게 배치할지는 아직 구현 전 결정이다. 그림과 글자의 실제 표시 크기를 유지하며 패널을 나누거나 같은 GPU 영역 안에서 스크롤하는 방법을 비교한다. 이 과정에서 저장상의 페이지당 개수와 ItemCode를 바꾸지 않는다. 기존 iPad 세로의 배치·게임 동작을 기준으로 보존한다.

## 구현 후 필요한 검사

- 실제 각 Session에 iPhone 가로/iPad 세로 배치를 주입한다. 동시 치트 화면의 바깥 격자만 바꾸는 검사로 대신하지 않는다.
- 인벤25·장비6·BOT3·퀵5·상점24의 처음/끝 칸, 페이지, 빈 칸, 재고0, 해금/미해금과 팝업을 함께 검사한다. 표시 bbox와 버튼 hit 및 드롭 격자를 각각 기록한다.
- 생성 직후와 후속 tick을 검사한다. 상세·기지 설명·사령부 행·타이틀·무기 선택이 옛 HD 좌표로 돌아가는 누락을 찾는다.
- 클릭·이동·바깥 release/cancel·동일 ID 멀티터치·화면 전환 중 취소·동적 팝업 등록 순서를 검사한다. 모달의 빈 영역 터치가 뒤 버튼으로 새지 않아야 한다.
- 한국어 제목·본문·숫자·가격·국가/날짜·장비 수치의 실제 글자 크기와 줄바꿈·잘림을 기록한다. 텍스트 준비 요청의 원본 폰트·크기·영역과 최종 표시 배율을 구분한다.
- 거래의 전체 입력 차단, StageClearBG와 문 전환의 완전한 가림, 안전 영역과 역입력, HUD에 가려진 전장 터치를 검사한다.
- 게임코어·자원 한 벌 유지와 저장·음향·난수·phase 순서 보존을 정적으로 검사한다. 동시 치트와 정식 플레이 검사를 마친 뒤 마지막에 HD/iPad 포팅판과 일괄 대조한다. 기능별 포팅판 왕복이나 iPhone에서 HD 로직 교차검증을 다시 시작하지 않는다.

카메라가 넓어지면서 발생하는 `isInScreen`·AI·생성·공격 예외·난수 차이는 [공통 조사 계획](universal-design-audit-plan-20261113.md)의 별도 게임 규칙 검사로 유지한다.

## 남은 정확한 항목

- **기지·사령부·상세 전체 분기:** 표와 동적 자식, 모든 가변 임무 행, 일반판 상세 팽창의 완전 대응은 후보로 남았다. 확인하지 못한 동작을 임의로 구현하지 않는다.
- **버튼7000:** HD GuiGame handler에 분기는 있지만 실제 생성/등록과 도달 조건은 아직 확정하지 못했다. 네이티브 담당도 생성 근거를 확보하지 못했다고 답했다. 임의 버튼을 추가하지 않는다.
- **표시 정책:** HD 합성 그림과 한국어 본문의 iPhone 가로 가독성·가림은 실행 측정 전이다. contain·확대 이동·스크롤 중 채택과 지원 범위를 기록해야 한다.
- **현행 등록표 정합성:** `Screens::coverage()`의 `WndInven0x34918`은 현행 캐시의 init `0x3490c`, `DlgSystemMenu0x23fb0`은 `0x23fc8`과 다르다. shop 상세에 `false`가 남지만 `buildDetail/layoutDetail/tickDetail` 코드 연결은 있다. 등록표 주소·상태와 실제 검사 근거를 보강한다. 등록표 숫자만으로 완료나 미구현을 판정하지 않는다.

이 문서는 조사와 개발 기준을 보존한다. 게임 소스 수정·실행 검증·기기 설치·브랜치 병합 완료 보고가 아니다.

## 재현 도구

`python3 tools/audit_iphone_ui_followup.py`로 주소·자원명·selector·해시와 선택한 계약을 다시 색인한다.
