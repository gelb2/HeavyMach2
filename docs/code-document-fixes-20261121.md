# HeavyMach 2 코드·문서 수정과 에셋 소비 점검 — 2026-11-21

코드·문서 대조 31건 중 29건을 반영했다. 태블릿 세로 기지 제목이 잘리는 문제와 미사용 Phone 분기 제거는 아래 표의 26·27번에 남아 있다. 두 수정 위치는 iPhone·iPad·Android도 읽는 공통 C++ 파일이다.

가장 큰 실행 차이는 웹 효과음이었다. HeavyMach 1과 MachDefense는 웹에서도 C++ OpenAL 경로를 사용한다. HeavyMach 2 웹은 이전에 JavaScript가 효과음의 파일을 읽고 디코딩해 재생마다 노드를 만들었다. PWA와 Tauri를 공통 PCM reader와 OpenAL 쪽에 연결했다. 그림은 이미 공통 메뉴·프레임·아틀라스를 사용했다. 이번 점검에서 패키지의 그림 1,359개와 음원 58개는 Apple·Android와 내용이 일치했다.

## 사운드와 그림의 생산·소비

- **HeavyMach 1** `bd0aa73ad0bf765f3e54c1800c89b8d550a5e1e9`. `Web/tools/package_assets.py`가 공유 자원을 20 MiB 이하 묶음으로 나눈다. `Sources/Web/WebGLRenderer.cpp`는 원본 그림을 디코딩해 색·알파 변형별 텍스처를 준비하고 재사용한다. `Sources/Web/WebAudio.cpp`는 모노 PCM16을 읽고 음원별 OpenAL 버퍼와 소스를 재사용한다.
- **MachDefense** `387e554a504acce44230fc007bd95253ea425862`. `Web/CMakeLists.txt`가 자원을 웹 패키지로 연결한다. `Web/src/Assets.cpp`와 `Web/src/Renderer.cpp`는 공통 디코딩과 모드별 지연 업로드를 쓴다. `Web/src/Audio.cpp`와 `Sources/Audio/OpenALEffects.cpp`는 모노·스테레오와 8·16비트 PCM을 준비해 OpenAL 소스를 재사용한다. MP3 배경음은 `Distribution/Web/audio.js`의 호스트 경로다.
- **HeavyMach 2 그림.** `tools/prepare_campaign_assets.py`가 공유 캠페인 자원을 준비한다. `Image.cpp`가 JPEG와 일반·CgBI PNG를 디코딩하고, `PreparedTiles.cpp`가 텍스처·알파 변형·아틀라스를 준비한다. `Screens.cpp`와 전장 세션이 그림을 선택하고 프레임에 담는다. WebGL 렌더러는 공통 프레임의 텍스처·좌표·그리기 순서로 출력한다. 휴대폰 상점은 승인한 격납고와 별도 패널을 사용한다. 웹의 새 그림, 플랫폼별 색 변환, 패널 배치를 추가할 근거는 발견되지 않았다.
- **HeavyMach 2 소리.** `GameSession::orderedStartupSounds`의 순서로 준비하고, 이후 새 효과음만 공통 `decodeWave`로 읽어 버퍼와 소스에 올린다. `OpenALEffects::play`가 원래 위치 값을 적용한 뒤 기존 소스를 정지하고 다시 재생한다. 앱을 비활성화하면 OpenAL 효과음과 출력 장치를 멈춘다. Emscripten이 브라우저 출력과 연결한다. MP3 배경음은 별도 음악 어댑터를 사용한다.
- **패키지 비교.** 정식·치트 웹 패키지 각각에서 경로가 같은 그림 1,359개와 음원 58개를 추출했다. 준비 캠페인, iOS 정식 시뮬레이터 번들, 갤럭시 검증에 사용한 Android 정식 APK를 SHA-256으로 대조했다. 파일 차이는 0개다. 두 선행작과 묶음 방식·원본 형식은 다르다. 그림 파일 일치와 실행 경로는 화면의 모든 픽셀이나 실제 스피커 출력이 세 작품에서 같다는 판정에 쓰지 않는다.

## 실행 근거

- Chrome·WebKit·Firefox에서 기지 화면의 실제 메뉴 효과음이 재생되는 동안 OpenAL 샘플 위치가 진행했다. 반복 입력 전후 OpenAL 컨텍스트는 1개, 소스와 버퍼는 각각 50개였다. 기지 화면이 안정된 뒤 600 ms 동안 텍스처 파일 읽기와 GPU 업로드가 늘지 않았다. 시설을 바꾸는 시험과 고정 화면 관측은 별개다.
- Chrome 치트판에서 Ruin Field로 나가 이동과 교전을 일으켰다. 브라우저 출력 버퍼의 프레임 수·샘플레이트·채널 수·64개 샘플을 준비 자원과 대조했다. 기관총 `Wpn_Gun01.wav`, 미사일 `Wpn_Missile01.wav`, 피격음과 지면 폭발음이 실제 재생을 시작했다. 같은 파형의 `Wpn_Default.wav`와 `Wpn_EnGun.wav`는 버퍼만으로 구분할 수 없다.
- Chrome의 설치형 정식판·치트판에 대해 설치, 독립 앱 실행, 오프라인 재실행과 저장 유지를 확인했다. 브라우저에서는 사령부·상점·전장·기지 귀환과 두 판 사이의 복구를 포함한 14개 시나리오를 통과했다. 파일 손상·이어받기·오프라인 다운로드 검사와 초기 숨김·재개 시나리오도 통과했다.
- Tauri 정식·치트 앱의 빌드와 로컬 서명을 확인했다. Rust 저장 검사 6건과 데스크톱 어댑터 검사 3건을 통과했다. 디렉터리 동기화 실패를 주입해 교체된 주 저장의 인식과 백업 실패 뒤 주 저장 보존을 각각 확인했다.
- 공통 CTest 등록 76개를 두 입력으로 실행했다. 캠페인 자원으로는 원작 퀘스트·배치·파일 수를 확인하는 검사 15건과 원작 Stage 입구 수를 고정한 검사 1건이 실패했다. 그 입구 검사에서 현행 캠페인의 Stage 입구 83개는 모두 도달했고 원본의 기준 수는 82개다. 원본 자원에서 실패한 화면·세션 2건은 캠페인 자원에서 통과했다. 원본 그림 검사에서는 승인한 Phone 편집본 3개도 디코딩하되 원본 그림 수 집계에서 제외했다. 수정 뒤 원본 1,276개와 PNG 크기를 확인했다. 각 검사에 맞는 입력을 쓰면 76건 모두에 통과 결과가 있다.
- 공통 OpenAL 호스트 검사에서 원본 WAV 57개 모두 믹서 출력이 발생했다. 기관총 음원 200회 반복에서 컨텍스트·소스·버퍼 수가 유지됐다. 이 검사는 Mac의 소프트웨어 루프백을 사용했다.
- 저장소의 자체 Markdown 116개에서 로컬 링크 930건의 파일과 제목 위치를 확인했다. 진입 문서에서 자체 문서 116개 모두에 도달한다.
- 실제 기기에서 소리를 듣는 검사, 세 작품의 장면별 화면 대조, 실물 iPad의 브라우저 설치 후 제목 잘림 대조는 별도로 남아 있다. 이번 PWA·Tauri 변경은 모바일 공통 소스를 수정하지 않았다.
