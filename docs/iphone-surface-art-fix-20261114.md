# iPhone 화면 늘림·배경·HUD 수정

## 사용자 지시와 확인

바탕화면의11/14 iPhone 캡처3장을 직접 확인했다. 전장 하단 끝 픽셀 연장, HUD 아래 여백, 사령부 HD 배경 사용을 수정한다. 검은 레터박스·비등방 스케일·에셋 찌그러뜨림·끝 픽셀 반복을 금지한다. 이전 카메라 수정/설치는 완료됐으며 이번 세 항목은 아직 미완료다. 작업 브랜치는feat/iphone-universal-20261113이다. 다른 두 게임과 iPad의 게임/저장은 수정하지 않는다.

## 수정 위치

1. `MapPreview`의 맵 밖 UV strip을 제거한다. 공통 CameraPresentation/WorldNavigation이 실제 유한 맵 안에 시야를 제한하도록 고친다. HUD를 띄우기 위해 카메라를 맵 밖으로 보내지 않는다. 별도 parallax 배경이 있는 맵은 원본 종횡비와 UV를 유지하면서 필요한 경우 배경에만 균일 cover를 적용한다. 지형·유닛·충돌 배율은 바꾸지 않는다. 넓은 창에서는 필요한 최소 배율을 균일하게 적용한다. iPad regular의 게임 카메라는 그대로 보존한다.
2. 비전투 장면은 공통 아트 profile과 reader로 원본Phone2.0.1 배경을 선택한다. HD 유닛/무기/게임 데이터/인게임 버튼을Phone 자원으로 교체하지 않는다. 원본 이름·확장자·바이트를 별도PhoneMenu namespace 안에 보존하고 기존 캐시의 ID를 구분한다. 공통 decoder는 이미JPEG를 지원한다. PreparedTiles의 PNG전용 크기 판독을 공통 PNG/JPEG header 판독으로 보강한다. 플랫폼별 별도 게임코드를 만들지 않는다.
3. Phone 기지는 원본6기지tble의 위치/scale을 그림·강조·시설버튼에 같은 변환으로 적용한다. HD callback 집합에 있는ID만 유지한다. Phone의 추가 정비 버튼/기능을 새로 노출하지 않는다. Base002/005의 강조 교차참조도 원본대로 읽는다. 480×320과 현대 가로화면의 비율 차이는 균일 cover와 장면 pan으로 처리해 모든 시설/길 버튼에 접근할 수 있게 검사한다. 그림과 버튼을 따로 이동하거나 늘리지 않는다.
4. `HUDLayout`의 사용자 배치 범위와 clip을 전체canvas로 통일한다. `Screens`의 별도 safe-area clip도 같은 공통 결과를 사용한다. 설정 저장·재실행과 실제 드래그/터치를 검사한다. 기존 iPad 기본배치에 새 변경이 필요한 경우 사용자 지시와 기대 결과를 따로 기록한다.

## 원본 근거

Phone2.0.1 SHA256:23ff9c74c7d890cc6f28952b4845f6c616bae4bb7207a393f80ed9ed76062d32. source-provenance.json의 저장소 밖IPA만 읽는다. [기존 원본 배경 조사](iphone-background-asset-research-20261114.md)와 원본REA export를 재사용한다. 슬롯/사령부/상점/정비JPG는960×640이며 원본Retina wrapper로 표시한다. Base/Main_BG/StageClearBG는480×320이고 이 자원은일반getTile에서Retina=false다. 모든Phone그림에Retina를일괄적용하지 않는다. Main_Title/Episode는Retina wrapper, TitleBig은일반getTile이다.

## 검사 순서

세 항목을 공통 코드에 구현한 뒤 필요한 C++검사와 정식/치트 Apple컴파일을 한 묶음으로 진행한다. 마지막에 iPhone/iPad 시뮬레이터에서126조건 동시 검사, 모든메뉴/6기지시설/문전환/맵모서리/근원거리줌/경로재지정/사용자HUD끝단배치·저장재실행을 확인한다. 원본에 없는맵그림·UV외부채움·UI프레임워크를 추가해 통과시키지 않는다. 새 iPhone 실기기 설치는 현재 요청 범위에 포함하지 않는다. 실패는 기준을 낮추거나 숨기지 않는다.

## 공통 검사 결과

C++77/77과 Apple test build를 통과했다. 38개 전장×두 창 크기×네 모서리에서 전체 원본 quad의 화면 채움과 UV 범위0..1을 검사했다. 실제 Phone 원본 PNG/JPEG의 디코딩·Retina 논리 크기·제목 회전 중 네 모서리 포함, 6기지의 원본 좌표와 실제 버튼 입력·장면 드래그, HUD v1→v2 위치 보존과 화면 네 모서리 배치를 검사했다.

상점·정비의 전체 배경은 Phone JPG다. 상품24개와 인벤토리25칸의 HD 규칙을 보존하기 위해 HD UI 패널만 기존 그림의 GPU quad/clip으로 표시한다. 상점16칸·인벤토리20칸인 Phone 게임 규칙으로 바꾸지 않는다. 패널 Sprite는 화면 소유자 생성 시 한 번 준비하며 매 프레임 재디코딩하지 않는다.

초기 실패도 로컬에 보존했다. 맵 밖 보정을 제거하자 진입 시 Player가 화면 아래로 빠지는 문제가 드러났다. 유한 맵과 Player 보호 범위가 교차하지 않을 때 가장 가까운 유효 맵 경계로 옮기도록 수정했다. 공통 동시 검사 입력 계획도 HUD 뒤의 가까운 적에만 멈추지 않도록 수정했다. 실제 버튼·경로·무기 로직을 사용하며 HP·명중·발사 결과를 주입하지 않는다. 최종77개에는 126조건 동시·110개 원본 무기 발사와 같은 프레임5종 발사가 포함된다.

iPhone/iPad 시뮬레이터의 실제 GPU/동시 Native 검사는 진행 중이다. 이 문단을 통과나 실기기 설치 완료로 해석하지 않는다.

## GPU 검사에서 발견한 후속 수정

Native 첫 묶음에서는 치트 화면 크기 변경 뒤 `PhoneMenu/Base001.jpg`가 미준비 상태인 오류를 확인했다. `ConcurrentRuntime::setDisplay`에서 새 Screens 소유자의 준비 자원을 GPU에 전달한 뒤 기존 소유자를 정리하도록 연결했다. 그 후 실제 Native 360프레임의 메뉴·전투 동시 검사는 통과했다.

실제 전투 GPU 캡처에서 단순 size/center quad로 제출한 지형이 검게 나오던 실패를 보존했다. CPU 좌표·크기·clip·RGBA와 GL texture matrix는 정상으로 기록됐으며 GL 내부 원인을 확정하지 못했다. 맵의 compact 출력은 기존 `VisualLayer` Tile2D의 전체4정점·UV0..1 생성 함수를 재사용하도록 통합했다. regular iPad 경로는 그대로 둔다. 확장 UV, 끝 픽셀 반복, 별도 파일·decoder·context는 추가하지 않는다. 같은 제출 경로와 전체 전투 프레임의 최종 검사를 진행한다.

유한 맵 하단에서는 카메라를 맵 밖으로 보낼 수 없으므로, 줌아웃 중 기본 HUD가 Player 중심을 가리는 구간도 공통 표시 정책에서 제한한다. 실제 HUD 조각 범위와 맵 경계 거리로 최소 배율을 계산하며 일반 대기1과 iPad 고정1을 유지한다. 사용자 HUD 배치를 게임 월드 규칙으로 만들지 않는다.

iPad 이전120조건×1,200프레임과 대조한 결과 게임 상태 해시 차이0이다. 그림 차이는 HUD 편집 안내 문구를 바꾼119번 한 조건이다. 다른119조건의 그림 해시는 같다. 이 결과는 해당 비교 실행의 근거이며 마지막 Native 전수 결과는 아직 남는다.
