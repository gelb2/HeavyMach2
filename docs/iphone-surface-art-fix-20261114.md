# iPhone 화면 늘림·배경·HUD 수정

바탕화면에 놓인11/14 스크린샷3장을 확인하고 전장 끝 픽셀 늘림, 비전투 배경, HUD 아래 여백을 수정했다. 사용자 진행 저장과 다른 두 게임은 변경하지 않았다. 이번 수정은 iPhone/iPad 시뮬레이터 대상이다. 실기기 설치와 develop/main 병합은 수행하지 않는다.

## 수정한 동작

| 항목 | 결과 |
| --- | --- |
| 전장 | 실제 맵 안에서 카메라 범위를 제한한다. 확장 UV·끝 픽셀 반복·검은 레터박스·비율 변형을 사용하지 않는다. |
| 비전투 배경 | 제목·로딩·슬롯·6기지·사령부·상점·정비에 원본 Phone 그림을 연결했다. 원본52파일의 이름·확장자·인코딩·바이트를 보존한다. |
| 상점·정비 | 배경의 원본 칸에 HD 아이콘·버튼을 맞춘다. HD 패널이나 ItemBox를 중복해서 그리지 않는다. 상세창·장비 탭·기지 복귀와 드롭 좌표도 같은 변환을 쓴다. |
| HUD | 기본 휴대폰 HUD가 화면 아래에 닿는다. 사용자 조각은 화면 네 끝까지 이동·저장할 수 있다. 기존 설정의 실제 위치도 보존한다. |
| 게임 규칙 | HD의 상품24개/페이지·인벤토리25칸·원본 item index·구매/판매/장비/BOT/저장 로직을 유지한다. |

정식·치트는 같은 공통 C++ 코드와 HD 게임 자원을 사용한다. Apple 전용 게임 UI·별도 게임 규칙·새 엔진·새 효과음 재생기·추가 오디오 컨텍스트를 넣지 않았다. 원본과 검사 실패, 이전 CPU/메모리 trace를 로컬에 보존했다.

## 원본 그림과 표시 기준

원본 Phone2.0.1 SHA256은 `23ff9c74c7d890cc6f28952b4845f6c616bae4bb7207a393f80ed9ed76062d32`다. 저장소 밖 IPA를 읽기만 한다. `prepare_phone_menu_assets.py`는 승인한 파일을 `PhoneMenu/`에 복사하며 원본 해시와 파일 목록을 대조한다. 이름만 바꾼 포맷·재압축·이미지 재생성은 없다. 기존 공통 PNG/JPEG decoder와 자원 캐시를 사용한다.

슬롯/사령부/상점/정비 JPEG는960×640이며 원본 Retina wrapper를 적용한다. Base/Main_BG/StageClearBG는480×320 일반 getTile 자원이다. Main_Title/Episode, 카테고리 그림, 상세창도 확인한 원본 Retina 규칙을 따른다. 모든 Phone 그림을 일괄2배 또는1/2로 취급하지 않는다. [기존 조사](iphone-background-asset-research-20261114.md).

공통 `MenuGridLayout`은 원본480×320 좌표를720×480 UI 단위로 표현한다. 같은 HD 아이콘/버튼의 논리 크기와 셀 간격을 연결하기 위한 변환이다. 배경은 원본 종횡비를 유지하고 화면 전체를 채운다. 시설/길 버튼은 배경과 같은 변환·장면 이동을 쓴다. 화면보다 넓거나 높은 그림의 끝 픽셀을 늘리지 않는다.

| --- | --- |
| GuiShop0x442c8/0x4369c/0x40f2c | 상품 첫셀(55,220),4열×4행, 간격40 |

| 상세창0x405b8/0x42f00 | 원본 상세창 그림, 위치, 가로→세로 펼침과 텍스트/큰 그림 위치 |
| 탭0x403b0/0x415f0 | 배경/그룹 전환 후 상세·BUY·SELL을 닫는다. 인벤 선택 하이라이트와 페이지는 유지한다. |

HD24/25칸을 보존하기 위해 원본4행 격자 안에서 상품4열×6행과 인벤5열×5행의 추가 행을 화살표로 표시한다. **이 스크롤은 복원판의 표시 기능이며 원본 스크롤로 보고하지 않는다.** 실제 상품 수에 따라 상품 스크롤 범위를 제한한다. 페이지당 수량과 item index는 바꾸지 않는다. 드롭은 동일한 표시/스크롤 역변환을 거쳐 기존 HD5열·page25와 장비/BOT 좌표로 전달한다.

## 발견한 실패와 수정

첫 GPU 캡처에는 Phone 배경의 칸 위에 작은 HD 패널이 중복돼 있었다. 통과한 테스트 수로 완료 처리하지 않고 실제 캡처를 보고 패널을 제거했다. 원본은 셀마다 ItemBox를 추가하지 않는다는 사실도 확인했다. 원본 좌표에 같은 HD 아이콘과 입력만 올리도록 고쳤다.

독립 검토에서 다음3건을 추가로 고쳤다. 실제 GameSession에 Screens를 연결한 검사로 확인했다.

- 탭 전환의 상세창 닫기를 원본2112 `push`로 전달한다. 선택 하이라이트는 유지하고 상세·BUY·SELL만 닫는다.
- 거래 확인창이 열린 동안 로컬 탭·스크롤·배경 이동과 검사 보조 reveal이 뒤쪽 화면을 바꾸지 못하게 한다.
- compact→regular 전환에서 버튼 반올림 설정이 남지 않게 원래 `none`을 명시한다.

처음 맵 밖 보정을 제거했을 때 Player가 아래로 벗어나는 문제도 드러났다. 유한 맵과 Player 보호 범위가 만나지 않으면 가장 가까운 유효 맵 경계로 옮긴다. 하단에서 줌아웃할 때 기본 HUD에 Player 중심이 가리는 범위는 공통 표시 정책에서 제한한다. 일반 대기1과 iPad 고정1은 유지한다.

치트 화면 크기를 바꾼 뒤 새 Phone 텍스처를 준비하지 않는 누락도 고쳤다. `ConcurrentRuntime::setDisplay`에서 새 소유자의 준비 자원을 GPU에 전달한 뒤 기존 소유자를 정리한다. 동시 검사 입력 계획도 HUD 뒤 가까운 적에 멈추지 않도록 보강했다. HP·명중·발사 결과를 주입하지 않는다.

단순 size/center 지형 quad가 검게 나오던 초기 GPU 실패를 보존했다. 당시 좌표·크기·clip·RGBA·texture matrix는 정상으로 기록됐고 GL 내부 원인은 확정하지 못했다. compact 맵을 기존 `VisualLayer` Tile2D의 전체4정점·UV0..1 생성 경로로 연결했다. regular iPad 경로는 유지한다. 최종 전투 캡처에서 검정 화면과 끝 픽셀 늘림은 재발하지 않았다.33개 배율의 동등 quad 비교에서는 정점 색 보간에 따른8비트1단계 차이까지 검사하며, 이를 원작 전체 픽셀 동일성으로 주장하지 않는다.

## 범위와 남은 일

이번 세 항목의 결과와 과거 카메라 정식판 설치를 구분한다. 현재 iPhone 실기기의 마지막 설치는 이전 카메라 수정판이다. 가로 왼쪽, 장기 실기기 발열, 기존 허브 포그라운드15초 전환 실패, 전체 캠페인은 이 작업의 통과 결과로 바꾸지 않는다. 원본의 모든 기능이 같다는 판정도 하지 않는다.

원본·사용자 저장·실패 로그·실제 GPU PNG·패키지 명세·trace는 로컬에 보존한다. 보고는 기존 HeavyMach2 누적 목록에 연결한다.
