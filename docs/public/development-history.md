## 일반판과 HD판의 비교

확보한 일반판 네 종과 HD판 두 종에서 패키지 해시, 게임 데이터, 무기·파츠·임무, 배치와 그림의 차이를 확인했다. 원래 앱을 실행하는 비교용 포팅판과 새 C++ 소스로 만든 복원판을 함께 사용했다. 복원 코어의 게임 데이터는 HD 1.0.3에서 준비하고, iPhone 메뉴는 일반판 2.0.1도 참조한다. 두 판본에서 확인한 동작을 기기별 비교 기준으로 삼았다. [여섯 판본 조사](../ipa-version-audit.md) · [비교용 포팅 앱](../../Compatibility/README.md) · [HD 원본 함수 조사](../hd-original-function-audit-20261111.md)

## iPad에서 플레이가 이어지도록 복원

초기 작업은 iPad에서 기지·전장·사령부·저장이 이어지게 하는 데 집중했다. 예를 들어 사령부 완료 화면은 완료한 임무를 전환하고, 보상과 아이템 수량을 저장한다. 같은 저장과 입력을 사용한 비교에서는 원작 HD와 복원판 모두 80 Cr과 100 Cr을 순서대로 지급했고, 최종 잔액과 EXP, 보상 수량이 일치했다. 정식 iPad 앱에서는 작성자가 실제 임무를 수락·완료하고 전투·수집을 확인했다. [사령부 대조](../command-detail-restoration-20261111.md) · [iPad 사용자 플레이](../ipad-release-installation-20261111.md)

## iPhone 화면과 공통 기능

iPhone 가로 화면에 맞춰 기지와 상점, 전장 화면을 조정했다. 원본 Phone 상점과 정비의 크기를 다시 측정했고, 공통 렌더러에서 그림·거래 버튼·슬롯 배치를 같이 처리했다. 실제 플레이에서 보고한 점프 누락, 급격한 배율 변화, Skyway 레이어 떨림을 재현해 수정했다. 같은 시기의 iPhone·iPad 시뮬레이터 치트 앱은 각각 126조건·2,100프레임을 실행했다. [상점 비교](../iphone-shop-reference-coordinates-20261119.md) · [재현·수정·검사](../iphone-module-audit-20261118.md)

## 화이트마운틴과 미등장 콘텐츠

기지 그림이 남은 화이트마운틴과 HD 1.0.0의 설원 그림 여섯 장을 조사했다. 새 포털과 보스 의뢰, 적 배치를 구현해 Desert 01에서 설원으로 이어지게 했다. 원래 갖고 있던 무장과 발사음을 활용해 25종의 무기와 레이저 공습·수집 BOT에 플레이 경로를 연결했다. 두 기기의 치트 앱은 포털 14방향, 보스 의뢰 4건과 장비 검사 29건씩을 실행했다. [그림·데이터 조사](../original-unused-content-20261119.md) · [전장·보스·무장 결과](../white-mountain-implementation-20261119.md) · [보스 거리·글꼴과 정식판 설치](../white-mountain-dual-release-20261120.md)

## Android·웹·Mac과 저장 이동

Android는 게임 규칙과 화면을 공통 C++ 타깃에서 읽는다. 갤럭시에 정식·치트 APK를 설치하고, 두 앱에서 같은 iPad 저장을 확인했다. 이 구현은 PR #23으로 `develop`에 병합됐다. 후속 작업에서는 동일 코어의 정식·치트 PWA와 Tauri Mac 앱, 슬롯 전체를 옮기는 복구코드를 만들었다. Mac Chrome에서 설치한 두 PWA의 오프라인 재실행과 저장 유지, iPhone 시뮬레이터의 홈 화면 실행을 확인했다. Tauri 세로 창과 각 호스트의 저장 검증 범위는 기기 기록을 따른다. [갤럭시 플레이](../../Android/검증-20261120.md) · [PWA와 Mac](../pwa-device-validation-20261120.md) · [복구코드](../save-transfer.md)

## 에셋과 현재 확인 범위

HeavyMach 1·MachDefense와 그림 및 효과음이 실제로 소비되는 경로를 비교했다. HeavyMach 2 웹과 Tauri의 효과음도 공통 OpenAL을 사용하게 했다. 정식·치트 웹에서 그림 1,359개와 음원 58개를 추출해 Apple·Android 패키지와 비교했고, 설치형 Chrome의 전투에서 원본 기관총·미사일과 피격·폭발음을 출력 버퍼로 확인했다. 세로 태블릿의 기지 제목 잘림과 모바일 공통 화면에 남은 미사용 분기는 TODO에 있다. [에셋 사용 대조](../code-document-fixes-20261121.md) · [현재 체크](../todo.md#현재-체크--2026-11-21)

## 내가 일을 시키고 테스트한 방법

일반판과 HD판의 구현·정책 차이 때문에 약식 하네스를 쓰기로 했던 당시 판단을 원문에 남겼다. [약식 하네스 도입 경위](../harness-adoption-note-20261115.md)

나는 실제 iPhone에서 여러 점으로 경로를 그린 뒤 다른 곳을 찍고 두 번 탭해도 점프가 안 되는 경우를 보고했다. Codex는 어느 좌표가 입력에서 사라지는지 기록하며 재현했다. 화면에서 같은 위치로 환산되는 작은 이동 이벤트를 월드에 넘기지 않도록 바꿨고, iPhone과 iPad 시뮬레이터에서 새 경로를 한 점과 여러 점으로 지정하는 경우를 각각 반복했다. 두 시뮬레이터에서 조건별 다섯 번을 통과했다. 실물에서 길게 반복했을 때의 성공률은 TODO에 남겼다. [입력과 SP 소비 검사](../iphone-module-audit-20261118.md) · [실제 녹화의 발췌](gameplay-gallery.md#iphone의-이동-경로와-상점)

화이트마운틴에서는 새 그림부터 그리기 전에 기존 그림과 배치 데이터를 조사하도록 했다. 나중에 포털 근처에 보스가 바로 나타나는 점을 보고 전장 안으로 옮기도록 했다. 치트판으로 포털 이동과 도착, 보스 접근·격파, 사령부 보고와 저장을 확인했다. 두 실기기에는 같은 정식판과 iPad 진행을 넣었고, 내 iPhone에서 화이트마운틴이 열리는 걸 확인했다. [치트 실행과 두 기기 정식 설치](../white-mountain-dual-release-20261120.md)

PWA는 앱 아이콘으로 실행한 창에서 검증하도록 했다. Safari 탭의 짧은 화면에서는 Shop과 Exit가 겹쳤고, iPhone 시뮬레이터 홈 화면에서 실행한 앱에서는 두 버튼을 각각 확인했다. 기기와 앱의 실행 형태가 다른 결과를 각각 기록했다. [PWA 재현과 설치 앱 실행](../pwa-device-validation-20261120.md)

## 코드 구조

HD와 일반판에서 읽은 자원은 준비 도구를 거쳐 같은 캠페인 폴더에 모인다. C++ 코어는 원작 표와 맵을 읽고 메크를 조립하며 전투·임무·버튼·저장을 처리한다. 각 호스트는 화면·입력·소리·저장을 자기 플랫폼에 연결한다. [자원 준비](build-and-install.md#원본-자원-준비) · [기술스택과 원작 에셋](../technology-and-assets.md)

| 호스트 | 화면·입력·저장 |
| --- | --- |
| [Apple](../../Sources/Platform/Apple) | Objective-C++ 호스트가 터치와 OpenGL ES 출력을 연결한다. 원작 WAV 효과음은 OpenAL, 배경음은 AudioQueue로 출력한다. |
| [Android](../../Sources/Platform/Android) | Kotlin Activity와 JNI가 NDK 공통 코어에 입력을 전달한다. EGL·GLES, OpenAL, 앱 전용 저장소를 사용한다. |
| [웹/PWA](../../Sources/Platform/Web) | Emscripten이 코어를 Wasm으로 빌드한다. WebGL 2와 OpenAL을 쓰고, 설치 캐시와 IndexedDB는 웹 호스트가 관리한다. |
| [Tauri Mac](../../Desktop/Tauri/README.md) | 검증한 동일 웹 파일을 번들에 담는다. Rust 호스트가 진행·복원 전 백업과 HUD 배치를 Mac 앱 데이터 폴더에 저장한다. |
