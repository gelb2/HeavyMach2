## 1. iPhone에서 경로를 바꾼 뒤 점프가 안 됨

나는 iPhone에서 경로를 다시 그은 뒤 두 번 탭해도 점프가 안 되는 경우를 제보했다. iPhone 시뮬레이터에서 이 입력을 반복하자, 손가락이 캔버스 좌표상 같은 위치에 있어도 UIKit의 미세한 좌표 차이로 이동 이벤트가 전달됐다. 그 이벤트가 첫 탭 기록을 지웠다.

코덱스는 캔버스로 변환한 뒤 같은 좌표에 남은 이동 이벤트가 전장에 전달되는 경우만 걸렀다. 메뉴와 HUD의 이동 이벤트는 기존 순서로 처리한다. iPhone·iPad 시뮬레이터에서 경로를 한 점 또는 여러 점으로 바꾸는 경우를 각각 다섯 번 실행했다. 두 기기에서 각 10회 모두 점프 한 번과 SP 100 소비를 확인했다. 실기기의 반복 실패율은 아직 측정하지 않았다. [입력 재현과 수정 후 결과](../iphone-module-audit-20261118.md#수정과-시뮬레이터-검증)

## 2. 이동 중 확대 급변과 Skyway 배경 떨림

나는 iPhone에서 전장 화면의 배율이 갑자기 변하고 Wasteland Base에서 Skyway로 나간 뒤 배경이 미세하게 떨린다고 제보했다. 이동 중 플레이어가 기본 HUD에 가까워지면 카메라가 새 배율 하한을 즉시 적용했다. Skyway에서는 배경과 화면 폭이 거의 같을 때 작은 수치 차이로 배경의 가로 위치 제한이 끊겼다.

코덱스는 HUD에 가까워질 때 보정을 목표 배율에 점진적으로 반영하고, 배경의 가로 여유가 없으면 화면 가운데를 기준으로 위치를 고정했다. 78개 맵의 37,440틱에서 iPhone 배율이 한 틱에 0.01을 초과해 바뀐 횟수가 19회에서 0회로 줄었다. Skyway의 iPhone 시뮬레이터 300프레임 비교에서 배경 가로 이동 최대값은 3.170pt에서 0.000031pt로 줄었다. iPad의 비교 프레임 두 장은 수정 전후 픽셀이 같았다. 실제 iPhone에서 같은 경로를 이동할 때의 연속 프레임은 추가 확인이 필요하다. [계측·수정·검증](../iphone-module-audit-20261118.md#수정과-시뮬레이터-검증) · [Skyway 진입 경로](../iphone-module-audit-20261118.md#wasteland-base에서-skyway로-나간-뒤의-떨림)

## 3. iPhone 상점의 빈칸과 레이저 건 구매 거절

나는 인벤토리에 빈칸이 보이는데 레이저 건 구매가 거절된다고 했다. 저장 사본은 75칸이 모두 찼다. 화면은 25칸짜리 페이지를 20칸과 5칸으로 나눴지만 두 번째 화면에도 20칸 배경을 그렸다. 이 때문에 전체 여섯 화면 중 2·4·6번째가 실제 저장에 없는 빈칸을 각각 15개씩 표시했다.

코덱스는 상점·장비 화면의 배경을 실제 슬롯 수에 맞췄다. 호스트에서 저장 사본을 사용하자 가득 찬 상태의 LS-102 구매는 거절됐고, 한 칸을 비우자 구매됐다. 같은 저장으로 iPhone 시뮬레이터의 상점·장비 여섯 화면을 각각 캡처해 20·5·20·5·20·5칸을 확인했다. 수정판의 실기기 재확인은 남아 있다. [저장 사본과 화면 검증](../iphone-inventory-last-page-20261120.md)

### iPhone 상점에서 기지 배경이 비쳐 보임

상점은 iPhone 원작의 화면을 다시 캡처해 아이콘·상세창·거래 버튼 크기와 페이지를 대조하도록 했다. 기존 iPhone 상점에서는 뒤의 허브 그림이 비쳐 보였다. 격납고 그림에서 빈 상품 칸과 패널을 분리한 편집본으로 상점·정비소를 채우고, 실제 슬롯과 버튼은 공통 UI에 남겼다. 화면 전체를 채운 결과와 기존 iPad 상점 6곳의 픽셀을 시뮬레이터에서 대조했다. [원본 상점 크기·배경·버튼 비교](../iphone-shop-reference-coordinates-20261119.md)

## 4. iPad 상점의 특수공격 탭에 레이저 공습이 없음

iPad에서 내가 찾던 상품은 특수공격 탭의 레이저 공습 `02006`이었다. 복원 데이터에 넣은 상품 레벨 30 때문에 상점이 Lv24~50에만 이 상품을 진열했다. 내 저장은 Lv22였다.

코덱스는 상품 레벨을 원본 행의 0으로 되돌려 다른 공습과 같은 상시 판매 규칙을 적용했다. iPhone·iPad 치트 앱을 Lv22로 열어 상품 진열과 BUY, 30 Cr 결제, 퀵 슬롯 등록을 확인했다. 전장에서 공습 소모, 발사체 10발과 적 HP 감소, 지정 효과음 재생도 확인했다. [레이저 공습 진열·결제·전투 검사](../campaign-and-ipad-followup-20261120.md#특수공격-탭의-레이저-공습)

## 5. 설원 진입 직후 보스가 보임

나는 포털에서 설원에 들어서자마자 보스가 보이는 배치가 다른 전장과 다르다고 지적했다. 보스 위치를 맵 중앙부로 옮기고, 의뢰를 수락한 뒤 보스 위치의 240단위 안으로 접근해야 기존 생성기가 작동하도록 했다. 기지 출구 글꼴도 기존 포털에 쓰는 Trebuchet 굵은 이탤릭으로 맞췄다.

iPhone·iPad 치트 앱에서 포털 14방향과 보스 의뢰 4건을 각각 실행했다. 포털 진입 직후엔 보스가 등장하지 않았고, 접근 뒤 등장·전투·격파·보상 저장이 이어졌다. 나는 정식 iPhone 앱에서 화이트마운틴 진입을 확인했다. [포털·글꼴·보스와 정식판 확인](../white-mountain-dual-release-20261120.md)

## 6. Safari 탭에서 상점을 눌렀는데 기지에서 나감

iPhone 17 Pro 시뮬레이터의 가로 Safari 탭은 캔버스에 874×338을 제공했다. 첫 기지에서 Shop을 눌렀을 때 슬롯 화면이 열렸다. 같은 크기의 공통 C++ 검사에서 화면 안으로 옮긴 Exit의 터치 영역이 Shop 중앙과 겹쳤다. 입력 처리 순서상 Exit가 터치를 먼저 받았다. 같은 기기 분류와 폭에서 높이만 402로 높인 검사에서는 여섯 기지의 Shop이 터치를 받았다.

내가 확인을 요구한 것은 아이콘으로 실행한 설치형 PWA였다. iPhone 시뮬레이터 홈 화면에서 실행한 치트판 첫 기지에서는 Shop과 Exit가 각각 동작했다. 정식판에서는 상점 왕복을 확인했다. 874×338 Safari 탭의 겹침과 실기기에서 같은 상점 경로를 반복하는 검사는 남아 있다. [공통 코드 재현 좌표](../pwa-wasm-audit-20261120.md#현재-범위의-화면-검사) · [홈 화면 실행과 터치 결과](../pwa-device-validation-20261120.md#iphone-홈-화면에서-실행한-치트판)

## 7. Tauri Mac 화면이 검거나 깨져 보임

나는 타우리 맥 버전 테스트 도중 화면이 깨지거나 검게 나오는 것을 봤다. PWA와 Tauri가 쓰는 웹 실행부에서는 저장 이동 창을 연 채 화면 크기를 바꾸거나 WebGL이 복구된 뒤 일시정지 상태에서 그리기가 재개되지 않는 조건을 찾았다. 코덱스는 게임 진행을 멈춘 상태에서도 이 경우에 화면을 다시 그리도록 수정했다.

데저트 기지 정비소에서는 작은 원본 패널과 공통 HD 버튼 좌표를 함께 쓰면서 검은 여백과 슬롯 어긋남이 생겼다. 원본 격납고 그림과 공통 HD 인벤토리 패널을 배치해 그림과 아이템 드롭 좌표를 맞췄다. Chromium에서 창 크기 변경과 WebGL 복구를 검사했고, 맥미니에서 정비소 입장·아이템 이동·기지 복귀를 확인했다. 새 클론의 정식판에서는 기지·전장 입장과 이동, 재실행 뒤 저장 유지를 확인했다. 치트판은 별도 슬롯으로 기지에 들어갔다. 세로 치트판의 시설 왕복과 Mac 음향은 남아 있다. ## 8. 갤럭시 PWA가 홈 복귀 뒤 세로로 열림

공개 v0.1 설치 앱에서 홈 화면에 나갔다 돌아오자 전장이 384×749 세로로 바뀌었다. 설치 매니페스트에 방향이 없었고, 웹 캐시만 업데이트한 동안에는 Chrome이 관리하는 앱의 방향도 갱신되지 않았다.

v0.2는 휴대폰 설치 설정에 `landscape`를 지정한다. OS가 세로 화면을 제공하면 게임을 일시정지하고 가로 안내를 표시한다. 갤럭시에서 설치 항목을 갱신한 뒤 Android의 `SENSOR_LANDSCAPE` 설정과 홈 복귀 후 755×354 가로 화면을 확인했다. 반대쪽 가로 회전은 실기기에서 추가 확인이 필요하다. [재현과 갤럭시 갱신](../pwa-lifecycle-audit-20261121.md#갤럭시-설치-앱)

## 9. PWA가 홈 복귀 뒤 배경음을 이어서 재생하지 않음

홈 화면으로 나갈 때 음악 소스를 끝내고 복귀한 뒤 새 소스를 만들었다. 현재 웹 음악 어댑터는 소스와 시간 위치를 보존하고 컨텍스트를 정지했다가 재개한다. 다른 곡을 요청하는 장면 전환은 새 소스를 만든다.

갤럭시 공개 v0.2의 실제 전장에서 홈 화면으로 나갔다 돌아왔다. 새 소스를 만들지 않았고 같은 소스의 재생 시간이 다시 진행됐다. 효과음은 기존 공통 OpenAL 경로를 쓴다. [배경음 코드와 검사](../pwa-lifecycle-audit-20261121.md#원인과-수정)

## 10. 새 공개 클론에서 캠페인 자원이 없어 앱이 빌드되지 않음

공개 Git 체크아웃에는 코어 코드가 있었지만 네 플랫폼이 패키징할 캠페인 파일과 Apple 아이콘이 준비되지 않았다. 공개 PWA의 고정 버전에서 패키지 파일을 받아 SHA-256을 검증한 뒤 캠페인과 아이콘을 준비하는 명령을 추가했다.

새 공개 클론에서 1,576개 캠페인 파일을 준비했다. 기존 배포 준비 자원과 바이트가 일치했고 네 플랫폼을 빌드했다. [재현 명령](build-and-install.md#공개-빌드에서-자원-준비) · [실행 확인](validation.md#공개-클론에서-빌드와-실행)
