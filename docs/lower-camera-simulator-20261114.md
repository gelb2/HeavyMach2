# 카메라 하단 여유의 시뮬레이터 검사

원본 자원의 그리기 크기를 유지하면서 iPhone 카메라를94단위 더 내리는 방식은 이번 검사에서 채택하지 않았다. 38개 맵 모두 빈 영역이 드러났다. HUD를 그려도 가려지지 않는 검은 영역이 남는다.

검사는 iPhone Air 시뮬레이터의 실제 GLES 렌더러로 수행했다. 게임·맵·포털·자원·뷰포트 구현은 바꾸지 않았다. 검사 안에서만 두 카메라 위치의 정적 프레임을 만들었다. 정식판 수정·실기기 설치·실제 포털 이동 검사가 아니다.

검정색을 가진 원본 픽셀과 아무 자원도 그려지지 않은 곳을 구분하기 위해, 검사 프레임 맨 뒤에만1×1 A8 조사 텍스처를 놓은 프레임과 놓지 않은 프레임을 비교했다. 조사 텍스처는 제품 자원이나 원본 이미지로 저장하지 않는다. 정상 캡처에는 들어 있지 않다. RGB가8비트1단계를 넘게 달라지는 픽셀을 바탕이 드러나는 곳으로 기록했다.

Stage01_01에서는 카메라94하강 후 화면 아래93행이 지형 밖으로 나왔다. HUD가 없으면84,816픽셀이 검정 바탕으로 남았다. 기본 HUD를 그려도 바탕 영향36,833픽셀, 그중 순수 검정36,206픽셀이 남았다. HUD는 가로576범위를 차지하므로 양옆을 가릴 수 없다.

Stage02_06은 원본 배경이 있지만 원작 그리기 폭768로는912폭을 덮지 못한다.94하강·HUD 조건에서 검정37,409픽셀이 남았다. 현재의 추가 균일 확대를 쓰면 넓은 검정 공백은 없어지지만, 추가 확대 없이 채워졌다는 결과로 보고할 수 없다.

이 결과는94하강 표본의 결과다. 모든 작은 이동량·카메라X·줌·HUD배치·메크 이동을 전수 검사한 것으로 확대하지 않는다. 포털을 드러내려면 필요한 수십 단위의 하강이 실제 지형 밖을 드러낸다는 구조와 대표 GPU 결과가 일치한다. 기존 지형의 끝 픽셀을 연장하거나 원본 UV 밖을 반복해서 채우지 않았다.

## 함께 발견한 오른쪽 한 열

현재 추가 배경 확대 조건의5맵에서는 검정 픽셀은0이지만, 조사 바탕과 비교하면267..377픽셀이 달라졌다. 최종 검사에서 이 픽셀은 모두 오른쪽 끝X911 한 열에 있었다. 카메라 하강 전에도 관측됐다.

원본 배경의 폭384를512폭 POT 텍스처에 넣고 남는 영역을 투명하게 초기화하며 GL_LINEAR로 샘플링하는 현재 경로와 관련된 것으로 추정한다. 한 열이라는 관측만으로 내부 원인을 확정하지 않는다. 자원 샘플링 경계 조사 TODO로 남겼고, 이번에 제품 렌더러를 수정하지 않았다.

## 검사 성공과 후보 불합격을 구분한다

최종 Native 검사는1/1을 통과했다. 이는172조건의 측정값·기하·누출 위치와 예상한 실험 결과가 일치한다는 뜻이다. 카메라 후보의 합격 조건은 별도로 바탕 누출0과 추가 확대 없음으로 유지했고,94하강 조건은 모두 불합격이다.

처음에는 검사 코드의 자원 클래스/생성자 이름 오류로 컴파일이 실패했다. 이어 실행된 구 테스트 번들의0개 검사 결과는 성공 근거에서 제외했다. 이후에는 빌드 실패 시 실행을 멈추고 실제 통과 검사 수가1인지 확인했다.

두 번째 실제 검사는 배경이 완전히 불투명할 것이라는 예상과 달리 오른쪽 한 열의 누출을 찾아 실패했다. 이 실패와 소스를 보존했다. 마지막 검사는 그 누출의 위치를 명시적으로 검사하면서 후보의 바탕 누출0 기준은 그대로 유지했다. 독립 검토에서도 이 구분과 최종 수치를 확인했다.
