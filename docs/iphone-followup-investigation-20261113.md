# iPhone 개발을 위한 추가 조사와 남은 확인

2026-11-13. 작업 브랜치는 `feat/iphone-universal-20261113`이다. 사용자의 요청에 따라 앞선 일반판·HD판 비교에서 남은 항목을 조사하고, 확인 사실·개발 결정·검사 계획·금지사항을 연결한다. 게임 코드·에셋·설치된 앱·사용자 저장은 이번 조사에서 변경하지 않는다.

[개발 기준·계획·금지사항](iphone-development-contract.md) · [다음 세션 인계](../HANDOVER-IPHONE-UNIVERSAL.md) · [최초 정적 조사](universal-design-audit-results-20261113.md)

## 비교 기준과 보존 범위

비교 대상은 일반판2.0.1과 HD1.0.3이다. 두 기기의 차이와 출시 버전의 차이를 구분한다. 복원판은 HD 에셋 한 벌·HD 게임 규칙·같은 C++20 코어를 사용한다. iPhone에서는 일반판, iPad에서는 HD판의 실제 표시 크기·비례를 기준으로 삼는다. 일반판의 모든 게임 수치를 iPhone에 별도로 복제하지 않는다.

기존 여섯 IPA 파일9,123개 비교·이미지7,740항목 디코딩·원본 함수 본문 보존은 재사용한다. 파일 전수와 모든 함수 의미 대조를 같은 완료 상태로 기록하지 않는다. 사용자가 확인한 실제 iPad의 Wasteland 진행과 크래시 미발견 관측, 기존115조건·1,200프레임 치트 결과는 당시 범위로 보존한다.

| 상점 | 일반판16개/페이지, HD24개/페이지·6열 | 화면에 맞추려고 상품 수·선택/페이지 규칙을 일반판으로 바꾸지 않는다. |
| 에어리프트 | 일반판5행, HD6행. HD는 해금행에 따라 패널 높이를 바꿈 | HD의6개 항목과 해금·콜백을 유지하고 가림·입력을 검사한다. |
| 상점·정비 | 일반판은 한 클래스가 배경을 선택, HD는 두 화면 클래스 | HD 화면 역할과 콜백을 유지한다. 클래스 이름만으로 대응하지 않는다. |

| 타이틀 | 일반판 대기11초, HD10초 | UI 배치 변경으로 시간·입력 해금 시점을 바꾸지 않는다. |

| 저장 사건 | 직접 caller 일반6개·HD5개를 사건·조건에 연결. HD의 메뉴·맵 전환에는 isSave 조건 | 두 기기는 HD 저장 사건·28,204바이트 포맷·seed/XOR/checksum을 공유한다. 매 발사·보상·tick 저장을 추가하지 않는다. |
| RNG | 맵·저장·암호화 테이블도 random/srandom을 사용 | seed값뿐 아니라 호출 순서와 reseed 사건을 기록한다. 표시·배치 변경 코드에서 추가 RNG 소비를 만들지 않는다. 원작 맵 진입·저장 등의 reseed 사건은 보존한다. |
| 효과음 | 일반 재생은 파일명 cache의 기존source ID를 stop/replay. source 생성은cache miss 경로 | 동일 ID 재발사와 다른 ID 동시 재생을 구분하고 예열 뒤 생성·디코드 계수를 검사한다. |
| BGM | output callback·isRunning listener·pthread entry·effect loop worker의 pointer4개를 원본word와 연결 | queue 재생·정지·EOF·형식 변경을 효과음 context 수명과 구분한다. |
| 카메라 소비 | 일반판 draw는 월드 layer 0..8에 줌을 적용하고 HUD가 있는 layer 9 앞에서 matrix를 복구. 입력은 같은 배율의 역변환 | 월드 크기와 HUD 크기를 따로 계산하고 두 좌표 변환을 중복 적용하지 않는다. |
| HD 캐시 순서 | 일부 기체 이동·그리기는 기존 화면 캐시를 읽고 기반 tick에서 갱신. pause 중에도 camera와 base tick을 호출하는 경로 | 프레임 시작의 전체 화면 판정 재계산이나 월드 트리 전체 pause 반환으로 바꾸지 않는다. |
| 탄환point 경로 | 대상에 따라 점 충돌 함수를 선택하며 hit 시 impact 처리 뒤 대상 onDamage를 호출. 기본 collideCheck는 0이고 실제 활성 출처는 미확정 | 점·즉발·범위피해를 합치거나 point branch를 모든 무기의 실제 실행 경로로 단정하지 않는다. |
| 적 잔해·BOT 사망 | 잔해 deadline과 제거 요청·트리 제거를 연결. BOT은 base crash 뒤 저장 상태를 정리하고 destroy. 해당 분기에는 화면 밖 제거 조건이 보이지 않음 | 지상 이동의 화면 gate를 잔해 제거·BOT 사망에 공통 적용하지 않는다. |
| 누락진입30개 | 기존 Ghidra 본문 목록 밖 28개 진입은 REA 명령 추적, 2개는 Ghidra 해독 실패 뒤 LLVM 해석으로 보완. 두 Enemy 진입은 실제 피격·파괴 함수 | 누락 진입을 일괄 stub으로 취급하지 않는다. 명령 관측을 함수 전체 의미 동등성 완료로 바꾸지 않는다. |

HD CFString364개는 원본 SHA를 확인한 실행파일에서 읽어 로컬 주소표로 만들었다. 이를 통해 UI 함수의 숫자 상수를 실제 자원 파일명·ID와 연결한다. 전체 문자열은 `.local`에만 두고 저장소·보고 사이트에는 옮기지 않는다.

## 현재 복원 코드에서 함께 고칠 연결

기존 [화면 소비자20항목](evidence/universal-restored-layout-gaps-20261113.json)을 재사용하고 [현행 코드20파일과 추가 사실5개](evidence/iphone-common-display-consumers-20261113.json)의 SHA를 고정했다. 현재 게임 코드를 실행한 결과가 아니라 소스 연결을 읽은 결과다.

- `MapCamera::toScreen/toWorld`는 현재 viewport 중심과 이동값을 사용하는 변환이다. 별도 표시 배율은 아직 없다.
- `MapPreview::compose`는 이미 camera.viewport를 출력 Frame 크기에 전달한다. 모든 월드 Frame이 고정 크기라고 판단하지 않는다.
- Apple renderer는 논리 Frame을 실제 drawable에 등비 fit하고 입력을 그 역변환으로 돌린다. 안전 영역·UI 배치를 Session에 전달하는 연결은 아직 없다.
- `GameSession::Impl::drag`는 HD 인벤토리·퀵슬롯·장비 위치를 별도 수식으로 계산한다. 그림만 옮기면 아이템 드롭 대상이 남을 수 있다.
- 퀵아이템 입력은 일반 전장 입력보다 먼저 처리한다. 표시 배율을 추가할 때 두 소비자가 같은 화면 구성을 받아야 한다.
- `ConcurrentValidation::compose(viewport)`는 이미 그린 각 sourceFrame을 작은 칸에 모은다. 바깥 화면 크기만 바꾸는 것은 각 Session의 iPhone 표시·입력 검사가 아니다.
- 문 전환·맵 로딩·배너의 geometry를 바꾸더라도 phase/tick·저장·음향 사건 순서를 유지해야 한다.
- `Screens::coverage()`의 일부 주소·상태값은 현행 코드와 맞지 않는다. 이를 실제 미구현 목록이나 실행 완료율로 쓰지 않고 원본 근거·실제 소비 코드를 연결해 정리할 TODO로 남긴다.

## 후속 분야별 근거

분야별 문서는 같은 원본 해시와 기존 ASM·pseudo 캐시를 사용한다. 새로 확보한 명령은 조회 방법과 분석기 한계를 따로 남긴다. 원본 소스코드를 확보했다고 표현하지 않는다.

- [카메라·충돌·화면 판정·생성/BOT·누락 진입점](iphone-universal-native-followup-20261113.md)
- [전체 UI의 부모·입력·콜백과 현행 소비자](iphone-universal-ui-followup-20261113.md)
- [시간·저장·RNG·음향](iphone-universal-runtime-followup-20261113.md)

시간·저장·음향 후속은 고유217함수의 ASM·pseudo434파일과 BGM 관련pointer4개를 검증했다. HD 월드시간은31함수53호출, 전역 프레임시간은16함수, 직접 저장caller는두판본합계11개다. 정적 검색 지점 수를 실제 실행 횟수로 세지 않는다.

UI 후속은18개 화면 계약 중 선택한 계약15개를 확인했고 가변 분기 전체의 대응은3개 후보로 남겼다. 함수395개 색인 중 선택한 계약의 근거는112개이며 나머지283개는 문법 색인이다. 사령부/상세의 동적 버튼7000 생성자는 별도 미확정이다. 이 숫자를 전체 UI 실행 완료율로 환산하지 않는다.

## 개발 착수와 완료 판정의 구분

| 작업 | 현재 근거와 남은 조건 |
| --- | --- |
| 공통 화면 구성·host 전달 | 현행 소비 경로를 확인했다. bounds·안전 영역·방향 전달과 공통 변환의 기반 구현을 시작할 수 있다. 최종 기기별 배율을 확정한 상태는 아니다. |
| HD UI의 iPhone 배치 | 노드 위치·격자·콜백·현재 드래그 처리를 확인했다. HD의 25칸·24상품·6행을 보존하는 배치안을 구현·측정해야 한다. 기지·사령부·상세의 모든 가변 분기 동등성은 아직 확정하지 않았다. |
| 공통 전투 유지 | HD의 화면 캐시·피해·생성 조건과 순서를 보존한다. 표시 범위를 확장했을 때 실제 경계 전투가 원작 분기대로 작동하는지는 동시 치트와 마지막 원작 대조에서 확인해야 한다. |
| 시간·저장·음향 재사용 | 정적 계약을 추가 확인했다. 기존 공통 구현을 기기 분기로 대체할 이유는 없다. 실제 OS 중단·음향 지연·손상 저장·재시작은 별도 실행 검사다. |

공통 기반을 만들 수 있다는 판단과 전체 원작 의미 조사가 완료됐다는 판단은 다르다. 미확정의 일반판 AI·간접 참조·사용 여부가 미확정인 flag를 임의 구현해 빈칸을 채우지 않는다. 변경할 기능과 직접 관계없는 원작 잔여도 삭제하지 않고 아래 목록에 보존한다.

## 구현 전 또는 실행으로 확인할 항목

| 항목 | 구분 | 확인할 결과 |
| --- | --- | --- |
| 같은 조건의 실제 표시 크기 | 원작 실행·표시 기준 확정 | 메크/적/오브젝트/HUD의 장비·방향·프레임·줌·표적/경로를 맞추고 iPhone/iPad 각각의 표시 크기를 기록한다. 기존 표본값은 보존한다. |
| 화면 경계의 전투 | 코드 분기 확인과 실행 검사 | 지상/항공/BOT, 선택·점/즉발/범위피해·생성/재생성의 원본 예외와 갱신 순서를 유지하고 넓어진 시야의 조작 가능성을 확인한다. |
| 전체 패널의 가독성·입력 | 공통 배치 결정과 구현 뒤 검사 | HD25칸 인벤토리·24개 상점·6행 에어리프트·도움말·팝업의 내용·hit·드래그·툴팁이 누락되거나 어긋나지 않아야 한다. |
| 오디오 중단·복귀 | 실제 OS 실행 | interruption·route change·background/resume 때 clock·source/context·BGM queue가 중복되거나 stale ID를 사용하지 않아야 한다. |
| 음향 지연·다성음 | 실제 출력 계측 | 동일 ID 재발사·서로 다른 ID 동시 재생을 나누고 실제 출력과 지연을 확인한다. 버퍼0.5초 설정을 측정된 지연이라고 부르지 않는다. |
| 간접 호출·alias·library 잔여 | 정적 한계와 조건 추적 | 직접 호출 검색에 없다는 사실을 전체 기능 부재로 확대하지 않는다. 원작에서 활성화 조건이 미확정인 branch는 정상 플레이 동작으로 단정하지 않는다. |
| 저장 손상·재시작 | 실제 검사 | 원작checksum 실패 분기와 복원판의 실패 처리를 확인하고 사용자 저장을 초기화하지 않는다. |

분야별 문서가 구체적인 주소·분기·실행 조건을 보강한다. 이 표의 남은 실행을 완료했다고 쓰지 않는다. 모든 원작 상태 조합의 의미 동등성이나 유니버설 구현 완료도 주장하지 않는다.
