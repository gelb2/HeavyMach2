# 휴대폰 PWA 방향·배경음 검사

## 원인과 수정

공개 `v0.1`을 USB로 연결한 갤럭시에서 설치했다. 앱 아이콘으로 연 독립 창에서 홈 복귀 뒤 384×749 세로 화면이 된 게임을 확인했다. 기존 설치 매니페스트에는 방향 설정이 없었다. 배경음 코드는 홈 화면으로 나갈 때 곡을 끝내고 복귀하면 새 재생 소스를 만들었다.

HeavyMach 1은 설치 매니페스트에 `landscape`를 지정한다. OS가 세로 화면을 주면 게임을 멈추고 가로 안내를 표시한다. HeavyMach 2 휴대폰에도 같은 정책을 적용했다. 기존 앱이 갱신 전에도 새 실행 코드를 받으면 시작·복귀 때 표준 화면 방향 API로 양쪽 가로를 요청한다. 세로 화면에서 시간 진행과 입력을 멈추며, 양쪽 가로의 화면 크기와 안전 영역은 기존 경로에서 계산한다. 태블릿과 데스크톱은 방향 제한이 없는 설치 설정을 사용한다. [HeavyMach 1 WASM PR](https://github.com/gelb2/HeavyMach/pull/24) · [HeavyMach 2 웹 셸](../Web/Shell/app.js)

홈 화면으로 나가면 배경음의 재생 시간과 소스를 유지한 채 오디오 컨텍스트를 정지한다. 복귀하면 같은 소스를 재개한다. 장면이 실제로 다른 곡을 요청하면 새 곡을 재생한다. 효과음은 기존 OpenAL 재생 경로를 사용한다. [배경음](../Web/Shell/audio.js) · [시험](../Web/tests/audio.test.mjs)

변경은 Web 셸·패키징·검사에 들어갔다. 검증에 사용한 정식·치트 Wasm과 게임 데이터는 기존 빌드와 바이트가 같다.

## 실행 결과

| 범위 | 확인한 동작 |
| --- | --- |
| 정식·치트 설치 | Mac Chrome 독립 창 설치, 오프라인 재실행과 저장 유지. 브라우저 설치 안내 5종. 손상된 다운로드를 거부하고 다시 받아 오프라인 실행. |
| 타이틀·저장 | Chrome·Firefox에서 슬롯 생성·보존, 정식·치트 분리, 복구코드의 가져오기·내보내기·잘못된 코드 거부, 크기 변경 뒤 입력. |
| 시설·전장 | iPhone 및 Android 휴대폰 가로 모의에서 기지·사령부·상점·전장·복귀 포털, 크기 변경 뒤 상점 입력. 치트 브라우저에서 연결된 전장 44개 진입과 렌더링. |
| 에셋·효과음 | 기지와 상점 왕복 중 OpenAL 실제 샘플 진행과 소스·버퍼 재사용. 기지 대기 화면에서 텍스처를 새로 읽거나 올리지 않았다. |
| 시작과 복귀 | WebGL 시작 실패가 저장 잠금을 해제했다. 숨겨진 탭에서 시작하면 진행과 음향을 멈추고, 화면이 보이면 다시 진행했다. 배경음 단위 검사에서 세 차례 정지·재개 뒤 동일 재생 소스를 유지했다. |

Safari 주소창을 포함한 874×338 모의 탭에서는 기지 Shop과 Exit의 입력이 겹쳤다. iPad 가로 1194×834에서는 상점 Exit가 캔버스 밖에 배치됐다. Playwright WebKit은 오프라인 새로고침에서 내부 오류를 냈다. 기종별 OS의 회전·음향 정책과 개별 무기·퀘스트 전수 플레이는 이 표의 검사 범위에 포함되지 않는다. [화면 배치 근거](pwa-wasm-audit-20261120.md) · [남은 검사](todo.md#공유-복구코드와-웹mac-후속-작업--2026-11-20)
