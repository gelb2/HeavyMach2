# ExperimentalHUD 구성과 이동 계획

## 적용할 기준

**기능 UI와 정보는 유지하고, 큰 배경판과 불필요한 장식만 제거한다.** 레이더는 상시 표시한다. 레이더 열기/닫기 버튼, HUD 숨김/접기 설정은 만들지 않는다. 레벨·경험치·보유금을 다른 화면으로 옮긴다는 이전 제안도 철회한다. 빈 퀵슬롯은 아이템 등록 위치이므로 슬롯과 입력 영역을 유지한다.

이 문서는 개발 계획이다. 첨부 캡처는 현재 구현된 **클래식 HUD**다. ExperimentalHUD를 구현하거나 실행한 화면으로 제시하지 않는다. iPhone·iPad 모두 같은 공통 C++ HUD를 사용한다. 클래식 HUD와 기존 사용자 배치를 보존한다.

## 유지할 UI와 나눌 조각

| 조각 | 유지할 요소 | 이동 기준 |
| --- | --- | --- |
| 1. 상태·성장 | HP·BOOSTER/SP·EXP 막대, 사용 가능 표시, 레벨·Cr 수치와 구분 표식 | 하나의 조각으로 이동한다. 막대의 원작 값·증감·게이지 그리기 규칙을 유지한다. |
| 2. 왼쪽 무기 | 현재 무기 그림과 버튼, 선택 상태·사거리 밖 표시 | 오른쪽 무기와 별도로 이동한다. 왼쪽 선택 패널의 기준점이 된다. |
| 3. 오른쪽 무기 | 현재 무기 그림과 버튼, 선택 상태·사거리 밖 표시 | 왼쪽 무기와 별도로 이동한다. 오른쪽 선택 패널의 기준점이 된다. |
| 4. 퀵아이템 | 기존5슬롯·아이템 그림·수량·선택/등록 표시 | 5슬롯을 한 줄의 조각으로 이동한다. 빈 슬롯도 등록 기능과 함께 유지한다. |
| 5. 메뉴 버튼 | MENU·MISSION·ITEM 버튼과 누름 상태 | 세 버튼을 한 조각으로 이동한다. 각 원래 메뉴와 기능으로 연결한다. |
| 6. 레이더 | 격자·배경 구분선과 현재 사용하는 모든 마커 | 독립 조각으로 상시 표시하고 이동한다. 월드 좌표로 마커를 계산하는 원작 규칙을 유지한다. |
| 7. 대상 정보 | 원래의 선택 대상 이름·HP와 관련 표식 | 별도 조각으로 이동한다. 대상 선택/해제에 따른 원래 출현 조건은 유지한다. |

무기 선택창은 위7조각에서 빠뜨리지 않고 **왼쪽·오른쪽 보조 패널2개**로 관리한다. 항상 펼쳐 놓는다는 뜻은 아니다. 원래대로 해당 무기 버튼을 누르면 선택 가능한 보유 무기들이 펼쳐지고, 선택하면 원래 장비 교체 동작을 실행한다.

## 제거할 그림과 보존할 그림

제거 대상은 HUD 전체를 연결하는 큰 금속판, 외곽 프레임, 배관·볼트 등 기능을 전달하지 않는 장식이다. 원작의 버튼 그림·선택 강조·경고·수량·게이지·레이더 격자·구분 표식은 유지한다. 임무/레벨업 알림과 지역명 연출도 제거 대상이 아니다.

현재 `GameUI_BG.png`에는 장식뿐 아니라 기능을 읽는 데 필요한 바탕과 표식도 들어 있다. 파일을 통째로 그리지 않는 처리만으로 끝내지 않는다. 실제 픽셀을 확인해 필요한 영역을 기존 reader·UV/클립 경로로 소비한다. 원본 파일을 고치거나 iPhone 전용 변형 이미지를 만들지 않는다. 어떤 영역을 제거하는지는 캡처와 기능 목록으로 대조하고, 기능이 있는 영역은 장식으로 분류하지 않는다.

## 무기 선택 패널과 가변 배치

- 왼쪽·오른쪽 버튼을 옮기면 해당 선택 패널의 시작점과 펼침 기준점도 따라간다. 현재 `weaponChoices()`의 고정 좌표333/478과405,90을 새 위치와 무관하게 남기지 않는다.
- HUD 편집에서 선택 패널도 배치 대상으로 선택하고, 버튼 기준 상대 위치를 조정·저장한다. 왼쪽/오른쪽 값을 별도로 보존한다.
- 원래의 펼침/이동 애니메이션을 같은 로컬 좌표에서 실행하고 최종 표시·터치에 같은 변환을 적용한다. 움직이는 그림과 입력 영역이 어긋나지 않게 한다.
- 화면 끝에서는 패널을 화면 안쪽 방향으로 펼친다. 무기 수가 많으면 세로 스크롤 대신 페이지로 모두 접근하게 한다. 원래 보유 목록·장비 조건·공격력 차이·비활성 조건은 유지한다.
- 아이템의 실제 인벤토리 위치와 ItemCode를 유지해 선택한다. 보이는 행 번호로 다른 무기를 장착하는 일이 없어야 한다.
- 일반 플레이의 무기 터치는 선택에 사용한다. 위치 끌기는 HUD 편집에서만 처리해 전투 중 의도하지 않은 이동을 막는다.

## 기본 배치와 설정

첫 배치안은 상태를 하단 왼쪽, 두 무기를 하단 중앙, 퀵아이템을 그 옆, 메뉴 세 버튼을 오른쪽, 레이더를 독립 영역으로 둔다. 대상 정보는 위쪽에 둔다. 실제 버튼·텍스트가 겹치지 않는 크기와 간격은 양 기기의 캡처로 정한다. 이 배치안의 완성 화면은 아직 없다.

iPhone·iPad 모두7조각과 보조 패널2개를 제공한다. 화면 크기에 맞춘 위치 계산은 공통 표시 모듈에서 한다. HUD를 옮기기 위해 월드 뷰포트·카메라·포털·에셋 비율을 바꾸지 않는다. 화면 끝까지 배치할 수 있고, 안전영역을 강제 여백으로 사용하지 않는다.

스테이지의 메뉴 → HUD 설정에서 클래식/Experimental을 선택한다. 스타일별 배치와 compact/regular 배치를 분리해 저장한다. 클래식의 기존3조각·기존 설정 읽기는 유지한다. 적용/취소/기본 배치를 제공하고, 설정 적용 때만 기록한다. 게임 진행 저장 포맷과 장비·사격 로직은 변경하지 않는다. 숨김/접기/레이더 on-off 설정과 세로 스크롤은 추가하지 않는다.

## 현재 코드에서 바꿔야 할 연결

| 현재 코드 | 확인한 상태 | 구현할 연결 |
| --- | --- | --- |
| HUDLayout.hpp | gauges·combat·controls의3그룹이다. | 클래식3그룹을 보존하고 Experimental7그룹·두 패널의 배치를 별도로 표현한다. |
| Screens::field | 두 무기와 레이더가 combat, 퀵슬롯과 메뉴가 controls에 묶인다. | 각 새 그룹에 그림·문자·수치·버튼·레이더를 함께 배정한다. |
| Screens::weaponChoices | 실제 보유 위치/ItemCode를 사용하고 선택 버튼1024를 만든다. 펼침 목표 좌표는 고정이다. | 원래 장비 액션·아이템 식별을 유지하고, 버튼에 연결한 패널 좌표와 편집 위치를 적용한다. |
| Screens 입력/드롭 | 버튼과 표시 변환을 연결한다. 퀵아이템 드롭 좌표는 기존controls그룹을 역변환한다. | 새 퀵아이템 그룹의 변환을 사용해 등록·교체·선택 위치를 일치시킨다. |
| HUDState/Apple HUDStorage | compact/regular 프로필과 적용 시 설정 저장이 있다. | 스타일별 설정을 추가하고 기존 클래식 배치가 새 Experimental 설정으로 덮이지 않게 한다. |

기존 공통 C++ 게임 UI·GPU 스프라이트·원본 reader를 사용한다. UIKit 게임 버튼이나 별도 iOS HUD 구현을 추가하지 않는다. 화면마다 `visible` 값을 덮는 새 숨김 정책을 넣지 않는다. 원래 게임의 대상/사거리/무기 선택창 등 조건부 동작은 보존한다.

## 구현 후 확인할 것

1. 클래식의 기본/이동 배치와 기존 저장을 전후 대조한다. Experimental을 고른 뒤 다시 클래식으로 돌아와도 그대로여야 한다.
2. 기능 UI 목록, 실제 버튼 ID와 입력, 수치·게이지·레이더 마커의 누락을 확인한다. 제거된 장식 위치에 보이지 않는 터치 영역이 남아서는 안 된다.
3. 두 무기와 선택 패널을 화면 네 모서리·아래 끝으로 옮겨 실제 보유 무기를 선택하고 장착·발사까지 확인한다. 펼치는 동안에도 표시와 터치가 맞아야 한다.
4. 퀵5슬롯의 빈칸 등록·교체·사용·수량, 메뉴/미션/아이템, 대상 선택/해제와 레이더 갱신을 같은 프레임의 여러 치트 조건에서 검사한다.
5. iPhone·iPad에서 배치 적용·취소·기본값·재실행·스타일 전환과 입력을 검사한다. 세로 스크롤·패널 잘림·숫자 이탈을 합격 처리하지 않는다.
6. 설정 드래그·사격 중 저장0회, 원본 자원 캐시/렌더 경로·오디오 컨텍스트 수명을 확인한다. 최종 치트·시뮬레이터 검사 후 필요한 Instruments 측정을 진행한다.

## 캡처와 이미지 분석

아래 시각 자료는 현재 클래식 HUD의 실제 GPU 캡처와 그 위에 표시하는 분석 영역이다. 원본 PNG는 자르거나 재생성하지 않는다. 번호·색 테두리는 보고서의 별도 표시이며 게임에 구현된 새 UI가 아니다. iPhone 가로·iPad 세로의 기본 상태와 왼쪽/오른쪽 무기 선택창을 각각 제시한다. 캡처 출처·원본 크기·SHA와 실제 실행 결과는 함께 기록한다.


이번 캡처 결과: iPhone·iPad 각각90프레임 동안126세션을 동시 실행했고 기본/왼쪽/오른쪽 상태3장을 확보했다. 수정한 캡처 검사는 각각1/1이다. 처음 검사에서 오른쪽 버튼이 왼쪽 선택창을 닫았으므로, 원래 동작대로 닫은 뒤 오른쪽 버튼을 누르게 입력 순서만 수정했다. 실패 기록은 보존했다. 이 검사는 상태와 캡처 확보 검사이며 Experimental 구현 합격이나 게임 전체 시각 합격이 아니다.

**iPhone 오른쪽 선택창 캡처에는 월드의 대각선 검정 영역이 보인다.** 원인은 아직 확인하지 않았다. 원본 PNG와 해당 프레임을 그대로 보존하고 별도 결함으로 기록했다. HUD 계획의 의도된 배경·새 UI로 설명하거나 정상 화면으로 판정하지 않는다. iPad 캡처의 현재 검정 여백도 새로 제안한 화면 구성이 아니다.

필요한 그림을 나누는 계획에서 원본 격자·HP/SP/EXP 구분 표식·아이템 등록 칸·선택 강조를 보존한다. 장식 제거 범위는 원본과 현재 캡처를 대조해 확정하며, 이 보고서의 색 테두리가 최종 에셋 절단선은 아니다.
