설원 6장을 바닥 그림으로 쓰고 기존 맵 규칙으로 새 전장을 만든다. 원본에 남은 맵 번호·무기 번호와 HP는 난도 설정의 단서다. 새 포털, 퀘스트, 배치, 보상은 이번 확장에서 정한다. [원본 조사](white-mountain-feasibility-20261119.md)

| SnowPass | STAGE 12 | 화이트마운틴과 SnowBasin 사이의 첫 설원 전장 |

| SnowField | STAGE 13 | 설원 분지와 설원 능선 |

Desert 01의 북동쪽 포털 #3 (450, 474)에서 화이트마운틴 기지로 들어간다. 기지 출구는 원본 ID 5와 6으로 각각 Desert 01과 SnowPass로 연결한다. 원본 방문 저장에 있는 여섯 번째 슬롯은 실제 화이트마운틴 진입 때 열린다. 기존 맵 포털의 번호·좌표는 유지한다. 원본 데이터 파일을 그대로 보존하고 게임 빌드가 별도 생성한 확장 자원 폴더를 사용한다. 전투, 카메라, 입력은 공용 코어에서 소비한다.

## 2단계 보스와 무장

원본 보스 1~4 전장은 임무를 수락하면 기존 전장의 이벤트 포털이 열리고, 보스 맵의 돌아가는 문은 일반 포털이다. 여러 이벤트 포털이 같은 맵에 있으면 현재 `openGate`가 한꺼번에 연다. 새 보스는 그 효과 범위가 겹치지 않도록 기존 포털과 분리한다. 사령부의 격파 조건은 맵 ID도 지정한다. 보스 번호와 HP가 항상 오름차순인 것은 아니다. 05~08은 각각 HP 100,000·200,000·400,000·1,000,000이다. 원본 M001230의 Boss04 HP 120,000, 400,000 Cr 보상과 해금·전투 조건을 비교해 확장 보상을 정한다.

무장이 없는 비행기는 차체와 기존 그림을 사용한다. 발사에 필요한 장착점과 발사구를 작성하고 기존 적 비행체의 명중·미사일 유형에서 고른다. 접근 레벨은 HP·공격 범위·발사 간격과 같은 급의 기존 맵을 함께 비교한다. 무기·적의 발사음은 `WeaponInfo`의 실제 파일과 공용 오디오 경로를 확인한다.

Boss 05~08은 별도 전장 복제 없이, 수락한 의뢰가 지정한 설원 전장 한 곳에서만 기존 1회 보스 스포너로 생성한다. 보스 05~08은 전장 안쪽에 놓고 플레이어가 240단위 이내로 다가오면 생성한다. 완료 후에도 포털 왕복은 유지된다. 원본 일반 격파 조건은 기존 처리 방식을 사용하고, 새 의뢰의 `killAt`은 전장 ID도 대조한다.

| 의뢰 | 기존 포털을 통한 전장 | 플레이어 표시 레벨 | 대상 HP | 기지 보상 Cr · XP |
| --- | --- | ---: | ---: | ---: |
| M041010 | Base004 → SnowPass #1 → SnowBasin | 28 | 100,000 | 각 300,000 |
| M041020 | SnowBasin #1 → SnowField | 35 | 200,000 | 각 600,000 |
| M041030 | SnowField #1 → SnowRidge | 42 | 400,000 | 각 1,200,000 |
| M041040 | SnowFort #1 → SnowValley | 49 | 1,000,000 | 각 3,000,000 |

첫 임무는 원본 M001230 완료 후, 다음 의뢰는 앞 의뢰를 보고한 뒤 열린다. 원본 Boss04 의뢰가 HP 120,000에 보상 각 400,000을 지급한다는 기준에 맞춰 새 임무의 보상은 대상 HP의 3배로 정했다. 전투 중 원래 적의 경험치·현장 코인은 별도로 소비된다.

비행체 01·02·05는 각각 분지·평원·능선에 배치한다. 원본 HP 500·800·800을 쓰고 장착 파츠·머즐과 거리에 맞춘 사격을 추가한다. 평원에 기존 HP 500의 포탑 06을, 골짜기에 HP 67,000의 전차 30을 둔다.

## 3단계 획득

기존 상점은 아이템별 레벨 창을 적용한다. LS는 원본 장착 레벨을 지키고 같은 레벨대의 드롭에 소량의 가중치를 배정한다. HD 저격총 4종은 기존 판매 플래그에 입수 경로를 연결한다. 상위 장비가 초반 드롭으로 나오는 경우를 경계 검사한다. 동작이 확인된 레이저 공습·수집 BOT을 먼저 연결한다. 대시 공격·화염방사·EMP·방어 BOT은 별도의 전투 규칙과 검사가 필요한 항목으로 관리한다.

레이저 공습은 화면에 표시되는 Lv24~50에서 기존 가격 30 Cr로 구매한다. 두 시뮬레이터에서 구매 뒤 퀵 슬롯에 등록해 1개를 소비했고, 각각 탄 10발과 적 HP 200 감소를 확인했다. 수집 BOT 3종은 기존 Picker C와 같은 가격·수집 로직을 사용한다. 실제 전투 드롭을 수집해 플레이어에게 전달했다.

저격총 4종과 LS 21종은 각각 상점과 드롭 경로를 가진다. 초기 레이저는 기존 동급 드롭 그룹의 희귀 가중치를 쓰고, 후기 레이저와 저격총은 새 보스의 드롭 표를 사용한다. 후기 희귀 장비 11종은 상점이 열리는 최소 레벨부터 떨어진다. 레벨이 낮으면 해당 추첨 결과만 건너뛰며 코인 지급은 유지된다.

대시 공격·화염방사·EMP 및 방어 BOT은 공격·효과 규칙을 정하는 후속 작업이다. 이번에 활성화한 공습과 수집 BOT의 경로를 기기별 분기로 나누지 않았다.


## iPhone 보스전의 지형 그리기

Boss_07·08 격파 직후 iPhone에서 화면의 약 39%가 검게 표시됐다. 같은 카메라 위치를 고정한 뒤 지형 그리기만 바꿔 원인을 재현했다. 화면 밖까지 뻗은 지형 사각형을 다른 방식으로 그리는 후보에서는 삼각형 방향만 바뀌었다.

`MapPreview`는 화면을 채우는 불투명 지형의 정점과 텍스처 좌표를 같은 비율로 잘라 GLES에 전달한다. 일반 스프라이트와 투명한 Skyway는 원래 경로를 사용한다. iPhone의 검은 픽셀은 두 프레임 각각 39.2171%→0.0237%, 39.4585%→0.0205%로 줄었다. 같은 보스 시나리오의 iPad 캡처 16장은 PNG 바이트가 모두 같다. 원본 맵, 카메라 및 범용 화면의 호스트 검사 3건도 통과했다. 커밋은 `58b0938`이다.

## 최종 앱 확인

최종 확장 데이터와 지형 수정이 들어간 동일 치트 앱으로 iPhone·iPad 각각 포털 14방향, 보스 의뢰 4건, 장비 29건을 다시 통과했다. 장비 검사는 25종의 발사·피해·음원, 레이저 공습, 수집 BOT 3종을 포함한다. 보스 07·08의 두 기기 격파 프레임도 다시 캡처했다.

전체 호스트 검사에서 78건 중 77건을 통과했다. 원본 그림 수 검사는 로컬 폴더에 앞서 생성된 iPhone 상점·장비 그림 3개가 더 들어 있어 개수 단언에서 중단했다. 원본 파일만 담은 폴더에서 같은 검사로 그림 1,276장 디코딩과 PNG 1,238장 크기를 확인했다.
