# 일반판·HD판 패키지 전수 비교

2026-11-13. 등록된 일반판 4개·HD판 2개의 모든 ZIP 항목을 읽었다. 총 9,137개 항목 중 디렉터리 14개를 제외한 **9,123개 파일**의 경로·크기·SHA-256·종류를 기록했다. 여섯 IPA 모두 읽기 전후의 해시가 [원본 명세](source-provenance.json)와 같았다. 원본 파일·실행파일·그림·음원·복호 테이블을 추출하거나 외부로 보내지 않았다.

**주 비교는 일반판 2.0.1과 HD 1.0.3이다.** 일반판 내부의 세 인접 버전, HD 1.0.0→1.0.3, 일반판 2.0.1↔HD 1.0.0도 상세 비교했다. 여섯 판본 사이의 전체 15쌍에는 파일 종류별 동일·차이·단독 항목 수를 남겼다. 모든 차이를 기기 차이로 단정하지 않는다.

[결과 JSON](evidence/universal-package-differences-20261113.json) · [재현 도구](../tools/audit_universal_packages.py) · [합성 입력 검사](../tests/test_universal_package_audit.py)

## 주 비교에서 확정한 차이

| 종류 | 일반 2.0.1 | HD 1.0.3 | 공통 경로의 바이트 동일 / 차이 | 한쪽에만 있음: 일반 / HD |
| --- | ---: | ---: | ---: | ---: |
| PNG | 1,236 | 1,238 | 839 / 357 | 40 / 42 |
| JPEG | 60 | 38 | 33 / 5 | 22 / 0 |
| WAV | 56 | 57 | 56 / 0 | 0 / 1 |
| MP3 | 1 | 1 | 1 / 0 | 0 / 0 |
| MCB | 3 | 3 | 3 / 0 | 0 / 0 |
| TBLE·TBL | 135 | 141 | 76 / 59 | 0 / 6 |
| 동봉 셰이더 | 2 | 0 | 공통 없음 | 2 / 0 |

표의 공통 경로는 `Payload/<앱 이름>.app/`을 같은 `app/` 역할로 정규화한 상대 경로다. 실행파일은 plist의 `CFBundleExecutable`로 식별하여 같은 역할에 대응시켰다. 앱 바깥 메타데이터·첨부도 전체 목록에는 포함하고, 게임 자원의 존재와 구분했다.

### 그림과 파츠

- 다른 PNG 357개 중 **342개는 픽셀 크기도 다르다.** 나머지 15개는 크기는 같아도 바이트가 다르다. 동일한 크기만으로 같은 그림이라고 판정하지 않는다.
- 서로 다른 JPEG 5개는 `Stage02_04BG.jpg`부터 `Stage02_08BG.jpg`다. 일반판은 512×512, HD는 384×512다. 지형·배경의 비례나 카메라 시야는 실제 소비 코드와 함께 확인해야 한다.
- 일반 2.0.1의 PNG는 CgBI 1,235개·표준 PNG 1개, HD 1.0.3은 CgBI 1,236개·표준 PNG 2개다. PNG의 실제 청크를 읽었으며 `CgBI`가 `IHDR` 앞에 있는 경우도 처리했다.
- `MachInfo.mcb`, `MapInfo.mcb`, `PartsInfo.mcb`는 세 파일 모두 바이트 동일하다. 이 결과는 조립·맵 데이터의 동일성을 뜻한다. 실행파일의 조립·카메라·전투 소비 코드가 같다는 증명은 아니다.
- 한쪽에만 있는 그림·UI 파일의 전체 이름과, 크기가 다른 공통 그림의 치수는 JSON에 있다. 파일 존재만으로 해당 그림이 실제 게임에서 쓰이는지까지 판정하지 않았다.

유니버설 복원판은 HD 에셋 한 벌을 공유한다. 일반판 에셋을 별도 iPhone 전용 번들로 가져오거나, 일반판 전용 파츠 조립 코드를 만들 근거로 이 목록을 사용하지 않는다. 일반판의 그림은 표시 기준·기능 대응을 조사하는 자료다.

### 모든 공통 테이블 135개의 차이 분류

헤더는 135개 모두 같다. 활성 행·열·순서가 다른 테이블 59개는 다음과 같다.

| 분류 | 파일 수 | 확인한 차이 |
| --- | ---: | --- |
| 기지 UI | 6 | `Base001`~`Base006.tble`의 그림 참조·좌표·배율·일부 행 존재 차이 |
| 설명 사전 | 2 | 한국어 `Value` 2행, 영어 `Value` 9행 차이 |
| 아이템 | 1 | 하체 23종의 SP 관련 값과 일반판에서 비활성인 저격 무기 4종 |
| 무기 | 1 | 213개 정의 중 126행의 사거리·조준·피해 필드 차이 |
| 영어 임무 | 49 | 이름·수락 설명 문구 차이. 아래에서 조건·Action 행을 따로 비교 |

기지 표는 `Type` 값이 반복되므로 단순히 첫 번째 열을 고유 ID로 취급하지 않았다. `Type+ID`와 같은 값의 출현 순서를 함께 사용했다. 다른 표의 중복 첫 열도 출현 순서를 보존했다. 이 정적 대응은 원작의 실제 검색·실행 순서 검증과 별개다.

**하체 23종:** `ItemInfo` ID `12001`~`12023`의 `Param1` 또는 `Param2`가 다르다. `Param1`은 19행, `Param2`는 23행에서 다르다. 현재 HD 근거 구현의 [`Equipment.cpp`](../Sources/Core/Progression/Equipment.cpp#L34)는 두 값을 SP 최대량·회복량으로 소비한다. 보행 크기에 쓰는 `Param3`에는 이 비교의 차이가 없다. 하체 보행을 기기별 소스로 나눠야 한다는 뜻이 아니다.

**저격 무기 4종:** 일반판 `ItemInfo`에서 주석 처리된 `10501`~`10504`가 HD에서는 활성 행이다. 대응 파츠는 `P_Wpn_Sni_101`~`P_Wpn_Sni_104`다. `WeaponInfo`의 피해량 차이 4행도 이 네 파츠다. 이 항목들을 일반판에 원래 없던 그림이나 포팅 누락으로 분류하지 않는다.

**무기 213개 정의:** 사거리 `ShtRng` 113행, 조준 `AimRt` 86행, 피해 `Dmg` 4행이 다르다. 한 행에서 여러 필드가 다를 수 있으므로 수치를 더해 무기 수로 쓰지 않는다. 적·BOT·공습 등의 정의도 포함하며, 모두 플레이어가 장착하는 무기라고 부르지 않는다.

유니버설 복원판의 모든 기기는 **HD 게임 데이터와 규칙**을 공유한다. 일반판의 사거리·조준·SP 값을 iPhone에만 적용하거나 화면 배율 보정에 섞지 않는다.

### 임무 파일: 문구와 조건을 분리한 결과

- `MissionList.tble`는 주 비교에서 바이트 동일하며 60개 임무를 참조한다.
- 한국어 임무 60개 파일은 모두 바이트 동일하다.
- 영어 임무 60개 중 11개는 바이트 동일하고 49개가 다르다. 변경 행은 **`Name` 24행과 `AcptComment` 41행뿐**이다. 현재 HD 근거 reader의 [`Progression.cpp`](../Sources/Core/Progression/Progression.cpp#L84)는 이를 이름과 수락 설명으로 소비한다.
- 각 언어의 60개 파일에 대해 `Require`, `AcceptAct`, `CompleteAct`, `CompleteInf`, `StorySet` 및 나머지 비문구 행의 값과 순서를 별도로 비교했다. **일반판↔HD판의 조건·Action·보상 토큰 차이는 0**이다. 임무 참조·활성 행의 추가·삭제와 헤더 차이도 없다.

이는 **해당 원본 데이터 토큰이 같다**는 결과다. 두 실행파일이 토큰을 같은 수식·분기·시점에 처리하는지는 함수·실행 조사에서 확인한다. 임무 목록 60개가 같다는 사실만으로 원본 임무 로직 전체가 같다고 판정하지 않는다.

별도의 원본 언어 차이도 발견했다. **`M001220`은 여섯 판본 모두 한국어 `Require` 4행, 영어 3행**이며 같은 번호의 요구 행 값에도 차이가 있다. 기기 차이가 아니다. 한국어 기준 복원 요구를 유지하고 원본 언어 차이를 임의로 합치거나 수정하지 않는다.

### 음원·실행 설정

- 공통 WAV 56개와 MP3 1개는 바이트 동일하다. HD에만 `STAGE3.wav`가 추가돼 있다. WAV의 PCM 형식·채널·샘플 비트·샘플레이트와 MP3 헤더를 전수 읽었고 파싱 오류는 없다.
- 두 판본 모두 WAV에 8/16비트·모노/스테레오가 섞여 있다. 동일 음원 파일이 있어도 발사·피격 이벤트, 재생 시점·중첩·중단 복귀가 같다는 뜻은 아니다.
- 일반 2.0.1의 plist는 기기 family 1, 최소 OS 3.1, 가로 두 방향을 등록한다. HD 1.0.3은 family 2, 최소 OS 3.2, iPad 세로 두 방향을 등록한다. 이는 패키지 설정이며 실제 회전 함수의 동작과 구분한다.
- 일반판에만 동봉된 `.vsh`·`.fsh` 2개가 있다. 동봉만으로 실제 사용 렌더링 API나 호스트 오류의 원인을 확정하지 않는다.

## 버전 차이를 통제한 결과

| 비교 | 공통 파일 동일 / 차이 | 한쪽에만 있음: 앞 / 뒤 | 활성 토큰·순서가 같은 공통 표 |
| --- | ---: | ---: | ---: |
| 일반 1.0.0→1.1.0 | 1,389 / 6 | 0 / 6 | 133 / 133 |
| 일반 1.1.0→1.3.0 | 1,391 / 8 | 2 / 17 | 130 / 134 |
| 일반 1.3.0→2.0.1 | 1,077 / 332 | 7 / 95 | 132 / 134 |
| HD 1.0.0→1.0.3 | 1,445 / 20 | 456 / 21 | 129 / 141 |

HD 내부에서 다른 공통 표 12개는 `Base001`~`Base006`의 `.tbl`·`.tble`다. HD 1.0.0과 1.0.3 사이에서도 기지 UI 데이터가 바뀌었다. 주 비교에서 발견한 모든 UI 차이를 기기 크기 하나의 결과로 확정할 수 없다.

파일 수에는 하위 디렉터리의 nib·그림과 앱 바깥 동봉 자료도 포함한다. HD 1.0.0의 단독 파일 456개를 실제 게임 기능이나 사용 중인 자원 456종으로 해석하지 않는다.

주 비교에서 다른 파일 426개 중 412개는 HD 두 버전에서 동일하다. 각 파일의 여섯 판본 간 바이트 동일 그룹을 JSON에 기록했다. 이 통제는 차이가 어느 판본에 존재하는지 좁힌다. 개발자의 분리 의도·원인·공유 소스 범위를 입증하지 않는다.

일반 1.0.0·1.1.0·1.3.0의 `ItemInfo` `12021` 행은 열 11개 중 10개만 읽힌다. 기존 조사에서 기록한 탭 누락과 같다. 도구는 이 행을 임의로 패딩하거나 수정하지 않고 원래 열 수와 키를 기록한다.

## 확인 범위와 남은 검사

완료한 범위는 모든 패키지 항목의 바이트·정적 형식·표 토큰 비교다. PNG/JPEG는 헤더·청크·치수를 읽었다. 모든 그림의 디코딩 픽셀·투명 여백·접합점·실제 표시 크기를 같은 것으로 확정하지 않았다. 동일 파일도 원작 코드가 다른 좌표나 조건으로 소비할 수 있다.

다음은 함수·실행 조사와 연결한다.

1. 일반판·HD판의 표시/입력 변환, 파츠·그림·기지 표 소비와 카메라·전투 활성 범위.
2. `ItemInfo` SP 값, 무기 사거리·조준·피해와 임무 조건·Action을 실제로 소비하는 수식·순서.
3. HD에 없는 일반판 UI 파일의 기능을 공통 HD 자원·기존 공통 버튼 경로로 어떻게 대응할지 확인.
4. 같은 장비·방향·프레임에서 기기별 표시 기준과 안전 영역·터치 영역을 검증.

이번 조사에서는 게임 코드·원본 IPA·앱 패키지를 수정하거나 앱·시뮬레이터·실기기를 실행하지 않았다.

## 재현과 근거

```sh
python3 tools/audit_universal_packages.py
python3 -m unittest discover -s tests -p 'test_universal_package_audit.py'
```

- 여섯 원본 입력은 `docs/source-provenance.json`의 경로와 해시로 선택한다.
- 전체 파일 메타데이터 6개와 상세 비교는 `.local/evidence/universal-package-audit-20261113/`에 보관한다. `comparisons-full.json`은 로컬 상세 결과이며 원본 테이블 전체를 포함하지 않는다.
- 저장소 JSON에는 수치·파일/레코드 식별자·필드명·해시·차이 분류만 포함한다. 중복된 전체 이미지 메타데이터와 변하지 않은 버전별 표 상세는 로컬 목록에 남겼다.
- [기존 패키지 비교](evidence/standard-hd-package-metadata.json)의 PNG 동일 839·차이 357·크기 변경 342와 일치한다. [기존 여섯 판본 조사](evidence/ipa-version-audit-summary.json)의 각 판본 TBLE 수와 주요 표 3개의 인코딩/복호 해시도 모두 일치한다.
