# iPhone 인벤토리 마지막 화면과 레이저 구매

iPhone 실기기에서 빈칸이 보이는 상태에 레이저 구매가 거절됐다고 사용자가 보고했다. 이후 읽어 온 저장 사본에는 실제 인벤토리 75칸이 모두 차 있었다. 저장 페이지마다 20칸을 먼저 보여 주고 5칸을 다음 화면에 보여 준다. 기존 배경은 두 번째 화면에도 20칸을 그려, 전체 여섯 화면 중 2번째·4번째·6번째에 각각 가짜 빈칸 15개가 있었다.

상점과 장비 화면의 인벤토리 배경을 실제 버튼 범위에 맞췄다. 25칸을 20칸과 5칸에 나눠 보여 주고, 각 페이지의 두 번째 화면은 한 줄만 그린다. 두 화면의 그림, 버튼, 판매와 드래그는 기존 공통 표시 경로를 사용한다. 저장 용량과 구매 판정은 원래 규칙을 따른다.

| 시험 조건 | 실제 결과 |
| --- | --- |
| iPhone 사용자 저장 사본, 75/75칸 | LS-102 구매가 거절됐고 소지금은 그대로였다. |
| 같은 iPhone 사본에서 한 칸을 비움 | LS-102가 빈칸에 들어가고 1,950 Cr이 차감됐다. |
| iPad 사용자 저장 사본, 72/75칸 | 현재 진열되는 레이저 8종을 같은 시작 상태에서 각각 선택했다. 실제 BUY와 구매 확인을 눌러 각 가격의 결제와 아이템 추가를 확인했다. |

iPad에서 레이저 구매가 보이지 않았다는 별도 관측을 투두에 남겼다. 두 저장 사본은 Lv22이며 이 레벨에서 LS-D2, LS-10, LS-102, LS-103, LS-103D, LS-L20, LS-L21, LS-L30을 판매한다. LS-D의 판매 창은 Lv21까지다. 이 검사를 한 뒤 사용자는 iPad 쪽 항목을 “특수공격 탭의 레이저 공습”으로 특정했다. 해당 상품의 진열과 구매 수정은 [후속 검사](campaign-and-ipad-followup-20261120.md#특수공격-탭의-레이저-공습)에 기록했다.

수정 전에는 범용 표시 검사에서 마지막 화면에 존재하지 않는 줄의 배경을 검출했다. 수정 후 표시·입력과 원본 구매·판매·BOT 호스트 검사를 통과했다. iPhone 17 Pro 시뮬레이터에서 상점과 전투 동시 실행 검사를 통과했다. 상점 캡처에서 마지막 화면의 인벤토리 오른쪽에 실제 5칸만 보였다. 위 사용자 저장 사본은 호스트에서 시험했다.


## 중간 페이지 재검증

같은 iPhone에서 다시 읽은 저장 파일은 앞선 사본과 일치했다. 실제 슬롯 75칸의 아이템 번호와 아이콘 파일을 대조한 뒤, 두 화면 크기에서 상점과 장비의 아이콘 위치와 잘림을 검사했다. iPhone 시뮬레이터에서는 같은 저장 사본으로 상점과 장비의 여섯 화면을 모두 캡처했다. 두 화면 모두 20·5·20·5·20·5칸에 아이콘이 표시됐다. 수정 후보의 물리 기기 재검증은 남아 있다.
