# HeavyMach2 디자인·에셋 규칙 정본

2026-11-15 사용자 지시를 기준으로 한다. 이 문서는 화면·아트·에셋 관련 요구와 검사 기준의 정본이다. 최신 사용자 수정이 우선하며, 이전 계획·구현·보고서가 이 규칙을 바꾸지 않는다. 사용자 요구가 구현되지 않은 상태는 미완료로 기록한다.

현재 게임은 ExperimentalUI 구현 직전 코드로 [롤백](experimental-ui-rollback-20261115.md)했다. 아래 규칙을 적었다고 게임 구현이나 시각 검사가 완료된 것은 아니다. 기존 하네스와 검사 훅은 제거했다. 전체 화면 관측과 시각 합격은 아직 별도 검증이 필요하다.

## 2026-11-15 메뉴 페이지 전환

허브·상점·사령부의 가로·세로 스크롤을 모두 금지한다. 드래그·팬·자동 이동으로 항목을 드러내지 않는다. 목록의 다음/이전 내용은 원본 좌우 버튼으로 전환한다. 아이템 드래그/드롭은 보존한다. iPhone은 원본 Phone 버튼·정보창 배치와 자원을 사용하고, iPad는 기존 배치를 유지한다.

검사는 실제 버튼 입력으로 전체 HD 상품24개와 인벤토리25칸에 접근하는지, 양방향 드래그 후 장면·페이지·스크롤 값이 유지되는지 확인한다. 표시와 터치 경계·구매/판매·임무 상세도 검사한다.

## 2026-11-15 최신 하네스 범위

사용자 수정에 따라 두 독립 하네스로 한정한다. 에셋 검사는 허브·상점·사령부 배경의 iPhone 일반판/iPad HD판 원본 일치만 확인한다. 화면 검사는 같은 영역의 실제 시뮬레이터 캡처에서 검은 땜질·끝 픽셀 늘림만 확인한다. 각자의 모든 적용 항목을 충족해야 PASS다. 서로의 결과를 실행 조건으로 삼지 않는다. 파일·도구·Git·복구·스태시·하네스 제거를 차단하지 않는다. 옛 전역 차단/커밋 gate 설계는 폐기된 기록이다. [구현·검사 결과](two-menu-harness-scope-20261115.md)를 따른다. 다른 게임 요구와 메뉴 배치 미해결 항목은 유지한다.

- **A01:** 경로 이름뿐 아니라 실제 파일 바이트·SHA-256·판본·출처 명세를 확인한다. HD 그림을 `PhoneMenu/`로 이름만 바꿔 통과시키지 않는다.
- **A02:** 기지별 원본 테이블의 실제 참조를 전수로 읽는다. 기지 번호로 파일명을 추측하지 않는다. 현재 Phone Base002/005 시설 그림의 교차 참조도 보존한다. 선택→공통 reader→원본 형식 해석→텍스처 준비→실제 Frame→실제 패키지까지 같은 자원인지 확인한다. 승인 파일이 저장소에 있다는 사실만으로 합격하지 않는다.
- **A03:** 배경 선택은 공통 표시 정책에서 결정한다. Apple/Android 호스트마다 게임 UI와 그림 선택을 따로 구현하지 않는다. 기기 종류 전달은 호스트의 메타데이터 역할로 제한한다.
- **A04:** 작은 iPad 창이 Phone 그림으로 바뀌지 않아야 한다. 기기 종류와 창 크기·방향을 분리해 검사한다. 모르는 기기 종류를 조용히 Phone/HD로 대체하지 않는다.
- **A05:** 같은 그림·버튼 위치·터치 역변환·원작 ID/콜백이 함께 대응해야 한다. iPhone 비전투 버튼 배치는 원본 Phone판을 참고하고 상품 이미지는 HD판을 사용한다. 배치 기준을 에셋/게임 데이터 판본 선택과 혼동하지 않는다. HD 24상품/25인벤 등 게임 수량을 일반판의 그림 칸수로 줄이지 않는다. 실제 상품 텍스처의 출처/해시까지 검사한다.
- **A06:** 원본 소스를 확보했다고 표현하지 않는다. 현재 게임은 원본 IPA의 실행 코드·데이터·포팅판 관측에서 확인한 동작을 새 공통 소스로 복원하는 작업이다.

## 3. HUD와 원작 UI

- **H01:** 클래식 HUD를 남긴다. 스테이지 메뉴의 HUD 설정에서 클래식과 Experimental을 선택하도록 한다. 두 기기 모두 같은 공통 구현을 사용한다. 현재 Experimental 구현은 롤백했으므로 미완료다.
- **H02:** Experimental은 필요한 정보와 기능 UI를 유지하고 큰 배경판·불필요한 장식만 제거한다. 숨김·접기를 추가해 대신하지 않는다. 레이더 열기/닫기는 만들지 않고 상시 표시한다.
- **H03:** HP, BOOSTER/SP, EXP, 레벨, 보유금은 각각 독립 조각이다. 왼쪽 무기, 오른쪽 무기, 퀵5슬롯, MENU/MISSION/ITEM 3버튼, 레이더, 원래 대상 정보까지 총 11조각으로 계획한다. 레벨/EXP/Cr을 다른 화면으로 옮기지 않는다.
- **H04:** 좌우 무기 버튼을 누를 때 나오는 원래 무기 선택 패널 2개를 유지한다. 각 버튼의 이동을 따르며 두 패널의 상대 위치도 각각 이동·저장할 수 있어야 한다. 보유 목록·인벤 위치·ItemCode·장착 조건을 유지한다. 화면 밖 패널과 세로 스크롤로 처리하지 않는다.
- **H05:** 조각을 실제 기능 단위로 분리한다. HP/SP/EXP를 큰 한 덩어리로 남겨 놓고 세분화했다고 보고하지 않는다. 원본 한 장 안의 표식·기능 바탕과 별도 게이지/숫자를 연결한다. 원본 파일을 잘라 다시 만들었다고 혼동하지 않는다.
- **H06:** 게이지 값·색·숫자·레이더 마커가 실제 상태를 계속 반영해야 한다. 그림만 보이고 값/마커가 멈추면 실패다. 원래 마커 좌표·대상 정보 출현 조건·무기 사거리 표시를 유지한다.
- **H07:** 이동·저장은 iPhone/iPad에서 모두 지원해야 한다. HUD는 안전영역을 강제 한계로 삼지 않고 화면 끝과 맨 아래까지 배치할 수 있어야 한다. 표시·입력은 같은 변환을 쓴다. 적용·취소·기본 배치와 기존 저장 읽기를 검증한다.
- **H08:** 원작에 있던 이동 목표/경로 마크, 적 이름·HP, 메크/적 그림자, 레벨업·과제 달성 알림/음향, 지역명·포털, 기지 복귀 문 애니메이션과 BOT 표시 등을 임의 생략하지 않는다. 사용자가 발견한 E-10 달성 알림과 수집 퀘스트 보상 등은 미해결 TODO를 유지한다.
- **H09:** 앱 아이콘은 탭 투 스타트 화면의 원작 일러스트를 사용한다. 정식/치트 앱 아이콘을 준비한다. 새로 그린 그림을 임의 채택하지 않는다. 구체적인 파생 크기·압축은 기존 아이콘 준비 절차로 기록한다.
- **H10:** 기본 한국어를 유지한다. 원작 버튼 이름·음향·연출과 맞는 톤을 사용한다. 내부 ID·개발 과정·검수 상태를 플레이어 UI의 안내 문구로 대신하지 않는다.
- **H11:** 여러 이동 경로를 찍고 새 경로를 다시 입력한 뒤 더블탭 점프/전방 급속 이동이 묵살되는 사용자 관측을 검사한다. 원작의 유효 입력 시간·거리·상태를 기준으로 판정한다. 후속 정정을 무시하고 사용자의 다른 손 터치 때문이라고 확정하지 않는다. HUD 버튼·편집 드래그와 월드 이동의 터치 소유권도 구분한다.

## 4. 원작 아트·에셋 처리 절차

- **P01 원본 보존:** IPA·원본 실행파일·사용자 저장은 보존한다. IPA는 private Git을 포함해 Git/LFS/릴리스/CI 산출물/보고 사이트/클라우드로 보내지 않는다. 변경 이름·압축·분할로 우회하지 않는다. HM2 파일은 HM2 전용 공간에 둔다.
- **P02 형태와 원고:** 신규 아트도 원작 일러스트·원작 유닛과 실제 게임 크기를 대조한다. 채택 레퍼런스·시안·파츠/프레임 분리·채택본·변환 설정·해시를 연결한다. tone·형태·색·명암·도트의 불일치를 단순 고해상도라는 이유로 허용하지 않는다.
- **P03 형식:** 확장자와 실제 인코딩을 일치시킨다. CgBI/일반 PNG/JPEG, 채널·알파·POT/UV·Retina wrapper·프레임/타일 규칙을 역할별 원본과 대조한다. 모든 파일을 근거 없이 한 형식으로 바꾸거나 JSON을 원작 확장자로 이름만 바꾸지 않는다.
- **P04 데이터·조립:** 원작 레코드·ID·참조·파츠 트리·기준점·소켓·레이어·회전·애니메이션·무장 연결을 유지한다. 원본/신규 유닛 모두 exporter/공통 reader→조립→애니메이션/무장→렌더/충돌/공격의 같은 경로를 사용한다. 유닛별 C++ 임의 정의·전용 renderer·런타임 잘라 붙이기로 우회하지 않는다.
- **P05 확인하지 못한 것:** 원작 제작 도구를 확보했다고 주장하지 않는다. 파일/실행으로 확인한 계약을 복원한다. 미해석 데이터나 필요한 확장은 명시하며 조용한 임시 이미지·기본 유닛 fallback으로 누락을 숨기지 않는다.
- **P06 로드·재사용·해제:** 원작의 자원 로딩·준비·공유 캐시·재사용·수명·해제 경로를 조사하고 따른다. 예열 뒤 화면 그리기/드래그/사격마다 자원을 다시 읽거나 디코드·업로드·문자 준비하지 않는지 계측한다. 정상 화면 진입의 준비와 매 프레임 재생성을 구분한다.
- **P07 공통 스택:** C++20 공통 코어·기존 GPU 스프라이트·OpenAL 효과음·기존 플랫폼 어댑터를 유지한다. UIKit/CoreGraphics로 인게임 그림·버튼을 별도 구현하지 않는다. Python은 기존 오프라인 준비/검사 도구 역할로 제한한다. 새 게임 엔진·Ruby/Three.js 등 임의 런타임을 넣지 않는다.
- **P08 음향·저장:** 사격마다 DB/파일 쓰기, 효과음 context/source의 반복 생성/해제, 임의 Apple 효과음 프레임워크 대체를 금지한다. 원래 BGM/효과음 경로와 캐시·동시 재생을 구분한다. 백그라운드·전화·복귀의 일시정지/메뉴/음향 수명을 검사한다.
- **P09 패키지:** 소스 명세와 실제 앱/웹 등 패키지의 파일·참조·해시를 연결한다. renderer가 실제 사용하는 자원까지 대조한다. 누락/중복 ID/잘못된 참조는 실패다. 이번 우선 범위는 iPhone·iPad이며 다른 플랫폼 완료로 확대하지 않는다.
- **P10 권리와 광고:** 원작 그림·음원·맵/게임 데이터의 권리를 신규 소스의 MIT 허용과 섞지 않는다. 음원 구매/제작 출처·라이선스는 별도 조사 TODO이며 미확인을 확인 완료라고 쓰지 않는다. 세 작품에 광고를 표시하거나 요청하지 않는다.

세부 형식·기술 근거는 [기술스택과 에셋 절차](technology-and-assets.md), [실행 계약](runtime-contract.md), [원작 표시 측정](hd-landscape-plan.md)에서 읽는다. 이 문서는 원본의 미확정 필드를 새로 확정하지 않는다.

## 5. 검사·결과·보존

- **V01:** 정식/치트는 같은 공통 게임·UI·자원 로직을 사용한다. 치트는 경험치·레벨·아이템·진척도 제한을 건너뛰어 독립 조건들을 같은 시간에 검사한다. 버튼 하나씩 수동 확인한 것을 전체 동시 검사로 보고하지 않는다.
- **V02:** 모든 기능·UI·로직과 동시 치트 구성을 먼저 만든다. 구현 중에는 정적·공통 CPU·컴파일 검사로 진행하고, 기능별로 원작 한 장면을 보고 구현/빌드를 반복하지 않는다. 최종 묶음에서 원작 포팅판·정식·치트를 일괄 대조한다. 실패를 고친 뒤 관련 재검사는 허용하되 이전 실패는 보존한다.
- **V03:** 일반판 포팅판은 iPhone 기준, HD 포팅판은 iPad 기준으로 비교한다. HD를 iPhone에 띄워 버튼이 없다고 판단하지 않는다. 포팅판의 실제 게임을 재구현한 결과를 원본 실행으로 바꾸어 부르지 않는다.
- **V04:** 처음 목표는 iPhone 가로·iPad 세로다. 이후 양쪽 방향을 확장한다. 장치 접근/설치는 현재 사용자 범위를 따른다. 가로 왼쪽·추가 방향이 미검사면 그대로 기록한다.
- **V05:** 커밋 대상/차단 판정 전에 같은 후보의 치트빌드를 시뮬레이터에서 실행하고 실제 화면을 직접 본다. 작업 전에 고정한 사용자 요구사항 원문과 결과물을 항목별로 대조한다. 일치율 90% 미만은 탈락이며 에셋 선택/소비부터 코드 누락까지 원인을 추적한다. CPU/자동 검사 통과와 실제 화면의 요구 충족을 따로 판정한다. 실제 원본 PNG·실제 버튼 위치·자원 출처가 없으면 시각 합격으로 쓰지 않는다. 검은 패널·깨진 그림을 보고도 숫자상 PASS를 완료 근거로 사용하지 않는다. 90% 이상이어도 금지사항/필수 기능 위반은 탈락이다.
- **V06:** 실제 캡처는 원래 크기·비율·바이트를 보존한다. 보고를 위한 자르기·늘림·재생성·수정으로 실패를 감추지 않는다. 반응형 축소 표시와 원본 전체 크기 링크는 제공할 수 있다. 제어한 시험 UI 문구/상태와 실제 원작 플레이를 구분한다.
- **V07:** 메모리·프레임·발열은 치트/시뮬레이터·Instruments와 실제 기기 정식 Release를 구분해 계측한다. 누수 표가 없는 trace나 한 번의 누수 0으로 전체 수명/실기기 발열 해결을 주장하지 않는다.
- **V08:** 검사 생략·증거 누락·오래된 결과·하네스 오류를 통과로 바꾸지 않는다. 실패 원인과 다음 수정은 남기고, 미통과 기능의 완료 보고·정식 설치·배포를 막는다. 하네스 실패를 문제 수정 자체를 거부하는 명분으로 쓰지 않는다.
- **V09:** 사용자 원본·저장·원고·실패 근거를 보존한다. 롤백은 발생 시간과 의존 관계를 먼저 분석하고 선택 범위/파일을 확인한다. 기존 공유 커밋을 지우는 reset/force-push를 하지 않는다. 작업 브랜치→develop→main을 지킨다.
- **V10:** 새 검증 후보의 실행을 확인하면 재사용하지 않을 이전 빌드/캐시를 정리한다. 최신 정식·치트·원본 비교 후보와 필요한 증거는 유지한다. 소스·원본 IPA·저장을 캐시라고 지우지 않는다.
- **V11:** 보고서는 기존 비공개 HTML 보고 사이트와 HeavyMach2 누적 목록에 연결한다. 로컬 Markdown만 던지고 게시 완료로 보고하지 않는다. 계획·파일 변경·실행·시각 합격·커밋·설치·게시를 구분한다.

### 실물 대조·일치율 — 2026-11-15 사용자 추가

사용자 원문:

적용 순서는 작업 전 원문/검사 항목 고정 → 공통 구현/동시 치트 구성 → 시뮬레이터 실행 → 실제 화면·입력/상태와 원문 대조 → 불일치 원인 조사/수정/관련 재검사 → 커밋 대상 일치 확인/차단 판정이다. 캡처 존재·컴파일·로그만으로 실물을 보았다고 처리하지 않는다. 여기서 실물은 해당 후보의 실제 실행 화면이며 실기기 접근/설치를 새로 허용하는 지시로 확대하지 않는다.

일치율은 검사 전에 고정한 적용 요구 항목의 충족 비율로 계산한다. 원문 한 항목을 다수의 쉬운 검사로 쪼개 점수를 높이지 않는다. 미확인·일부 충족·검사 누락은 충족 수에 넣지 않는다. 비적용 항목은 사전 근거를 남기고 실패 후 임의로 빼지 않는다. 요구 원문·조건·실제 화면/동작 근거·판정·원인을 연결한다. 기기/기지/화면별 차이를 전체 평균으로 감추지 않는다. **90% 미만은 원인 재분석을 시작하는 탈락선이며, 90% 이상이라는 이유로 남은 필수 요구나 금지사항 위반을 허용하지 않는다.**
