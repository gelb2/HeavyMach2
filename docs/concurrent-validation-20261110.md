# 동시 치트 검증 구현과 남은 작업

2026-11-10. 일반 앱의 메뉴·버튼 개별 검사는 전체 동시 치트 검증이 아니었다. 사용자 지적 뒤 별도 자동 실행기를 구현했다. 이 문서는 실행 결과와 아직 끝나지 않은 범위를 구분한다.

## 같은 프레임에서 실행하는 조건

`Core/Validation/ConcurrentValidation`은 독립된 원본 형식 저장·게임 상태·난수를 가진 59개 Session을 같은 프레임 번호로 갱신한다. 55개는 실제 Player 장착용 무기 110개를 두 개씩 장착한 전투다. 나머지는 거래·임무·저장 재시작·이동 및 획득이다. 원작에서 서로 배타적인 화면을 한 Session에 동시에 열지 않는다. 메뉴를 조작하는 동안 다른 전투는 계속 진행한다.

원본 ItemInfo의 장비를 시작 저장에 준비한다. 피해·격파·드롭·획득·경험치·레벨업·임무 결과를 강제하지 않는다. 원본에 없는 Player 장비를 만들어 적 전용 WeaponInfo를 발사한 것으로 보고하지 않는다. 110개 장비가 사용하는 실제 WeaponKind는 5개다. 무기 소비 모듈이 지원하는 9종과 이 Player 장비 목록의 5종을 구분한다.

Apple 연결은 CADisplayLink 하나에서 모든 Session을 갱신하고, 모든 월드와 GPU 메뉴를 같은 화면의 독립 영역에 그린다. GLES 출력기와 OpenAL 컨텍스트는 각각 하나다. 서로 다른 효과음은 함께 재생하며, 같은 WAV의 source를 재시작하는 원본 동작을 유지한다. AL_PLAYING과 샘플 위치 증가를 다음 프레임 시작에서 관측한다. play 호출 횟수만으로 동시 출력 성공을 판단하지 않는다.

## 실행한 결과

C++ normal 및 전체 코어 ASan/UBSan에서 59개 상태를 각각 1,200프레임 실행했다. 실제 Player 장비 110개가 발사됐고 같은 프레임에서 최대 22개 장비·18개 전투가 발사했다. 실제 5종 WeaponKind가 같은 프레임에 발사한 구간도 있었다. 메뉴 조작 9프레임 모두 다른 전투의 발사·탄환·피해 활동과 겹쳤다. 레벨0→1, 거래 성공과 잔액 부족 거부, 임무 조건 충족, 원본 저장 해석 후 재시작을 확인했다. 임무 조건 충족을 보상 수령 완료로 확대하지 않는다.

새 이동 조건은 실제 월드 터치를 40회 전달했다. 이동 거리 1,363.08, 최대 시작점 변위 702.105를 관측했다. 원본 드롭의 실제 위치까지 이동해 코인 3건과 아이템 2건을 주웠다. Cr은 500→509, 재고는 2개 늘었다. 이동·자기 발사·다른 전투의 활동은 43프레임 겹쳤고, 실제 획득과 다른 전투는 4프레임 겹쳤다. 이 조건의 실제 피격은 관측되지 않았다. 기존 0~57 조건의 관측 결과는 추가 전과 같았다.

Apple의 첫 전체 58조건 검사는 1,200프레임 동안 효과음 22개가 함께 재생되며 샘플이 진행됐다. 다만 메뉴 진입 중 자원 3개를 추가로 읽어 실패했다. `SelMission.png`, `MissionInfo.png`, `Common_Btn_ACCEPT.png`를 실제 임무 메뉴 준비 경로에 추가했다. 수정 후 210프레임에서 추가 파일 read/exists와 PNG 업로드 0, 효과음 최대 23개 진행을 확인했다. 이 짧은 실행을 전체 1,200프레임 통과로 쓰지 않는다.

최종 채택 경로에서는 C++ 검사46개가 모두 통과했다. Apple iPhone·iPad에서 각각59조건·1,200프레임 전체 검사도 통과했다. 두 기기 모두 실제 효과음23개가 같은 관측 구간에서 재생되며 샘플이 진행됐다. OpenAL 컨텍스트는1개였고, 준비 뒤 context/source/buffer·효과음 파일 읽기·디코드 증가는0이었다. 추가 자원 read/exists와 PNG 업로드도0이었다.

실제 이동 조건은 양쪽 모두 Cr500→509, 코인3건·아이템2건·재고+2를 확인했다. 실제 잔액 증가를 제거된 코인의 합계와 별도로 비교했다. 같은 캐시 프레임의 기존 GLES/scissor 출력을 다시 그려 iPad3,870,400픽셀·iPhone3,447,360픽셀의 RGB 차이0을 확인했다. 이것은 출력 재현 검사이며 원작 포팅판과의 동등성 검사는 아니다.

300프레임에서 실제 상점 닫기 버튼을 누른 채 중단·복귀시켰다. 캡처와 눌림이 해제됐고, 정리 과정의 게임 action·추가 tick·저장·잔액·화면 변경은 없었다. CPU+GPU제출 시간의 p95는 iPad50.10ms·iPhone43.21ms였다. 한 Mac에서 두 시뮬레이터를 함께 실행한 수치이며 실기기 성능 또는60fps 합격을 뜻하지 않는다.

## 발견한 출력 차이

모든 검증 화면을 계속 그리는 비용을 줄이기 위해 독립 영역 사이의 공통 텍스처 그리기를 묶는 구현을 추가했다. C++ 순서·합성 검사와 독립 검토는 통과했지만 실제 GPU 비교는 실패했다. 같은 프레임의 기존 scissor 출력과 새 출력에서 RGB 차이 1을 넘는 픽셀이 1,141개였다. 원래 삼각형과 scissor를 보존하는 수정 뒤 짧은 검사는 통과했지만, 전체 실행에서 iPad1픽셀·iPhone40픽셀이 같은 기준을 넘었다. 경계 여유2픽셀을 추가해도 실패 수가 같았다. 이 선택적 최적화는 채택하지 않았다. 실험 소스·실패 로그·전체 캡처를 로컬에 보존하고 기존의 순서대로 그리는 GLES/scissor 경로를 사용한다. 게임 상태·화면·검사 수는 줄이지 않았다. 남은 픽셀 차이의 원인은 확정하지 않았다.

## 남은 검증과 다음 소비자

- 위 두 기기의 검증은 HD canvas를 각 검증 영역에 표시한 결과다. iPhone 최종 가로 HUD·표시 비례 및 원작 포팅판 동등성 검증은 남는다.
- Source의 실제 게임 시작점 연결. Validation은 별도 앱을 iPad시뮬레이터에 설치해1,200프레임 종료와 결과 파일59조건·warm0을 확인했다. 실행마다 UUID폴더를 쓰고 정해진 프레임 뒤 멈춘다.
- 퀵 아이템 실제 사용, 특수 공격, 대시, bot의 실제 행동·공격·획득, 다른 하체.
- 포탑·항공기 소비자의 CombatScene 통합과 전체 43맵·695스포너.
- 모든 60개 임무 유형·보상, 도움말·게임오버·캠페인 진행, 모든 버튼의 실제 효과.
- 포팅판과 같은 조건의 표시·입력·공격·음향 대조, 기기별 최종 크기·HUD·시야.
- OS 중단·출력 장치 변경·전역 초기 RNG 및 layer/atlas 합성 순서.

전체 기능 치트 앱과 정상 게임 복원은 아직 완료하지 않았다. 실기기 설치와 develop/main 병합도 하지 않았다.
