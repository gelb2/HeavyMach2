# HD 가로 화면 지원 계획

2026-11-09 사용자 지시에 따라 기록한다. 계획이며 아직 구현하지 않았다.

## 현재 근거

확보한 HD 1.0.0과 1.0.3의 게임 화면 회전 함수는 세로 두 방향만 허용한다. 1.0.0의 plist에는 가로도 등록돼 있으나, 두 판본의 포팅판에 가로 시작 옵션을 주어도 세로로 전환됐다. 원본 분석과 시뮬레이터 관측의 세부 범위는 [TODO](todo.md)에 있다. 출시 당시 모든 판본의 동작을 확인한 것은 아니다.

## 보존 조건

- 원본 IPA와 원본 비교용 포팅판의 게임 코드·데이터는 유지한다. 가로 시험판에는 별도 bundle ID와 저장 공간을 사용한다.
- HD 에셋의 해상도, 파츠 조립, 유닛·오브젝트 비례를 유지한다. 가로·세로를 다르게 늘이지 않는다.
- 화면 방향만 바꾸기 위해 원작의 사운드 재생·저장·전투 갱신 절차를 바꾸지 않는다.
- 원작 비교용 호환 실행기와 최종 C++ 공통 코어 복원판의 변경을 구분한다. 호환 실행기 시험 성공만으로 독립 복원을 완료했다고 하지 않는다.

## 구현 순서

선행 조건: [포팅판 메크·적·HUD 측정](reference-display-measurement-plan.md)으로 일반판 iPhone과 HD iPad의 주인공·적 종류별 크기, HUD 전체·요소별 크기를 따로 확보한다. 측정값과 미확인 범위를 기록한 뒤 복원판의 표시 배율·HUD 배치 기준을 확정한다.

1. **가로 출력·입력 확인:** 별도 시험판에서 가로 화면 안에 원작 768×1024 세로 구성을 같은 비율로 표시한다. 좌우 여백을 두고 회전·터치 변환·메뉴 입력을 확인한다. 이 단계는 가로 전체 화면 구성의 완료가 아니다.
2. **게임 영역 확장:** 원작 카메라 좌표·투영·배경 타일 표시 범위를 분석한 뒤 가로 출력 비율에 맞춘다. 화면에 보이는 영역과 적의 생성·활성화·전투 판정 영역을 구분한다. 시야가 넓어져 사거리·스폰·전투 진행이 의도 없이 바뀌지 않는지 검사한다.
3. **UI 배치:** HUD, 슬롯, 기지, 상점·장비·임무 메뉴, 이름 입력창과 키보드를 가로 화면에 배치한다. 화면 크기·안전 영역·터치 좌표를 같은 변환 기준으로 처리한다.
4. **회전과 수명:** 좌우 가로 전환, 세로 복귀, 앱 전환·복귀, iPad 창 크기 변화를 확인한다. 회전 중 저장·장비·임무 상태를 유지한다.
5. **원작 대조:** 같은 저장과 장면에서 원작 세로 기준과 가로 후보의 유닛 비례·파츠 위치·공격·피격·이동·임무·저장 복구·사운드 순서를 대조한다. 화면 밖 적의 활성화 범위도 검사한다.
6. **유니버설 앱 반영:** 검증된 공통 코어와 HD 표시 구성을 iPhone/iPad에 연결한다. 일반판 가로 기준도 별도로 유지해 비교한다. 어느 판본의 콘텐츠를 최종 기준으로 삼을지는 [IPA 전 버전 조사](ipa-version-audit.md)를 참고해 결정한다.

## 완료 기준

아이폰·아이패드 시뮬레이터에서 가로 화면 전체를 사용하며, 이미지 비례와 버튼 입력이 맞고, 메뉴·실제 플레이·진행·저장·음향 검사가 통과해야 한다. 사용자 지시에 따라 포팅판의 시뮬레이터 정상동작 확인 전에는 실기기에 빌드·설치하지 않는다. 이후 실기기 성능과 터치를 확인한다.

## iPad 확대 방지와 HUD 배치 — 2026-11-10 사용자 요구

사용자는 MachDefense 복원판에서 iPhone의 메크·전체 화면·HUD를 iPad에서 일괄 확대한 듯한 모습을 관측했다. 이 문서는 그 관측을 HM2의 예방 요구로 반영한다. MachDefense의 현재 구현 원인을 조사·확정한 기록은 아니다.

### 구현 조건

- 화면 전체를 하나의 비율로 확대해 채우는 구성을 최종 iPad 구성으로 사용하지 않는다. 앞 단계의 원작 세로 화면 맞춤 표시는 입력 검사용 임시 구성이다.
- 월드 좌표, 화면의 논리 크기, 출력 픽셀과 이미지 해상도를 분리한다. 고해상도 에셋은 선명도를 위해 사용하며 텍스처 픽셀 수로 메크 표시 크기를 결정하지 않는다. 일반판·HD판 각각의 원작 메크·지형·부품 비례를 측정해 표시 기준과 허용 범위를 먼저 기록한다.
- 더 넓은 유효 화면에서는 해당 표시 기준을 유지하며 카메라가 보여주는 월드 범위를 늘린다. 화면비가 다른 기기 사이에서 가로·세로 두 축이 모두 늘어난다고 가정하지 않는다. 실제 보이는 월드의 폭·높이·면적으로 비교한다. 같은 원칙으로 작은 iPad 창에서는 표시 범위를 줄이고 UI를 재배치한다.
- HUD는 월드 확대·축소와 별개로 배치한다. 우선 하단 중앙에 고정하며 글자와 터치 영역의 적정 크기 및 HUD 최대 폭을 정한다. 화면이 커졌다는 이유로 버튼·글자·패널을 비례 확대하지 않는다. 터치 영역과 그림 크기를 분리하고 안전 영역, 전장 조작과의 겹침, 가림 면적을 확인한다. 요소별 자유 이동 설정은 후속으로 둔다.
- 상점·장비·임무 목록은 여유 공간에 항목이나 상세 정보를 더 배치한다. 원작에서 없는 정보를 만들어 채우지 않는다. 작은 창에서는 읽기·조작 가능한 크기를 지키며 열 수와 배치를 조절한다.
- 더 넓은 시야가 적 생성·AI 활성화·공격 거리·임무 트리거를 바꾸지 않도록 표시 범위와 게임 규칙을 분리한다. 원작에서 화면 범위와 연결된 규칙을 발견하면 원작 동작과 복원 변경을 기록하고 검사한다.

### 비교와 합격 기준

같은 맵·저장·메크·장비·카메라 중심을 사용해 iPhone 가로, iPad 가로 전체 화면, 크기가 다른 iPad 창을 비교한다. 원작 일반판과 HD판은 각각의 기준 장면으로 따로 대조한다.

| 항목 | 기록·합격 조건 |
|---|---|
| 메크·오브젝트 | 출력 픽셀 및 논리 표시 크기, 화면 점유율, 부품 상대 위치 기록. 사전에 정한 기기별 원작 표시 기준 범위 안이며 화면 크기에 비례하는 일괄 확대가 없음 |
| 전장 | 카메라 월드 폭·높이·면적 기록. 더 넓은 유효 화면에서 더 많은 전장이 보임. 추가 적을 생성해서 콘텐츠 증가를 대신하지 않음 |
| HUD | 논리 크기·터치 영역·최대 폭·화면 가림 면적 기록. 하단 중앙 정렬, 안전 영역 안 배치, 버튼·글자 잘림과 전장 입력 충돌 없음 |
| 메뉴 | 같은 장비·임무 목록의 표시 항목 수와 상세 영역 비교. 큰 창에서 여유 공간을 사용하고, 작은 창에서도 읽기·입력 가능 |
| 전투·진행 | 공통 월드 좌표에서 같은 입력을 적용해 이동·공격·피격·적 활성화·임무 진행 대조. 화면 크기 변경만으로 게임 규칙이 변하지 않음 |

원본 캡처 크기와 측정값을 보존한 비교 페이지를 만든다. 페이지에서 두 캡처를 같은 폭으로 축소해 보여준 그림만으로 크기 검사를 통과시키지 않는다. 물리적인 크기·시인성·조작감은 시뮬레이터 검증 후 실기기에서 확인한다. 현재 이 항목은 요구·계획이며 측정값과 구현 결과는 아직 없다.

Apple의 [게임 인터페이스 설계 안내](https://developer.apple.com/videos/play/meet-with-apple/243/)도 기기 간 단순 비례 조정보다 화면에 맞춘 배치를 설명한다. 모든 콘텐츠 확대가 일률적으로 금지된 심사 조항으로 단정하지 않는다. 위 조건은 사용자가 정한 HM2 제품 요구로 적용한다.
