# iPhone 공통 화면 구현과 최종 검사 — 2026-11-13

보고서는 [HeavyMach2 누적 보고 목록](https://heavymach-dev-report-20261025.hiphopxy.chatgpt.site/heavymach2-restoration-20261110/)에서 계속 연결한다. 이 문서는 `feat/iphone-universal-20261113`의 iPhone 가로·iPad 세로 공통 구현을 다룬다.

## 사용자 지시와 작업 경계

사용자가 iPhone을 사용 중이므로 실기기를 연결·설치·실행하지 않는다. 전체 구현과 동시 치트 연결을 먼저 마친 뒤 시뮬레이터 검사를 마지막 한 묶음으로 실행한다. 구현 중에는 앱이나 포팅판을 기능마다 번갈아 실행하지 않는다. C++ 검사와 Apple 컴파일은 구현 중에 수행한다. 실패한 최종 검사를 자동 반복하지 않는다.

이 작업은 HeavyMach2 저장소에서만 진행한다. HeavyMach1·MachDefense·사용자가 편집한 개발자의 변·원본 IPA·기존 사용자 저장은 수정하지 않는다. develop/main 병합과 실기기 설치는 이번 요청 범위가 아니다.

## 공통 구현

| 영역 | 반영한 동작 |
|---|---|
| 자원·게임 코어 | HD 그림·음원·데이터 한 벌과 같은 C++20 reader·파츠 조립·게임 로직을 사용한다. iPhone 전용 에셋이나 게임 소스는 추가하지 않았다. |
| 월드 | HD 논리 단위를 유지하고 출력할 때 배율과 안전 영역 원점을 적용한다. 입력은 같은 변환을 역으로 거쳐 기존 HD 선택·이동·공격 소비자로 들어간다. |
| 표시 크기 | 작은 창의 월드 기본 배율은 HD 단위 변환에 맞춰0.5, 큰 창은1이다. 큰 창의 폭·높이를 통째로 곱해 유닛을 확대하지 않는다. 더 넓은 유효 화면은 더 넓은 카메라 범위가 된다. |
| 가변 줌 | 작은 창에서 원본 일반판의 표적/마지막 경로 기반 줌을 공통 표시 정책으로 연결했다. HD 단위의 표적 차이x/360·y/240 중 큰 값을 사용하고 목표를1..1.6으로 제한해 차이/100만큼 접근한다. HD 카메라 중심 제한과 게임 시간·RNG는 유지한다. 일반판 카메라 전체를 그대로 이식했다고 주장하지 않는다. |
| HUD | 하단·상단·중앙 알림·모달 패널·타이틀·슬롯 카드를 각각 배치한다. 원작 부모 위치 더하기와 파츠 조립을 먼저 수행하고 최종 출력에 변환을 적용한다. 매 tick 갱신도 같은 배치를 사용한다. |
| 상점·인벤토리 | 작은 가로 화면에서 기존 두 패널을 나란히 배치하고 넘치는 폭은 같은 GPU 영역에서 스크롤한다. HD25칸 인벤토리·24상품/페이지·6행 에어리프트·5퀵슬롯을 유지한다. 그림·버튼·장비/BOT/퀵슬롯 드롭 원점을 함께 변환한다. |
| 긴 목록 | 최대 임무 목록과 무기 선택 목록은 읽을 크기를 유지하면서 GPU 영역에서 스크롤한다. 목록의 표시 clip과 버튼 입력 경계가 같고 하단 고정 버튼 영역을 남긴다. 저장 인덱스와 원작 버튼 ID는 바꾸지 않는다. |
| 도움말·전환 | 한국어 도움말 원본3장을 유지하고 가로 화면에서는 세로 스크롤한다. 드래그는 페이지 이동/닫기 탭으로 처리하지 않는다. 문·맵 로딩은 기존 상태·효과음·저장 순서를 유지한 채 실제 출력 창을 덮는다. |
| Apple 호스트 | 실제 창 크기와 안전 영역 변경을 공통 코드에 전달한다. 정식판과 동시 치트의 각 독립 Session/Screens에 같은 설정을 적용한다. 게임 버튼을 UIKit으로 만들지 않는다. |
| 입력 수명 | 화면 변경·앱 비활성화에서 버튼·월드·도움말의 소유 터치를 정리한다. 안전 영역 밖에서 끝난 터치는 취소한다. 스크롤을 시작한 포인터는 UI가 끝까지 소유한다. |
| 음향·저장 | 기존 단일 OpenAL 효과음 캐시와 저장 이벤트를 유지한다. 화면 배치나 사격 때문에 DB/파일을 쓰거나 오디오 컨텍스트를 새로 만들지 않는다. |

화면 범위를 사용하는 HD `isInScreen` 소비자는 새로운 카메라 범위를 읽는다. 이동·피해·생성의 원작 조건식을 기기별로 분기하지 않았다. 넓어진 시야에서 실제 전투의 시점과 대상이 달라질 수 있으므로 같은 화면 결과를 그대로 보장하지 않으며, 경계 조건과 원작 표시 동등성은 별도로 판정해야 한다.

## 구현 중 검사

- 전체 C++ 검사73개를 통과했다. 기존70개와 새 화면/입력·iPhone 동시 치트·iPad 동시 치트3개다.
- 마지막 입력 수명 수정 뒤 관련3개를 다시 통과했다.
- 작은 창667×375, 안전 영역이 있는852×393, 큰 창1024×1366에서 출력/역입력·HD 수량·드롭·목록 접근·도움말 스크롤을 검사했다.
- 두 표시 구성의 치트는 각각115조건을1,200프레임 동안 함께 갱신했다. 무기110종·5계열 발사, 버튼 실패0, 준비 후 원본 자원 읽기/존재 확인 누락0을 확인했다. CPU 글자 검사는 실제 Apple 글꼴 대신 검사 대역을 쓰며 GPU·기기 가독성 완료를 뜻하지 않는다.
- 정식판 Apple build-for-testing과 별도 Validation 앱 컴파일이 성공했다. 컴파일만으로 실행을 통과했다고 판정하지 않는다.

초기 치트 검사에서는 넓어진 시야의 사거리 밖 적 선택과 고정 대시 좌표 때문에 실패했다. 원작 무기 수치를 바꾸지 않고 치트의 대상/목적지 선택을 현재 카메라·실제 사거리와 연결했다. 실패 로그도 로컬에 보존했다.

## 독립 검토에서 수정한 문제

1. 같은 기지 설명창을 재사용할 때 전용 배치 영역이 지워지던 문제.
2. 전장 터치가 하단 영역에서 끝나면 소유 포인터를 정리하지 못하던 문제.
3. 최대 임무/무기 목록이 화면 밖으로 잘려 접근할 수 없던 문제.
4. UI 스크롤과 월드가 같은 포인터의 시작/끝을 나눠 소유하던 문제.
5. 도움말 드래그 중 앱 비활성화 후 이전 터치가 남던 문제.
6. 자동 목록 이동과 실제 clip의 하단 경계가 다르던 문제.

최신 소스에 대한 독립 정적 검토에서 확정 P1/P2는 남지 않았다. 실제 기기별 비례·Native 입력·원작 픽셀 동등성은 정적 검토 결과에 포함하지 않는다.

### 실패 원인과 검사 코드 수정

1. **공통 상점 GPU 검사:** 최초 기지 도움말이 첫2002 탭을 소비했고 두 번째 탭은 기지 버튼 선택까지만 진행했다. 검사 화면은 base3인데 shop6을 기대한 상태로 후속 실패가 이어졌다. 도움말 종료를 검사 준비에 명시했다.
2. **공통 완료 임무 UI 검사:** 같은 최초 기지 도움말 종료가 빠졌다. 임무 결과창까지 도달하지 못해60초 대기가 실패했다. 도움말을 닫은 뒤 기지 버튼을 누르게 수정했다.
3. **iPhone 이동 UI 검사:** HD 단위100의 이동·적 회피 거리를 새 화면 point100으로 사용해 유효한 목적지 후보를 찾지 못했다. 공통 월드 표시 배율과 안전 영역·입력 하단을 사용하도록 수정했다. 임무 행128 이동도 화면 point와 HD 좌표를 구분했고, 잘린 행은 실제 드래그로 스크롤한 뒤 누른다.
4. **iPhone 동시 치트 검사:** 검사 창이 `UIScreen.bounds`의420×912 세로 크기를 사용했다. 정상 Source 앱은912×420 가로로 실행됐다. 세로 치트에서 Stage03_04 항공기의 발사240·피해1·격파0·제거0이 나왔다. 같은420×912 구성의 CPU 검사에서 이를 재현했고,912×420 가로 구성은 안전 영역 유무 모두 같은 세 전장의 발사·피해·격파·제거 기준을 통과했다. 검사 창을 실제 UIWindowScene에 연결하고 현재 iPhone 가로/iPad 세로 계약과 다르면 시작 단계에서 실패하게 수정했다. iPhone 세로 지원 시 이 조건은 다시 다룬다.

이 수정들은 검사 준비·좌표·창 구성과 DEBUG 관측 항목에 적용했다. 게임의 적 HP·사거리·피해·획득 수량이나 저장 규칙은 실패에 맞춰 바꾸지 않았다. 수정 뒤 전체 C++73개·실제 가로 크기912×420의 별도 CPU 두 구성과 Apple 검사 제품/별도 치트 앱 컴파일을 확인했으며, **시뮬레이터는 재실행하지 않았다. 수정된 Native 검사 전체 통과는 아직 확인하지 않았다.**

Xcode가 실패 뒤 자동으로 최대600초 진단 자료를 수집해 종료가 지연됐다. 각 검사 종료 후 해당 진단 자식 프로세스만 중단하고 테스트 로그·결과 묶음·첨부 자료는 보존했다. 후속 검사 도구에는1회 실행과 대형 자동 진단 수집 제외를 명시했다.

원작 포팅판과의 전체 픽셀/음향 동등성, 전 캠페인, 실기기 설치, develop/main 배포는 미확인/미실행이다.
