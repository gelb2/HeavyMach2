## 2026-11-13 후속 수정 — 전체 화면과 HUD

최신 사용자 지시에 따라 iPhone 검은 레터박스를 금지했다. 앞선 시뮬레이터 통과 기록은 실제 기기의 기지/사령부 세로 fit·설명 잘림·작은 HUD 결함을 놓쳤다. 아래는 그 후속 수정이며 앞 절의 결과를 덮어쓰지 않는다.

- 월드 출력/clip/입력 역변환은 화면 전체를 사용한다. 안전 영역은 HUD와 버튼 배치에만 사용한다. 공격·줌으로 출력 사각형이 변하지 않는다.
- 1024단위 유한 맵이 가로 화면보다 작아지는 경로에 최소 줌을 적용한다. 912×420에서 최저 줌은 약1.785, 월드 출력 배율은 약0.892다. 이는 현재 채택한 표시 정책이며 일반판 원작의 정확한 표시 비례를 검증했다는 뜻이 아니다. 공격·사거리·충돌 크기·이동 규칙은 공유한다.
- 원본에 선택적 배경이 있으면 같은 자원을 화면 전체에 표시한다. Player를 HUD 위에 유지하기 위한 카메라 여유는 기존 지형 가장자리 픽셀을 GL_CLAMP_TO_EDGE로 늘려 덮는다. 새 지형·충돌·그림 자원은 만들지 않았다. 이 가장자리 표시 확장은 원작과 구분한다.
- 작은 가로 화면의 HUD를0.5배에서 최대0.75배로 키웠다. HUD 그림·clip·버튼·무기 목록·퀵슬롯과 Player 보호 높이를 같은 변환으로 연결했다. 전투 줌으로 HUD 크기를 바꾸지 않는다.
- 기지 버튼을 왼쪽에 배치하고 설명 패널을 오른쪽에 분리했다. 배경은 전체 화면을 덮는다. 같은 원본 테이블·이미지·ID·콜백을 사용하며 iPad 기존 배치는 유지한다. 창 크기 변경 시 버튼 위치도 다시 계산한다.
- 사령부 목록은 실제 첫 행과 상세 높이에서 시작 위치/스크롤 범위를 계산한다. 상점·정비 화면은 같은 기지 배경을 함께 사용한다. 상품24개·인벤토리25칸·에어리프트6행을 줄이지 않았다.

공통 C++73개와 실제 iPhone Air 크기의912×420 구성 CPU 동시 검사를 통과했다. 115조건을 같은1,800프레임에 실행해110무기·5계열·동일 프레임5계열 발사, 버튼 실패0, 예열 후 자원 읽기/존재 확인 누락0을 확인했다. 기존 iPad 관찰 창은1,200프레임이다. 변경한 카메라에서는 Picker 회수에 더 오래 걸려1,200프레임 실패를 보존하고 작은 창의 관찰 시간을1,800으로 늘렸다. 기능 결과를 강제로 넣거나 성공 조건을 제거하지 않았다.

자동 입력은 실제 지형/적을 피하는 경로, 실제 소유02007 반복 사용, Picker의 미사일 발사 확인 후 반대편 무기 교환을 포함한다. 작은 창의 레일건 한 조건은120프레임에 실제 시스템 메뉴를 열고121프레임에 재개한다. 두 입력의 성공·pause 상태·그 사이 worldTime 정지를 검사한다. 다른114조건은 계속 동작한다. 이 입력에서5계열 발사가 같은 프레임에 겹쳤다. 모든 전투 입력이 OS 터치인 것은 아니며 일부 표적 선택은 공통 selectEnemy API를 사용한다.

GPU의912×420 출력 검사에서 기지 설명·사령부·상점·전투 전/표적 선택 후5캡처 모두 네 가장자리를 채웠다. 이 검사는 같은 작은 창 fixture를 양쪽 시뮬레이터에서 실행했다. 실제 iPad 세로 구성의115조건 결과와 구분한다. 실제 OS 터치 검사에서는 iPhone 게임오버 유도 중 움직이는 적 재선택 ID가 한 번 불일치했다. 이 실패와 나머지 검사 결과는 로컬에 보존하며 수정 후 검사 결과를 추가한다. 이후 아래에 최종 검사와 실기기 전달 결과를 추가했다.

후속 Native의 실제 Source 게임오버·기지 복귀·저장 재실행은 양쪽 모두 통과했다. iPhone은 같은 전장 안에서 표적 좌표를 다시 읽어 두 번째 실제 탭으로 요청 ID를 선택했다. 첫 탭 정확도 통과로 표현하지 않는다. 동시 검사에서는 iPad115조건이 통과했고 iPhone에서 게임오버 유도와 메뉴 집계가 실패했다. 첫 적만 공격한 뒤 생존한 자동 입력을 두 적에 대한 실제 공격으로 보강했으며, 기존11개 메뉴 입력과 새 전투 메뉴2개를 별도로 검사한다. ## 독립 검토에서 수정한 문제

1. 같은 기지 설명창을 재사용할 때 전용 배치 영역이 지워지던 문제.
2. 전장 터치가 하단 영역에서 끝나면 소유 포인터를 정리하지 못하던 문제.
3. 최대 임무/무기 목록이 화면 밖으로 잘려 접근할 수 없던 문제.
4. UI 스크롤과 월드가 같은 포인터의 시작/끝을 나눠 소유하던 문제.
5. 도움말 드래그 중 앱 비활성화 후 이전 터치가 남던 문제.
6. 자동 목록 이동과 실제 clip의 하단 경계가 다르던 문제.

### 실패 원인과 검사 코드 수정

1. **공통 상점 GPU 검사:** 최초 기지 도움말이 첫2002 탭을 소비했고 두 번째 탭은 기지 버튼 선택까지만 진행했다. 검사 화면은 base3인데 shop6을 기대한 상태로 후속 실패가 이어졌다. 도움말 종료를 검사 준비에 명시했다.
2. **공통 완료 임무 UI 검사:** 같은 최초 기지 도움말 종료가 빠졌다. 임무 결과창까지 도달하지 못해60초 대기가 실패했다. 도움말을 닫은 뒤 기지 버튼을 누르게 수정했다.
3. **iPhone 이동 UI 검사:** HD 단위100의 이동·적 회피 거리를 새 화면 point100으로 사용해 유효한 목적지 후보를 찾지 못했다. 공통 월드 표시 배율과 안전 영역·입력 하단을 사용하도록 수정했다. 임무 행128 이동도 화면 point와 HD 좌표를 구분했고, 잘린 행은 실제 드래그로 스크롤한 뒤 누른다.
4. **iPhone 동시 치트 검사:** 검사 창이 `UIScreen.bounds`의420×912 세로 크기를 사용했다. 정상 Source 앱은912×420 가로로 실행됐다. 세로 치트에서 Stage03_04 항공기의 발사240·피해1·격파0·제거0이 나왔다. 같은420×912 구성의 CPU 검사에서 이를 재현했고,912×420 가로 구성은 안전 영역 유무 모두 같은 세 전장의 발사·피해·격파·제거 기준을 통과했다. 검사 창을 실제 UIWindowScene에 연결하고 현재 iPhone 가로/iPad 세로 계약과 다르면 시작 단계에서 실패하게 수정했다. iPhone 세로 지원 시 이 조건은 다시 다룬다.

첫 한 묶음 직후의 수정들은 검사 준비·좌표·창 구성과 DEBUG 관측 항목에 적용했다. 게임의 적 HP·사거리·피해·획득 수량이나 저장 규칙은 실패에 맞춰 바꾸지 않았다. 수정 뒤 전체 C++73개·실제 가로 크기912×420의 별도 CPU 두 구성과 Apple 검사 제품/별도 치트 앱 컴파일을 확인했으며, **당시에는 시뮬레이터를 재실행하지 않았다. 이후 재검증 결과는 아래 절에 기록한다.**

Xcode가 실패 뒤 자동으로 최대600초 진단 자료를 수집해 종료가 지연됐다. 각 검사 종료 후 해당 진단 자식 프로세스만 중단하고 테스트 로그·결과 묶음·첨부 자료는 보존했다. 후속 검사 도구에는1회 실행과 대형 자동 진단 수집 제외를 명시했다.

원작 포팅판과의 전체 픽셀/음향 동등성, 전 캠페인, 실기기 설치, develop/main 배포는 미확인/미실행이다.


## 수정 후 재검증

사용자의 후속 지시에 따라 수정한 검사로 두 시뮬레이터의 전체20개 검사를 다시 실행한다. 실패한 이전 결과와 xcresult는 보존한다. 수정 없이 같은 실패를 반복하는 자동 재시도는 끄고, 새 실패가 나오면 원인을 수정한 뒤 해당 경로를 다시 검증한다. 실기기는 사용하지 않는다.

iPhone 검사 시작 로그에서912×420 가로·좌우 안전 영역68·하단20을, iPad에서1024×1366 세로·하단25를 확인했다. 실제 각 치트 Session의 설정도 결과 JSON에 남긴다. 검사 코드의 창 방향이 맞다는 사실과 게임 동작의 통과 여부를 따로 판정한다.

첫 재검증은 iPhone17/20·iPad19/20이었다. 최초 완료 임무 UI는 양쪽 모두 통과했지만, 공통 상점 상세·iPhone 실제 이동·iPhone BOT/장비교체가 실패했다. 실패한 xcresult·첨부 JSON·로그를 보존했다.

### 실제 카메라 결함과 수정

초기 iPhone 이동 실패를 검사 좌표 문제로만 설명한 것은 불완전했다. 정상 Source 로그에서도 월드 Player(-275,-412)가 화면 y=-5.84 또는14.56에 그려져 화면 밖 또는 HUD 아래로 벗어났다. 실제 시작 저장의240프레임 CPU 회귀 검사에서도 첫 프레임 y=60.05가 필요한 하단89보다 낮아 실패했다.

원인은 HD 세로 화면의 고정 카메라 경계x±128·y[-94,0]를 짧은 가로 화면에도 적용한 것이었다. 공통 카메라에서 실제 월드 시야·HUD 하단·Player 원본 반경을 사용해 경계를 계산하고, 작은 창은 ease 뒤 Player가 보이는 범위로 중심을 제한한다. 전체 지형이 보이는 축은 가운데에 고정한다. 추가 게임 tick이나 ease·RNG를 넣지 않았다. HD768×1024 기준의 기존 경계·이동 결과는 bitwise 비교로 유지했고, 현재 iPhone 시작 저장의240프레임 화면 내 표시는 통과했다. 원작 함수 HD0x11cac·일반판0x5a418은 기존 로컬 REA export로 대조했다. 작은 창의 Player 보호는 공통 표시 정책이며 원작 HD의 고정 경계와 같다고 주장하지 않는다.

### 검사 준비와 자동 입력 보강

- 상점에는 기지 첫 도움말과 별도로 최초 상점 도움말이 있었다. 상세 선택 전에 이 도움말도 실제 입력으로 닫게 했다. 게임 도움말 로직은 바꾸지 않았다.
- 짧은 시야에서는 기존 HD 고정 좌표와 다른 적·드롭이 활성화됐다. 자동 이동·공습·수리·BOT 입력의 하단을 현재 카메라/HUD로 계산하고 보이는 지상점으로 이동하도록 했다.
- 수집 BOT은 원작의400거리 검색·무작위 이동·20단위 접촉·실제 아이템 전달을 유지한다. 더 작은852×393에서 BOT 한 대의 접촉0이 발생해, 실제 드롭 가까이에 플레이어가 이동하는 검사 경로를 추가했다. BOT 위치·HP·드롭·포획 결과를 강제로 쓰거나 난수 seed·획득 기준을 바꾸지 않았다. 원작0x927c/0x95ac와 현행 BOT의 검색·배회 순서를 대조했다.
- 전장 대표 표적과 일부 무기쌍은 기존 공통 `selectEnemy` 선택/추적 경로를 사용한다. 모든 표적 선택이 포인터 입력을 거쳤다는 검사는 아니다. BOT의 적 탭·지상 이동·장비 버튼은 실제 입력 경로를 사용한다.
- 검사 실행기의 잘못된 `-test-iterations 1` 옵션은 Xcode가 실행 전에 거부했다. 그 시도도 보존하고 옵션을 제거했다. 실패 자동 재시도는 사용하지 않는다.

수정 후 전체 C++73개·작은 iPhone852×393/실제 iPhone912×420/큰 iPad1024×1366의115조건1,200프레임을 통과했다. 각 Attacker3종의 발사·피해, 각 Picker3종의 획득, 대표 포탑/항공기의 발사·피해·격파·제거와 장비 교체 후 발사를 검사했다. Source 검사 제품과 별도Validation 컴파일도 통과했다. 이 결과는 CPU/컴파일 근거이며 Native 통과와 구분한다.

두 번째 Native 묶음은 **iPhone20/20·iPad20/20을 모두 통과**했다. 각115조건1,200프레임에서 Picker 접촉은 iPhone4/2/3회·iPad3/3/2회였고 Attacker3종은 각각 실제 발사·적 HP 감소를 확인했다. 양쪽 준비 후 파일 읽기/존재 확인 누락0·이미지 추가 업로드0·같은 캐시 프레임 RGB 차이0이다. 실제 앱 터치의 이동·한국어 도움말·메뉴·장비·완료 임무/보상·저장 재실행·게임오버 기지 복귀도 통과했다. 이 결과는 아래 HUD 추가 수정 전 제품의 전체 검사다. 실기기는 사용하지 않았다.

### 캡처에서 추가 발견한 HUD 문제

전체20개 통과 뒤 iPhone의 실제 전장 캡처에서 HP·부스터 막대가 중앙 HUD 왼쪽 밖으로 길게 나오는 문제를 확인했다. 화면 전체를 새 기준으로 쓰면서 원래768폭 화면 밖에 가려지던 부분이 드러났다. 실제 판정을 추가하자667×375에서 clipLeft0·필요한 HUD left141.5로 실패했다.

하단 UI의 자르는 영역을 원래 HUD x0..768과 같은 표시 변환으로 옮기고 실제 안전 영역과 교차한다. 처음에는 이 계산만 고쳤지만 회귀가 계속 실패했다. atlas 제출이 자르는 영역을 버리고 있었기 때문이다. 독립 검토에서도 같은 P2를 확인했다.

공통 VisualLayer에서 각 atlas quad의 clip을 보존하고 같은 clip의 인접 구간만 묶어 출력하도록 고쳤다. 같은 타일의 A/A/B/A는 순서를 유지한2/1/1개 quad 구간이 된다. 원래 tile+blend 그룹·quad 지오메트리·16비트 인덱스·atlas 경로는 유지하고, 구간의 지역 인덱스를 계산한다. 호환 출력과 const/rvalue batch 출력 모두 최종 Sprite.clip을 전달하며 GPU는 기존 scissor를 사용한다. 창 크기가 바뀌어도 자원 그룹을 계속 늘리지 않는다. 게이지를 non-atlas로 바꾸거나 HP/부스터 수치·회복·저장·음향을 변경하지 않았다.

이 후속의 전체 C++73개·Source 검사 제품과 별도Validation Apple 컴파일, 두 기기의 관련 Native4/4씩을 모두 통과했다. 동시 GPU115조건1,200프레임·단일 indexed atlas draw·원본 A8 그림자·실제 터치/메뉴/저장 재실행을 포함한다. 양쪽 실제 전장 캡처에서 게이지가 중앙 HUD 안에 표시됨을 확인했다. HUD 수정 전후115개 상태의 비교 항목(발사·피해·격파·획득·이동·BOT·장비교체)은 차이0이었고, 준비 후 자원 누락/이미지 업로드0·같은 프레임 RGB 차이0도 유지했다. 양쪽 전체20개 통과를 이 후속 수정 뒤의 전체 재실행으로 표현하지 않는다. 원작 전체 화면·캠페인의 동등성, 실기기 설치·develop/main 병합은 여전히 별도다.


현재 Native 출력은 iPhone 가로 오른쪽912×420과 iPad 세로1024×1366이다. 반대쪽 iPhone 가로 방향·비대칭 안전 영역의 Native 검사와 같은 원작 장비/프레임/줌의 최종 표시 크기 대조는 별도 남은 범위다. 이전 실패·CLI 시작 거부·HUD 회귀 실패와 모든 xcresult는 로컬에 보존했다.
