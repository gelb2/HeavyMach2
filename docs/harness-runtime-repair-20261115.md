# 네이티브 훅 연결·실패 복구

## 확인한 결과

현재 작업 세션에서 네이티브 훅이 실제 발동한다. 금지된 sentinel 파일 생성은 차단됐고, 허용된 임시 파일의 수정은 전후 기록에 연결됐다. 의도한 패치 검증 실패 뒤, 실제 native transcript를 읽는 복구 명령으로 해당 호출만 실패로 종결했다. 직후 임시 파일 삭제도 정상 실행됐다. 프로젝트 파일의 수정 전·후 해시를 보존했다.

현재 대화 세션 ID는 `01a1abd6-0133-7292-abf5-1f3c44bddf80`이다. 별도 CLI만 실행하고 현재 앱 세션에서도 연결됐다고 추정한 결과와 구분한다. Codex 데스크톱 앱에서 확인하지 않은 훅 버튼을 안내했던 요청은 철회했다. 사용자의 추가 재시작이나 버튼 조작은 필요하지 않다.

## 원인과 수정

| 결함 | 실제 원인 | 수정 |
| --- | --- | --- |
| 현재 세션에서 일부 호출을 건너뜀 | 외부 폴더에서 시작한 대화에도 HM2 프로젝트 훅이 로드됐다고 가정했다. 도구의 cwd가 HM2이면 사용자 디스패처가 즉시 반환했다. | 해당 분기를 제거했다. 기존 사용자 디스패처 하나를 사용하고 중복 프로젝트 콜백은 제거했다. 다른 훅과 notify 설정은 보존한다. |
| 패치 실패 뒤 후속 수정 차단 | 도구가 파일 검증 단계에서 실패하면 현재 실행기가 PostToolUse를 전달하지 않는 경우가 있었다. pending 기록이 계속 남았다. | `recover-failed`를 추가했다. 동일 세션·같은 입력의 실제 실패 출력, 현재 Pre 이후 종료 시간, 파일 무변경을 모두 확인한다. |
| 중복 파일 패치가 같은 고장을 유발 | 한 패치에서 같은 파일을 Delete와 Add로 각각 지정했다. | 중복 대상은 pending을 만들기 전에 거부한다. 하나의 Update File로 작성한다. |
| 복구 중 받은 정정 누락 | unresolved 요청 처리에서 원문을 저장하기 전에 반환했다. | pending을 보존하면서 최신 사용자 원문과 요구를 기록한다. |
| gate가 자기 실행을 차단 | 직접 CLI gate가 검사 pending을 만든 뒤 자기 pending을 거부했다. | gate는 보호 파일 수정 pending을 만들지 않는다. 실제 staged tree와 현재 근거 검사는 유지한다. |
| 문서만 커밋한 뒤 push 차단 | 문서 전용 커밋의 새 tree를 gate 기록에 남기지 않았다. | 해당 tree와 문서 전용 범위·visualPass=false를 기록한다. 이후 제품 변경·tree 불일치는 계속 거부한다. |
| 승인된 HEAD로 다른 미검증 브랜치를 push 가능 | 현재 HEAD만 검사하고 pre-push의 실제 outgoing tip을 승인 tree와 대조하지 않았다. | native pre-push 입력의 각 tip을 승인 tree와 대조한다. 다른 브랜치의 미검증 tree는 차단한다. |
| 정본 수정 뒤 사용자 재시작 요구 | 네이티브로 관측한 정책 수정도 다음 사용자 입력 없이는 반영하지 못했다. | 정상 Post에서 새 정본을 다시 주입하고 해시를 갱신한다. 외부의 미관측 변경은 계속 차단한다. |

## 복구가 보존한 것

처음 고착된 호출 `exec-9f497d2f-2caa-42f5-b306-8aa6a224d718`은 `.codex/hooks.json`의 중복 작업 때문에 파일 수정 전에 실패했다. 당시 pending.before, 세션 files, 현재 보호 파일의 바이트·모드가 모두 일치하는 경우에만 복구했다. 상태 원본을 백업하고 `maintenance-recovery / FAILED_NO_MUTATION`을 기록했다. 가짜 PostToolUse나 게임 PASS를 만들지 않았다.

그 뒤 디스패처가 건너뛴 기간의 변경은 별도 `maintenance-bootstrap` 기록으로 보존했다. 대상은 하네스 코드와 하네스 테스트 두 파일이며, 실제 before/after를 남겼다. 이를 네이티브 훅이 감독한 변경이라고 소급해서 표시하지 않았다. 게임 소스·원본 IPA·사용자 저장은 변경하지 않았다.

새 native 실패 시험은 `exec-af671fce-4d04-4c4e-809c-440d0bc3a9b5`다. 같은 세션의 실제 출력 call `call_ab99a216ada34673acb4765fb6321cb0`을 읽었고, 복구 결과는 `RECOVERED_FAILED_NO_MUTATION`이다. 뒤이은 파일 삭제까지 확인했다. 로컬 원시 대화와 transcript는 Git·보고 사이트에 복사하지 않는다.

최종 수정본에서도 같은 시험을 다시 실행했다. 현재 Pre 이후 종료 시간까지 검사한 호출은 `exec-c5fa8f46-7865-469f-bfaf-01d4be0c5c04`, 실제 출력은 `call_bee46875cc1b4ae3853445d8ef0817b9`다. 복구와 후속 삭제가 성공했고 pending=0, unattested=[]를 확인했다. 실패 근거를 지우지 않았다.

## 검사 범위와 남은 작업

하네스 회귀 검사는 네이티브 이벤트 계약·실패 복구·오래된 결과·요구 누락·staged tree·원본 자원·PNG 검사 등을 다룬다. 실행 로그와 JSON은 `.local/presentation-harness/check-*.{log,json}`에 보존한다. 현재 후보의 로그를 기준으로 판정하며 이전 통과를 재사용하지 않는다.

최종 후보 검사 `check-1794703374120537000`은 59개 통과, 종료 코드 0이다. 후보 해시는 `b0f2f09cb1b0d635fc315ca81e34f7c5111c14ceff438e111987e10b5c4383c1`, 로그 SHA-256은 `0d1db724fb772437a8ccfb5f50bce7f5d5db27c53f17212c7bc0fe2c7968112c`다. 앞선 실패 실행과 독립 검토의 발견도 로컬에 보존했다. 이 수치는 하네스 검사이며 게임 시뮬레이터 검사 수가 아니다.

하네스 기반과 게임 화면의 합격은 구분한다. 이 수정은 게임 소스·앱·설치본을 바꾸지 않았다. 전체 기지·기기·상태의 실제 renderer 관측 수집, 원작 실패 화면으로 검출기 보정, 생성 텍스트 관측, 시뮬레이터와 실제 이미지 열람을 잇는 전체 실행은 남아 있다. 그 검증 없이 하네스 전체 완료나 허브·사령부·상점 개선 완료로 보고하지 않는다.

실행 기록은 로컬 작업 절차의 근거다. 같은 사용자 권한을 가진 사람이 임의로 조작할 수 없는 보안 장벽이라고 설명하지 않는다. 제품 화면의 성공 기준과 90% 탈락선·필수 규칙은 [정본](design-and-asset-rules.md)과 [계획](presentation-harness-plan-20261115.md)을 유지한다.
