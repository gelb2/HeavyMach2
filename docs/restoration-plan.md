# HeavyMach 2 복원 준비

## 유니버설 설계를 위한 원본 차이 조사 — 2026-11-13

현재 iPad 플레이의 사용자 관측을 기준으로 보존하고, 일반판 iPhone과 HD iPad의 패키지·그림·데이터·실행파일 차이를 전수 목록으로 조사한다. [이번 조사 결과](universal-design-audit-results-20261113.md), [범위와 설계 확정 기준](universal-design-audit-plan-20261113.md)을 우선한다. 같은 HD 자원과 공통 C++ 코어를 유지하며 iPhone 전용 에셋·별도 게임 코드는 만들지 않는다.

기존 표본의 메크 크기 비율을 고정 phone 배율로 바로 적용하지 않는다. 원본 일반판의 가변 카메라 배율, reader 단위 변환, 입력·선택·화면 판정·생성·시간·저장 차이를 확인해 공통 화면 구성 계약을 보강한다. 원작 실행이 필요한 미확정은 조건을 묶어 각 판본의 원래 기기 구성에서 확인한다. 현재 단계에서는 게임 코드·앱 빌드·기기 설치를 변경하지 않는다.

## 현재 작업 범위 — 2026-11-11

최신 사용자 지시에 따라 [현행 작업 순서](validation-build.md#작업-순서)를 적용한다. 원본 바이너리와 데이터의 기능·UI·로직을 빠짐없이 목록화해 공통 코드에 구현하고 정식판·치트판에 연결한다. 구현을 갖추기 전에는 포팅판과 기능별 교차 대조를 반복하지 않는다.

전체 기능 구현·수정, 동시 치트 구성·검사와 정식판의 일반 플레이 확인을 마친 뒤 마지막 단계에서 일괄 대조한다. 같은 iPad 시뮬레이터에서 HD 포팅판·정식판·치트판의 저장과 입력을 맞추고 코드 흐름·에셋 로드·음향·아이템·진행·저장 결과를 비교한다. 구현 중 iPhone 시뮬레이터나 실기기를 HD 로직 교차 검증에 사용하지 않는다. iPhone·일반판 대조는 별도 요청 시 진행한다. 아래의 과거 목표와 실행 기록에는 당시 순서가 포함돼 있다.

다른 플랫폼 확장과 빌드 설치·전달·배포, develop/main 릴리스는 보류한다. 현재 진행 상황은 [TODO](todo.md)에 기록한다.

## 현재 상태

2026-11-13 기준 실제 iPad 정식판에서 사용자는 Wasteland까지 이동·전투·일부 임무 완수와 크래시 미발견을 보고했다. 기존 iPad 시뮬레이터 치트 검사는 115조건·1,200프레임이며 전체 게임 분기 검증은 미완료다. [확인한 범위와 남은 문제](public/validation.md)를 현행 상태로 읽는다. 지금은 일반판·HD판의 차이를 조사하고 있으며, 유니버설 화면 구성을 구현하거나 새 앱을 설치하지 않았다.

### 초기 구현 당시 기록 — 2026-11-10

독립 비공개 저장소 준비와 main 반영을 완료했다. 현재 작업 브랜치에서 맵·장비 조립에 이어 [보행·조준·터치·지형 충돌](locomotion-restoration-20261110.md)을 구현·시뮬레이터 검사했다. 검증에서 발견한 차이를 고치고 [전투 복원 계획](combat-restoration-plan-20261110.md)을 기록한 뒤 [무기 데이터·포구 소비](weapon-data-restoration-20261110.md)를 구현했다. Source/Validation 앱은 현재 보행 단계이며 발사·피해·음향·진행 전체는 미완료다. 판본별 결과와 남은 오류는 [TODO](todo.md)에 기록한다.

원본은 외부 Originals 폴더의 일반판4개·HD판2개다. 일반판2.0.1과 HD1.0.3 패키지 비교에서 MachInfo.mcb·MapInfo.mcb·PartsInfo.mcb 3개가 바이트 동일했다. 같은 이름의 PNG839개는 동일하고357개는 다르며 그중342개는 크기도 다르다. .tble135개 중59개가 다르다. 두 실행 파일의 코드 영역도 다르지만 함수별 의미와 실행 동등성은 미확인이다.

## 유니버설 앱 방향

- 2026-11-10 사용자 채택: **HD 그래픽 공통 사용 + 검증된 공통 게임 코어 + 기기별 표시 구성**으로 복원한다. 이미지의 픽셀 크기는 선명도에, 원작에서 확인한 좌표·크기·기준점은 조립과 게임 표시에 사용한다. 일반판 iPhone·HD iPad 기준 포팅판을 각각 보존한다.
- 현재 측정한 첫 전장 수치를 최종 상수로 고정하지 않는다. 같은 장비·적·방향·줌의 기준 장면과 원작 조립 데이터를 확인해 기기별 표시 기준에 연결한다. HD 그림의 형태·여백·기준점·참조 누락을 일반판과 대조하고 공통 데이터·reader·조립 경로로 처리한다.
- 표시 배율과 HUD 배치 확정 전에 [일반판·HD 포팅판의 주인공·적·HUD 크기 측정](reference-display-measurement-plan.md)을 수행한다. 두 포팅판의 측정값과 복원판의 기기별 값을 연결해 비교한다.
- 일반판 표시 구성과 HD판 표시 구성을 별도로 보존한다. 에셋·카메라·HUD·메뉴·부품 크기/기준점을 각 원작과 대조한다.
- 그림 해상도와 월드의 표시 크기를 분리한다. HD 이미지의 픽셀 수만큼 게임 오브젝트를 키우지 않는다.
- HD판의 게임 규칙·콘텐츠를 기준으로 공통 코어를 복원한다. 일반판은 iPhone 표시 기준과 동작 비교 자료로 유지하며, HD와 다른 게임 규칙을 숨기지 않고 기록한다. 원작 데이터 reader·파츠 조립·렌더·입력 경로를 조사하고 별도 임의 유닛 경로를 만들지 않는다.
- 원작 좌표계, 출력 픽셀, 필터링·알파·블렌딩을 분리해 확인한다. 화면비 변화에서 가로세로를 따로 늘이지 않는다.
- iPhone/iPad 대상 하나의 앱을 구성하되, 실제 동작과 검증 전에 완성됐다고 표현하지 않는다.
- iPad를 iPhone 화면의 일괄 확대판으로 만들지 않는다. 메크 표시 기준·월드 시야·HUD 배치를 분리하고 더 넓은 화면에 더 많은 전장과 정보를 표시한다. HUD 하단 중앙 고정 및 기기별 측정·합격 기준은 [가로 화면 계획](hd-landscape-plan.md)의 2026-11-10 요구를 따른다.

### HD 기준 코어·에셋과 기기별 크기 — 2026-11-10

사용자 원문: “소스코드와 에셋은 hd것을 쓰되, 크기는 포팅판 2개에서 측정한 대로 플랫폼 별로 크기는 다르게 대응한다.”

이 방향은 기술적으로 가능하며 다음 기준으로 적용한다.

1. **HD 기준:** HD 실행파일·데이터에서 확인한 게임 동작과 콘텐츠를 새 공통 소스로 복원하고 HD 그래픽을 공통 사용한다. 원작의 소스코드를 확보해 그대로 사용하는 상태라고 표현하지 않는다.
2. **기기별 표시:** iPhone의 메크·적·오브젝트 표시 크기는 일반판 포팅판, iPad는 HD 포팅판의 검증된 기준에 연결한다. HUD는 기능과 그림을 보존하며 하단 중앙 배치 계획을 적용한다. 원작 HUD 배치를 그대로 복제해야 한다는 뜻은 아니다.
3. **크기의 의미:** 달리 적용하는 크기는 화면 표시 크기다. 월드 좌표의 유닛·충돌·이동 속도·탄환·사거리·공격 판정은 HD 기준 공통 규칙을 따른다. 화면↔월드 입력 변환도 같은 카메라 변환을 사용하며 보이는 크기와 판정이 어긋나지 않게 검사한다.
4. **조립과 변환:** 메크 본체·무장·접합점·관련 효과를 일관된 좌표 변환으로 표시한다. 에셋별 원작 기준점 차이를 대응표로 처리하며 임의 유닛별 C++ 보정을 넣지 않는다. HUD 크기는 월드 표시 배율과 별도로 관리한다.
5. **측정 적용:** 현재 첫 전장의 표본값을 최종 상수로 고정하지 않는다. 장비·적 ID·방향·줌을 맞추고, 원작 데이터와 측정 오차를 확인해 기기별 기준을 확정한다. 이후 화면 크기 변화에서는 유닛 일괄 확대보다 카메라 시야 확장을 적용한다.

HD와 일반판의 콘텐츠·동작 차이는 게임 규칙과 표시 차이로 구분해 남긴다. 이 결정은 HD 기준 유니버설 복원판의 방향이며 일반판의 모든 게임 규칙까지 별도로 재현하는 두 엔진 제작 요구가 아니다. 현재는 기록 단계이며 구현·검증은 남아 있다.

### 화면 방향의 구현·검증 순서 — 2026-11-10 후속 지시

1. 복원판의 **iPhone 가로·iPad 세로** 구성을 먼저 완성하고 각 포팅판과 대조한다. 일반/치트 앱에서 메뉴·장비·전투·임무·저장 복구·음향·표시·입력을 검증한다. 이 단계에서 iPad 가로 구현을 선행 조건으로 요구하지 않는다.
2. 위 정상동작 검증 후 **두 기기 모두 가로·세로 지원**으로 확장한다. 추가 구성은 iPhone 세로·iPad 가로다. 회전 중 카메라·HUD·터치 좌표와 장비·진행·저장 상태를 확인한다. 최초 두 구성도 회귀 검사한다.

원작 비교용 포팅판의 방향 규칙은 보존하고, 복원판에서 추가한 방향은 복원 확장으로 기록한다. 기기별 표시 크기와 화면 확장·HUD 원칙은 두 단계 모두 적용한다. 포팅판 시뮬레이터 검증 전 실기기 설치 금지도 유지한다.

### 표시·입력·공격 판정의 대조

일반판과 HD 포팅판은 이 동작을 판별할 비교 기준이다. 같은 장비·적·방향·거리·카메라 배율과 입력 절차를 고정하고 다음을 관측한다.

- 화면의 동일 대상·HUD 버튼을 누르고, 화면→월드 변환·대상 선택·이동 목적지가 맞는지 확인한다. 기기 사이에서 같은 원시 픽셀 좌표를 눌렀다는 사실로 같은 입력이라고 취급하지 않는다.
- 같은 월드 조건에서 조준 방향·포구·탄환 경로·피격 효과·HP 변화·격파·보상 결과를 대조한다. 발사광이 닿아 보이는 것만으로 명중을 확인하지 않는다.
- 유닛 중심·가장자리·바로 바깥, 사거리 안·경계·밖, 이동 중·정지 상태를 비교한다. 반복 관측이 필요한 무작위·타이밍 조건은 함께 기록한다.
- 일반판과 HD가 다르면 표시 배율·입력 변환·게임 규칙·버전 차이를 구분한다. 최종 게임 규칙은 HD를 기준으로 하며 일반판 표시는 그대로 대조한다.

관측만으로 내부 충돌 도형이나 수식이 하나로 확정되지 않으면 해당 reader·원작 실행 코드·실행 계측을 연결해 확인한다. 포팅판 두 개의 대조로 확인할 수 있는 현상과 추가 분석이 필요한 내부 값을 구분하며, 모른다는 이유로 임의 구현하지 않는다.

### 포팅판 대조에 따른 보강 — 2026-11-10

[실행·데이터·함수 대조 결과](reference-comparison-results-20261110.md)를 기록했다. 두 판본에서 이동·적 선택·격파·임무1/5·500→503Cr를 확인했다. 동일 장비 ID·월드 거리·시간을 고정한 경계 검사는 아직 수행하지 않았다. 일반판의 검은 지형 오류도 남는다.

- HD 터치 선택의 반지름 비교와 탄환의 점 포함 검사를 구분한다. 기반 클래스의 점 포함 검사는 월드 위치와 boundRect 사각형을 사용한다. 그림의 알파 경계나 유닛별 임의 충돌 도형으로 대체하지 않는다. 실제 적 클래스·무기별 소비 경로를 연결한다.
- HD의 isInScreen은 카메라 범위와 여유60을 사용하는 경로에서 갱신되며 탄환 충돌 후보 조건에도 들어간다. 초기 HD 기준 시야의 결과를 먼저 재현한다. 기기별 시야 확장은 렌더 범위와 전투 후보 영역을 각각 기록하고 경계의 선택·명중·AI·스폰·임무를 검사한 뒤 확정한다. 더 넓은 화면의 조작 가능성과 HD 결과 보존 사이에 차이가 생기면 설계를 고치고 규칙 차이를 명시한다. 표시 여부 조건을 임의로 삭제하지 않는다.
- WeaponInfo213행 중126행이 다르다. 일반판과 다른 HD 사거리·조준·피해 값은 HD 기준 규칙으로 보존한다. 두 판본의 결과를 맞추려고 기기별 전투 보정을 넣지 않는다.
- 다음 비교는 검증된 실행기 소스/패치 기준과 판본별 저장 사본, 장비·적 ID·월드 좌표·카메라·갱신 시간을 고정한다. 서로 다른 저장 형식을 직접 복사하지 않는다. 같은 화면 픽셀 대신 같은 월드 조건으로 검사한다.

위 사항을 먼저 해소한 뒤 기기별 표시 배율·시야·HUD 구성을 확정한다. HD 공통 코어와 iPhone 일반판 표시 기준, iPad HD 표시 기준, 최초 iPhone 가로·iPad 세로의 순서는 유지한다.

HeavyMach 1·MachDefense와 같은 C++20 코어와 플랫폼별 기술 구성을 사용한다. 새 런타임·게임 엔진·사격별 DB 쓰기·효과음 재생기 임의 대체·UIKit 인게임 구현을 넣지 않는다. 원본 보존·제작 원고·변환·저장 형식·공통 reader·파츠 조립·실제 패키지 검사를 연결한다. 원작의 제작 도구는 미확보이며, 파일 및 실행에서 확인한 절차를 복원한다.

검토 뒤 최초 구현은 HD 데이터 reader·조립·GPU 표시 명령과 C++ 코어 연결부터 시작한다. HM1의 모노 PCM16 제한 대신 HM2의 실제 PCM 형식을 처리하고, 저장·음향·그래픽의 수명/호출 계측을 첫 실행 경로에 연결한다. 기능을 만든 뒤 별도 언어·플랫폼 UI로 갈라진 구현을 다시 합치는 순서로 진행하지 않는다. iPhone 가로·iPad 세로 우선과 기존 포팅판 검증 조건은 유지한다.

치트 앱은 [최신 동시 검증 요구](validation-build.md)에 따라 경험치·레벨·장비·아이템·진행 조건을 함께 준비하고 실제 기능을 실행한다. 원작에서 배타적인 화면은 독립 인스턴스에서 병렬 검사한다. 모든 버튼/기능 목록과 복합 시나리오의 미검사 범위를 추적한다.

## 포팅 앱을 먼저 확보하는 순서

[HeavyMach 1 초기 이력 검토](heavymach1-history-review.md)를 바탕으로 [일반판·HD판 포팅 앱 검증 계획](reference-port-validation-plan.md)을 추가했다. 두 원본 포팅 앱을 각각 자기 기기에서 검증한 뒤 같은 유니버설 복원 앱의 iPhone/iPad 구성을 대조한다. 포팅 앱 실행과 새 소스 복원, 일반/치트 검사, 원본 없이 독립 빌드를 별도 단계로 관리한다.

## 다음 조사

HD의 가로 화면 지원은 [별도 계획](hd-landscape-plan.md)에 기록했다. 원본 세로 비교판을 보존하고 가로 시험판을 검증한 뒤 유니버설 복원판에 반영한다. 여섯 IPA의 콘텐츠·내부 날짜 비교는 [전 버전 조사](ipa-version-audit.md)를 따른다.

원작 두 앱의 확인된 차이와 당시 분리 개발의 가능한 이유는 [일반판·HD판 분리 배경](original-phone-hd-separation.md)에 기록했다. 두 실행파일의 차이를 두 개의 독립 소스코드 전체를 확보·확인한 것으로 표현하지 않는다.

1. 여섯 원본 해시와 앱 버전·아키텍처·암호화 상태를 보존한다.
2. 두 판본의 실행 가능한 비교 환경을 확보하고 기준 장면·입력·저장을 기록한다.
3. 다른 테이블59개의 의미, 좌표·카메라·렌더 변환, 부품 크기와 접합을 분석한다.
4. 원작 함수·데이터→복원 구현→회귀검사 대응을 기록하고 구현한다.
5. 같은 장면의 유닛·배경·UI 크기와 비례, 실제 전투·저장·진행을 판본별로 확인한다.

이 계획은 게임 구현 완료나 원본 전체 소스 확보를 뜻하지 않는다.
