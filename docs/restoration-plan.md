# HeavyMach 2 복원 준비

## 현재 상태

독립 비공개 저장소 준비와 main 반영을 완료했다. 현재 작업 브랜치에서 일반판·HD판의 원본 포팅 앱을 시뮬레이터로 검증 중이다. 판본별 실행 결과와 남은 오류는 [TODO](todo.md)에 기록한다. 독립 게임 소스 복원판의 구현과 전체 정상동작 검증은 아직 완료하지 않았다.

원본은 외부 Originals 폴더의 일반판4개·HD판2개다. 일반판2.0.1과 HD1.0.3 패키지 비교에서 MachInfo.mcb·MapInfo.mcb·PartsInfo.mcb 3개가 바이트 동일했다. 같은 이름의 PNG839개는 동일하고357개는 다르며 그중342개는 크기도 다르다. .tble135개 중59개가 다르다. 두 실행 파일의 코드 영역도 다르지만 함수별 의미와 실행 동등성은 미확인이다.

## 유니버설 앱 방향

- 일반판 표시 구성과 HD판 표시 구성을 별도로 보존한다. 에셋·카메라·HUD·메뉴·부품 크기/기준점을 각 원작과 대조한다.
- 그림 해상도와 월드의 표시 크기를 분리한다. HD 이미지의 픽셀 수만큼 게임 오브젝트를 키우지 않는다.
- 같은 동작이 확인된 데이터와 코어만 공통화한다. 원작 데이터 reader·파츠 조립·렌더·입력 경로를 조사하고 별도 임의 유닛 경로를 만들지 않는다.
- 원작 좌표계, 출력 픽셀, 필터링·알파·블렌딩을 분리해 확인한다. 화면비 변화에서 가로세로를 따로 늘이지 않는다.
- iPhone/iPad 대상 하나의 앱을 구성하되, 실제 동작과 검증 전에 완성됐다고 표현하지 않는다.
- iPad를 iPhone 화면의 일괄 확대판으로 만들지 않는다. 메크 표시 기준·월드 시야·HUD 배치를 분리하고 더 넓은 화면에 더 많은 전장과 정보를 표시한다. HUD 하단 중앙 고정 및 기기별 측정·합격 기준은 [가로 화면 계획](hd-landscape-plan.md)의 2026-11-10 요구를 따른다.

## 기술스택과 에셋 절차

[기술스택과 에셋 절차](technology-and-assets.md)를 구현 기준으로 적용한다. HeavyMach 1과 같은 플랫폼별 기술 구성을 사용한다. 원본 보존·제작 원고·변환·저장 형식·공통 reader·파츠 조립·실제 패키지 검사를 연결한다. 원작의 제작 도구는 미확보이며, 파일 및 실행에서 확인한 절차를 복원한다.

## 포팅 앱을 먼저 확보하는 순서

[HeavyMach 1 초기 이력 검토](heavymach1-history-review.md)를 바탕으로 [일반판·HD판 포팅 앱 검증 계획](reference-port-validation-plan.md)을 추가했다. 두 원본 포팅 앱을 각각 자기 기기에서 검증한 뒤 같은 유니버설 복원 앱의 iPhone/iPad 구성을 대조한다. 포팅 앱 실행과 새 소스 복원, 일반/치트 검사, 원본 없이 독립 빌드를 별도 단계로 관리한다.

## 다음 조사

HD의 가로 화면 지원은 [별도 계획](hd-landscape-plan.md)에 기록했다. 원본 세로 비교판을 보존하고 가로 시험판을 검증한 뒤 유니버설 복원판에 반영한다. 여섯 IPA의 콘텐츠·내부 날짜 비교는 [전 버전 조사](ipa-version-audit.md)를 따른다.

1. 여섯 원본 해시와 앱 버전·아키텍처·암호화 상태를 보존한다.
2. 두 판본의 실행 가능한 비교 환경을 확보하고 기준 장면·입력·저장을 기록한다.
3. 다른 테이블59개의 의미, 좌표·카메라·렌더 변환, 부품 크기와 접합을 분석한다.
4. 원작 함수·데이터→복원 구현→회귀검사 대응을 기록하고 구현한다.
5. 같은 장면의 유닛·배경·UI 크기와 비례, 실제 전투·저장·진행을 판본별로 확인한다.

이 계획은 게임 구현 완료나 원본 전체 소스 확보를 뜻하지 않는다.
