# 휴대폰 상점 상품 페이지 수정과 배치 검사

iPhone Lv22 저장 사본에서 무기 48개가 16·8·16·8·0개로 표시됐다. 정식 iPhone과 치트 PWA에서 사용하는 상품표, 패널과 진열 아이콘은 바이트가 같았다. 공통 상점은 HD 상품 페이지 24개를 휴대폰에서 16개와 8개로 다시 나누고, 상품 수가 24의 배수일 때 빈 페이지를 추가한다. 원작 iPhone 상점은 한 페이지에서 상품 16개를 순회한다. [원작과 화면 비교](iphone-shop-comparison-20261119.md)

## 수정 범위

- 공통 모듈에 판매 목록의 시작·끝과 페이지 수를 계산하는 함수를 둔다. 휴대폰은 16개씩 연속으로 배치한다. iPad의 HD 화면에는 기존 24개·기존 페이지 규칙을 적용한다.
- 화면의 상품, 페이지 표시와 터치, 상세, 구매가 같은 목록 범위를 사용한다. 구매 확인의 상품 번호와 누른 상품 번호를 대조한다. 상품을 읽는 순서, 레벨·가격 조건, 오른쪽 인벤토리 25칸의 저장과 입력은 기존 규칙을 적용한다.
- 상품 격자, 패널, 배경, Detail, BUY·SELL, Exit, Shop·Equip은 기존 좌표와 480×320 변환을 적용한다. 마지막 페이지에 상품이 일부만 있으면 남은 칸에는 상품 터치 영역을 만들지 않는다.

## 합격 기준

1. 수정 전 iPhone·iPad·Android·설치형 PWA 상점을 각각 캡처한다. 같은 환경, 저장, 탭, 화면 크기의 수정 후 캡처와 비교한다. 상품 격자 내부와 페이지 점에서만 판매 목록 변경을 허용한다. 패널·배경·조작부의 위치와 크기, iPad HD 상점의 렌더링은 기준 화면과 일치해야 한다.
2. 전체 상품 표시와 터치가 같은 위치에 있어야 한다. 상세는 행에 맞춰 기존 위치에 열려야 한다. 상세·BUY·SELL과 카테고리·페이지·Exit·Shop·Equip의 조작 영역이 겹치거나 잘리면 실패다. 화면 축소와 넓은 가로 화면에서 실제 터치를 검사한다.
3. 상품 수 0·15·16·17·24·32·48개에서 누락·중복·추가 빈 페이지를 검사한다. Lv22 무기는 16·16·16개, 파츠는 16·10개로 보여야 한다. 마지막 페이지의 다음 버튼, 역순 페이지 이동, 탭 변경, 상품 상세·구매·취소, 인벤토리 페이지 이동을 확인한다.
4. Android·iPhone·iPad 정식 후보와 치트 PWA의 검사 결과를 빌드와 환경별로 기록한다. 레이아웃 차이, 입력 실패 또는 상품 번호 불일치가 하나라도 나오면 해당 후보는 실패다.

iPhone 캡처의 지정 영역 밖에는 장당 62~107개의 색상 차이점이 있었다. 모두 RGB 채널당 1단계 차이였고, 공유 배치 검사는 상품 격자·상세·BUY·SELL·페이지·Exit·Shop·Equip의 좌표와 터치를 통과했다. 원시 차이 수와 판정 기준을 비교 기록에 함께 남겼다.

공통 검사에서 0·15·16·17·24·32·48개, 두 번째 화면의 마지막 상품 선택과 상품 번호가 같은 구매 확인, 실제 구매·판매 및 인벤토리 페이지를 검사했다. Apple의 별도 SG-1 기준 검사는 수정 전에도 실패했다. 현재 캠페인의 첫 상품은 LS-D이고, 해당 검사는 첫 상품이 SG-1이라고 고정한다. Apple 정식 시뮬레이터 앱은 따로 빌드했다. 실물 iPhone·iPad·갤럭시는 연결이 끊긴 상태에서 확인해 설치·조작과 공개 배포가 남았다.

상점 후보와 기준 양쪽에서 장비 단위 검사의 과거 목록 개수가 캠페인 데이터와 다름을 확인했다. 현재 레벨 21의 무기 48개로 HD 페이지 경계의 기존 조건을 검증한다. 레벨 99에서는 판매 가능한 Sn-HawkEye 한 종을 확인한다. 테스트의 기대값을 현행 상품표에 맞췄다.

공개 iPhone 복구코드의 인벤토리 75칸이 모두 차 있었다. PWA는 무기 구매를 거절하고 잔액을 유지했다. 거래 성공 검사용 사본에서는 마지막 인벤토리 페이지의 미장착 아이템 한 칸을 비워 같은 구매를 다시 검사했다. iPhone 복구코드 원본과 Tauri 치트판의 기존 저장은 보존했다.

Android 상점 12장도 비교했다. 태블릿 6장은 픽셀이 모두 같았다. 폰 6장의 차이는 상품·페이지 표시 영역에 있었다. 상점 진입 직후의 전환 프레임은 별도 보관하고 배치 비교에는 문이 열린 뒤의 화면을 사용했다. WebKit 브라우저의 iPhone·iPad·Mac 세로 프로필에서 기지, 상점, 전장 및 포털 복귀를 재현했다.
